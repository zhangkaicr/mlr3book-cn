背景与解释（译者注）：上面这段手工计算中，列名写作 rmse，但代码求的其实是均方误差（Mean Squared Error, MSE）——即残差平方的均值 mean((truth - response)^2)，并没有开平方。若要得到均方根误差（Root Mean Squared Error, RMSE），应写 mean((truth - response)^2)^0.5 或直接使用 sqrt()。原文在此处只是命名不严谨，计算逻辑本身没有错，读者不必被列名误导。

  1. (*) 在不使用 mlr3 的 autoplot() 函数的情况下，自己编写一个 ROC 绘图函数。你的函数签名应为 my_roc_plot(task, learner, train_indices, test_indices)。函数应使用 Prediction 的 $set_threshold() 方法以及 mlr3measures。

下面给出一个函数，它在一个概率网格上循环计算真正例率（TPR，灵敏度）与假正例率（FPR，1 - 特异度）。这些概率通过 PredictionClassif 对象的 $set_threshold() 方法被设为阈值。这样我们通过迭代计算 x 与 y 值来构造 ROC 曲线，随后即可用 geom_step() 绘出阶梯函数。请注意，我们不需要重新训练学习器，只是在函数开头调整一下对已有预测所施加的阈值。

my_roc_plot = function(task, learner, train_indices, test_indices) {
  # 训练学习器，只预测一次。
  learner$train(task, train_indices)
  pred = learner$predict(task, test_indices)
  # 从预测矩阵中取出正类的预测
  pos_pred = pred$prob[, which(colnames(pred$prob) == task$positive)]

  # 设定用于评估的概率网格。
  prob_grid = seq(0, 1, 0.001)

  # 对每个可能的阈值计算 TPR、
  # FPR，并汇总为 data.table
  grid = data.table::rbindlist(lapply(prob_grid, \(thresh) {
    pred$set_threshold(thresh)
    data.table::data.table(
      thresh = thresh,
      # y 轴 == 灵敏度 == TPR
      tpr = mlr3measures::tpr(
        truth = pred$truth, response = pred$response,
        positive = task$positive),
      # x 轴 == 1 - 特异度 == 1 - TNR == FPR
      fpr = mlr3measures::fpr(
        truth = pred$truth, response = pred$response,
        positive = task$positive)
    )
  }))

  # 按阈值降序排列，以便使用 ggplot2::geom_step
  data.table::setorderv(grid, cols = "thresh", order = -1)

  ggplot2::ggplot(grid, ggplot2::aes(x = fpr, y = tpr)) +
    # 阶梯函数，先走水平 (h) 后走垂直 (v) 方向
    ggplot2::geom_step(direction = "hv") +
    ggplot2::coord_equal() +
    ggplot2::geom_abline(linetype = "dashed") +
    ggplot2::theme_minimal() +
    ggplot2::labs(
      title = "My Custom ROC Curve",
      subtitle = sprintf("%s on %s", learner$id, task$id),
      x = "1 - Specificity", y = "Sensitivity",
      caption = sprintf("n = %i. Test set: %i", task$nrow, length(test_indices))
    )
}

library(mlr3misc)

focus_search = function(task, learner, search_space, resampling, measure, random_search_stages, random_search_size) {

  repeat {

    # 在随机设计上调节学习器
    instance = tune(
      tuner = tnr("random_search", batch_size = random_search_size),
      learner = learner,
      task = task,
      resampling = resampling,
      measure = measure,
      search_space = search_space,
      terminator = trm("evals", n_evals = random_search_size)
    )

    # 确定最优配置
    best_config = instance$result_x_search_space

    # 收缩搜索空间
    params = map(search_space$subspaces(), function(subspace) {
      best = best_config[[subspace$ids()]]
      lower = subspace$lower
      upper = subspace$upper

      new_lower = best - 0.25 * lower
      new_upper = best + 0.25 * upper

      if ("ParamInt" %in% subspace$class) {
        new_lower = round(new_lower)
        new_upper = round(new_upper)

        p_int(max(new_lower, lower), min(new_upper, upper), tags = subspace$tags[[1]])
      } else {
        p_dbl(max(new_lower, lower), min(new_upper, upper), tags = subspace$tags[[1]])
      }
    )
    search_space = invoke(ps, .args = params)

    random_search_stages = random_search_stages - 1
    if (!random_search_stages) return(best_config)
  }
}

filter_forward_selection_search = function(task, learner, resampling, measure, filter, n, max_features) {
  features = task$feature_names

  # 计算过滤器分数
  filter$calculate(task)
  scores = filter$scores

  result_features = character(0)
  while (max_features > length(result_features)) {

    # 选出要尝试的 n 个特征
    filter_features = sample(names(scores), size = min(n, length(scores)), prob = scores)

    # 创建特征矩阵
    states = matrix(FALSE, ncol = length(features), nrow = length(filter_features))

    # 把过滤器特征加入矩阵
    for (i in seq_along(filter_features)) {
      states[i, which(features %in% filter_features[i])] = TRUE
    }

    # 把已选中的特征加入矩阵
    states[, which(features %in% result_features)] = TRUE

    # 把矩阵转换为设计
    design = setnames(as.data.table(states), features)

    # 评估各特征组合
    instance = fselect(
      fselector = fs("design_points", design = design, batch_size = nrow(design)),
      task =  task,
      learner = learner,
      resampling = resampling,
      measure = measure
    )

    # 当前最优特征集
    result_features = instance$result_feature_set

    # 从分数中移除已选中的特征
    scores = scores[!names(scores) %in% result_features]
  }

  result_features
}

这些规则很容易翻译成 R 代码：我们先取出正类的预测概率，对真实标签向量做 0-1 编码，然后计算两个向量之间的平均绝对误差。

mae_prob = function(truth, prob, task) {
  # 从任务中取出正类
  positive = task$positive
  # 选出正类的概率
  prob_positive = prob[, positive]
  # 得到真实标签的 0-1 编码
  y = as.integer(truth == positive)
  # 对绝对差取平均
  mean(abs(prob_positive - y))
}

3.1 在超参数优化过程中，有多少观测被用于训练 XGBoost 算法（不含验证数据）？又有多少用于随机森林？提示：无法利用验证数据的学习器会忽略它。

外层重采样已经从数据中移走了 20 个观测（外层测试集），只留下 80 个数据点（外层训练集）供内层重采样使用。接着有 16 个观测（0.2 * 80，即内层留出重采样的测试集）被用于评估各个超参数配置。这样就剩下 64 个（80 - 16）观测用于训练。对 XGBoost 而言，构成内层测试集的那 16 个观测同时也被用作验证数据，因此不会再从那 64 个训练点中扣除更多数据。由于随机森林不支持验证，内层测试集的这 16 个观测只会被用于评估超参数配置，而不会被同时用作内部验证。因此，随机森林和 XGBoost 模型都使用 64 个观测来训练。

3.2 如果选中 XGBoost，最终模型会用多少观测来训练？如果选中随机森林呢？

两种情况下都会使用全部 80 个观测（即外层重采样得到的训练集）。这是因为在最终模型拟合时不会生成验证数据。

3.3 如果我们把 GraphLearner 的 $validate 字段设为 0.25 而非 "test"，上面两个问题的答案会如何变化？

在这种情况下，验证数据不再与内层重采样测试集相同，而是从构成内层训练集的 64 个观测中划分出来。由于这发生在任务进入 GraphLearner 之前，XGBoost 模型和随机森林都只能访问 48（(1 - 0.25) * 64）个观测，其余 16 个被用于生成验证数据。请注意，随机森林同样会忽略验证数据，因为它不具备 ‘validation’ 属性，因而无法使用它。此外，AutoTuner 现在会用另一个集合来调节步长和提升迭代次数（巧的是两者规模都是 16）。因此，问题 3.1 的答案将从 64 变为 48。

但这并不改变 3.2 的答案，因为同样地，在最终模型拟合时并不进行验证。

请注意，我们通常建议在调优时把验证数据设为 "test"，所以这应当只被当作一个说明性例子。

如果我们把 XGBoost 分类器的 $validate 字段设为 0.3，验证数据就会从 PipeOpOpPCA 的输出任务中生成。然而，由于 PipeOpPCA 并不知道 LightGBM 分类器打算做验证，这个任务完全按训练逻辑做了预处理。由于验证性能的用意是衡量模型在预测阶段的表现如何，验证数据本应按预测逻辑来预处理。因此，把 PipeOpPCA 输出的 30% 切分出来作为 XGBoost 分类器的验证数据是无效的。所以，PipeOps 的 $validate 字段无法设为 predefined' orNULL’ 之外的值。只有 GraphLearner 自身才能决定验证数据在进入 Graph 之前是如何生成的，从而验证数据会按预测逻辑做预处理。
