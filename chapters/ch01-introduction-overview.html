欢迎来到「R 中的机器学习（Machine Learning in R）」宇宙。在本书中，我们将一步步带你领略 mlr3 所提供的功能。如果你想为我们的宇宙贡献力量、提出任何问题、阅读文档，或者只是想和团队聊聊，可以前往 https://github.com/mlr-org/mlr3，其 README 中有若干有用的链接。

mlr3 包 (Lang et al. 2019) 以及更广泛的 mlr3 生态系统为 R 语言 (R Core Team 2019) 提供了一个通用、面向对象且可扩展的框架，用于回归（回归, Regression）（第 2.1 节）、分类（分类, Classification）（第 2.5 节）以及其他机器学习任务（第 13 章）。在最基本的层面上，这个统一接口提供了训练、测试和评估许多机器学习算法的功能。你还可以在此基础上更进一步，进行超参数优化（hyperparameter optimization）、计算流水线（computational pipelines）、模型解释（model interpretation）等等。mlr3 的整体目标与 R 的 caret 和 tidymodels、Python 的 scikit-learn 以及 Julia 的 MLJ 类似。总体而言，mlr3 的设计目标是在提供比其他 ML 框架更多的灵活性的同时，仍为使用高级功能提供简便的途径。虽然 tidymodels 特别擅长让简单的 ML 任务变得非常容易，但 mlr3 更面向高级 ML。

背景与解释（译者注）：本书所指的「ML 任务（Task）」与日常所说的"任务/工作"含义不同，而是 mlr3 中的核心概念——一个 R6 对象，它封装了「数据集 + 预测目标」构成建模问题。回归与分类即监督学习（supervised learning）的两大基本问题：回归的目标变量是连续数值（如房价），分类的目标变量是离散类别（如物种）。同时注意 mlr3 与 caret、tidymodels 的关系：它们都是 R 生态中的机器学习统一框架，相当于建立一个"统一的 API"来调用底层大量算法；但 mlr3 默认基于 R6 的引用语义（reference semantics）和嵌套表格（data.table、list-column）设计，更强调灵活性、可扩展性与可组合性，也因此在构建复杂流水线、调优与基准测试（benchmarking）时表现更强。

在我们展示 mlr3 的全部威力之前，我们建议你先安装 mlr3verse 包，它会一次性安装 mlr3 生态系统中的若干重要包。

install.packages("mlr3verse")

在本书纸质版出版之后新增的章节，都会用「+」号标注。

可复现性（Reproducibility）

在每章开头，我们都会运行 set.seed(123)，并使用 renv 管理包版本，你可以在 https://github.com/mlr-org/mlr3book/blob/main/book/renv.lock 找到我们的 lockfile（锁定文件）。

背景与解释（译者注）：set.seed(123) 用于固定 R 随机数生成器的种子，使涉及随机性的步骤（如交叉验证折的划分、自助抽样）在每次运行时产生相同结果，以便复现书中的输出。`renv` 是 R 的依赖管理工具，类似 Python 的 `requirements.txt`/`pipenv`：lockfile 记录每个包的确切版本，保证"同样的代码 + 同样的环境"得到同样的结果。这也是机器学习研究中「可复现性（reproducibility）」的基本要求，值得中文读者在自行实验时也养成习惯。

1.3 mlr3book 代码风格（mlr3book Code Style）

在本书中，我们将统一采用以下代码风格：

  1. 赋值一律使用 =，而不是 <-。

  2. 类名使用 UpperCamelCase（大驼峰命名法）。

  3. 函数名和方法名使用 lower_snake_case（小写下划线命名法）。

  4. 提到函数时，我们只会为 mlr3 宇宙之外的函数，或可能存在歧义（无法判断函数存在于哪个包中）的函数加上包前缀（例如 pkg::function）。注意你可以用 environment(function) 查看某个函数是从哪个命名空间加载的。

  5. 我们按如下方式标记包（package）、字段（field）、方法（method）和函数（function）：

    • package（首次出现时高亮）
    • package::function() 或 function()（见第 4 点）
    • $field 表示字段（封装在 R6 类中的数据）
    • $method() 表示方法（封装在 R6 类中的函数）
    • Class（主要用于 R6 类，可以通过语境与包区分）

现在让我们通过第一个示例看看这在实践中是如何运作的。

1.4 示例入门 mlr3（mlr3 by Example）

mlr3 宇宙包含一系列广泛的工具，可以带你从基础 ML 走向复杂实验。作为入门，这里是一个最简单功能的示例——训练一个模型并做出预测。

在这个示例中，我们在 penguins 数据集的一个子集上训练了一棵决策树（decision tree），在其余数据上做出预测，然后用准确率（accuracy）这一度量（measure）进行评估。我们会在第 2 章中更详细地展开这一过程。

背景与解释（译者注）：这段代码蕴含了 mlr3 的核心范式，也是与 base R/caret 差异最大的地方：任务（Task）—学习器（Learner）—预测（Prediction）—度量（Measure）。tsk("penguins") 用"字典键（key）"直接从内置数据字典中加载封装好的任务；partition() 把数据按约 2/3、1/3 的比例划分训练集与测试集；lrn() 创建学习器；然后通过 R6 的 $ 操作符调用 $train()、$predict()、$score() 方法。相比 caret 的函数式接口（如 train()），R6 把"状态"封装在对象内部（如学习器是否已训练、模型存在哪里），这是理解全书代码的关键。`partition()` 划分后，每个观测的行号（row_ids）即为主键，训练/预测都基于行号而非重新赋予的索引。

mlr3 的接口还可以让你仅用几行代码就运行更复杂的实验：

library(mlr3verse)

tasks = tsks(c("breast_cancer", "sonar"))

glrn_rf_tuned = as_learner(ppl("robustify") %>>% auto_tuner(
    tnr("grid_search", resolution = 5),
    lrn("classif.ranger", num.trees = to_tune(200, 500)),
    rsmp("holdout")
))
glrn_rf_tuned$id = "RF"

glrn_stack = as_learner(ppl("robustify") %>>% ppl("stacking",
    lrns(c("classif.rpart", "classif.kknn")),
    lrn("classif.log_reg")
))
glrn_stack$id = "Stack"

learners = c(glrn_rf_tuned, glrn_stack)
bmr = benchmark(benchmark_grid(tasks, learners, rsmp("cv", folds = 3)))

bmr$aggregate(msr("classif.acc"))
         task_id learner_id classif.acc
1: breast_cancer         RF      0.9649
2: breast_cancer      Stack      0.9342
3:         sonar         RF      0.7536
4:         sonar      Stack      0.7246

在这个（复杂得多的！）示例中，我们选择了两个任务和两个学习器，用自动调优（automated tuning）来优化随机森林学习器中的树的数量（第 4 章），并用了一个机器学习流水线来插补缺失数据、合并因子水平并堆叠各模型（第 7 章和第 8 章）。我们还展示了诸如加载学习器（第 2 章）以及为基准测试（benchmarking）选择重采样（resampling）策略（第 3 章）之类的基础功能。最后，我们使用三折交叉验证（three-fold cross-validation）下的平均准确率比较了各模型的性能。

背景与解释（译者注）：这个例子几乎预告了全书的主题：ppl("robustify") 是一个"稳健化"流水线（自动处理缺失值插补、类别水平合并、特征标准化等预处理）；auto_tuner() 将调优器（如网格搜索 grid search）与学习器、重采样策略打包成一个"自动调优学习器"（automated tuner）；ppl("stacking") 实现集成学习中的"堆叠（stacking）"——用一个元学习器（meta-learner，这里是逻辑回归 classif.log_reg）组合多个基学习器的输出。as_learner() 把流水线对象转化为"图学习器（Graph Learner）"，从而能用统一的 Lemer 接口使用它们。benchmark() 则批量运行"任务 × 学习器 × 重采样"的全组合并汇总性能。可以看到 mlr3 把标记性思路推向极致，这也是它能在一行内组合出复杂实验的原因。

在本书中你将学会如何做所有这一切，以及更多。

1.5 mlr3 生态系统（The mlr3 Ecosystem）

在本书中，我们经常提到 mlr3，它可能指单一的 mlr3 基础包，但通常指我们生态系统中的全部包，这一点应该根据语境来判断。mlr3 包提供了生态系统中其余部分所依赖的、用于构建更高级机器学习工具的基础功能。图 1.1 展示了我们生态系统中那些以预处理、流水线化、可视化、附加学习器、附加任务类型等方式扩展 mlr3 的包。

背景与解释（译者注）：图中 "Special Tasks"（特殊任务）一类展示了 mlr3 生态的可扩展性：除了回归与分类，还能处理生存分析（mlr3proba 还提供概率预测与分布模型）、聚类（mlr3cluster）、时空数据（mlr3spatiotempcv）、函数型数据（mlr3fda）、公平性评估（mlr3fairness）等。「Tuning」（调优）类中的 mlr3mbo 提供基于模型的贝叶斯优化（model-based optimization / Bayesian optimization），mlr3hyperband 提供搜索效率更高的连续减半法；「Feature Selection」类做特征选择（特征筛选）。这些包共同构成一个"平台"：你可以只装 mlr3verse 全家桶，也可以按需只挑少数几个包，这正是本书第 1.1 节建议配置多仓库（R-universe + CRAN）的原因。

1.5.1 面向初学者的 R6（R6 for Beginners）

R6 是 R 较新的一种面向对象编程范式。如果你有任何（基于类的）面向对象编程经验，那么 R6 应该会让你感到熟悉。我们只关注使用 mlr3 所需要了解的 R6 部分。

对象（Objects） 是通过用 $new() 初始化方法构造一个 R6Class 变量的实例而创建的。例如，假设我们已经实现了一个名为 Foo 的类，那么 foo = Foo$new(bar = 1) 就会创建一个 Foo 类的新对象，并把构造函数的 bar 参数设为值 1。在实践中，我们在 mlr3 里实现了很多"糖函数（sugar）"功能（第 1.6 节），使构造和访问更加方便。

一些 R6 对象可能会有可变状态（mutable states），这些状态封装在它们的字段（fields）中，可以通过美元符号 $ 操作符访问。接续前面的例子，我们可以用 foo$bar 访问 foo 对象中的 bar 值，也可以给它赋一个新值，例如 foo$bar = 2。这些字段还可以是「活动绑定（active bindings）」，即在被引用或修改时执行额外的计算。

除了字段之外，方法（methods） 允许用户检查对象的状态、获取信息，或执行一个改变对象内部状态的动作。例如，在 mlr3 中，学习器的 $train() 方法会通过构建并存储一个模型来改变学习器的内部状态。修改对象内部状态的方法常常会返回对象自身。其他方法可能返回一个新的 R6 对象。在两种情况下，都可以用 $ 操作符一个接一个地调用方法，实现方法的「链式（chain）」调用；这与 tidyverse 包中使用的 %>% 操作符类似。例如，Foo$bar()$hello_world() 会先运行对象 Foo 的 $bar() 方法，再运行 $bar() 返回的对象（可能还是 Foo 自身）的 $hello_world() 方法。

字段和方法可以是公有的（public），也可以是私有的（private）。公有字段和方法定义了与对象交互的 API。在 mlr3 中，除非你想通过添加新类来扩展我们的宇宙（第 10 章），否则可以安全地忽略私有方法。

最后，R6 对象是 environment（环境），因此具有引用语义（reference semantics）。这意味着，例如，foo2 = foo 并不会创建一个新的、名为 foo2 且是 foo 副本的变量；相反，它创建了一个引用 foo 的、名为 foo2 的变量，因此设置 foo$bar = 3 也会把 foo2$bar 改成 3，反之亦然。要复制一个对象，请使用 $clone(deep = TRUE) 方法，所以想要复制 foo 应写成：foo2 = foo$clone(deep = TRUE)。

$clone()

背景与解释（译者注）：引用语义是 R6 与 base R 的 S3/S4 对象系统（以及 R 中"函数式 + 复制即改"习惯）最本质的区别：普通 R 变量赋值是"值复制"，而 R6 对象是"引用共享"。若忘记 $clone(deep = TRUE) 而直接把 foo2 = foo，两处"对象"实际指向同一份状态，一处修改会"波及"另一处——这是新手最常踩的坑。另外 $clone(deep = TRUE) 强调"深拷贝"：浅拷贝（deep = FALSE）只复制顶层环境，其内嵌的字段（如表数据）仍被共享。这与 Python 对象的"可变对象引用"行为类似。对于只读地调用方法而言这些差别无感，但一旦涉及 $train()、修改数据等写操作就要小心。

更长的介绍我们推荐查阅 R6 vignette（小册子），地址是 https://r6.r-lib.org/；更多细节可参见 https://adv-r.hadley.nz/r6.html。

1.5.2 面向初学者的 data.table（data.table for Beginners）

data.table 包实现了 data.table()，它是 R 的 data.frame() 的一个流行替代品。我们之所以使用 data.table，是因为它速度极快，并且可以很好地扩展到更大的数据。

和 data.frame 一样，data.table 可以用 data.table() 或 as.data.table() 构造：

library(data.table)
# converting a matrix with as.data.table
as.data.table(matrix(runif(4), 2, 2))
       V1     V2
1: 0.2989 0.5856
2: 0.1594 0.1488
# using data.table
dt = data.table(x = 1:6, y = rep(letters[1:3], each = 2))
dt
   x y
1: 1 a
2: 2 a
3: 3 b
4: 4 b
5: 5 c
6: 6 c

data.table 的使用方法与 data.frame 非常相似，但它们提供了额外的功能，让复杂操作变得更容易。例如，数据可以在 [ 操作符中用 by 参数按组汇总，还可以用 := 操作符原地（in-place）修改。

# mean of x column in groups given by y
dt[, mean(x), by = "y"]
   y  V1
1: a 1.5
2: b 3.5
3: c 5.5
# adding a new column with :=
dt[, z := x * 3]
dt
   x y  z
1: 1 a  3
2: 2 a  6
3: 3 b  9
4: 4 b 12
5: 5 c 15
6: 6 c 18

最后，data.table 也使用引用语义，所以你需要用 copy() 来复制（clone）一个 data.table。深入的介绍我们推荐名为 “Introduction to Data.table” (2023) 的 vignette。

背景与解释（译者注）：by 参数实现"分组-汇总"（split-apply-combine），等价于 base R 的 aggregate() 或 tidyverse 的 group_by() + summarise()；:= 则实现原地添加/修改列，不需要重复复制整张表，这正是 data.table 快的秘诀之一。与 R6 一样，data.table 也是引用语义：当把 dt 赋给另一个变量再修改时，原表也会跟着变，须用 copy() 显式复制。作为统计学习者，若更熟悉 tidyverse（dplyr）语法，可把 data.table 与 dplyr 对照记忆：dt[i, j, by] 中的 i 对应 filter（行筛选），j 对应 mutate/summarise（列操作），by 对应 group_by（分组）。二者的取舍在现代 R 中常与"易读性 vs 性能"挂钩。

1.6 重要的 mlr3 工具（Essential mlr3 Utilities）

mlr3 包含几个对我们生态系统中简化代码至关重要的实用工具。

糖函数（Sugar Functions）

mlr3 中的大多数对象都可以通过称为辅助函数（helper functions）或糖函数（sugar functions）的便捷函数创建。它们为常见的代码惯用法提供了快捷方式，减少了用户需要编写的代码量。例如，lrn("regr.rpart") 会返回这个学习器，而不必显式创建一个新的 R6 对象。在本书中，我们大量使用糖函数，并在每章末尾提供相应的「完整形式（full form）」，以呈现完整细节。糖函数的设计覆盖了大多数用户的绝大多数使用场景；只有当你想要构建自定义对象或扩展时，才需要了解完整的 R6 后端知识。

mlr3 中的许多对象名都按照以下约定标准化：mlr_<type>_<key>，其中 <type> 是 tasks、learners、measures 以及本书将介绍的其它类，<key> 指对象的 ID。为了简化构造对象的过程，你只需要知道对象键（object key）和用于构造该类型的糖函数即可。例如：mlr_tasks_mtcars 变成 tsk("mtcars")；mlr_learners_regr.rpart 变成 lrn("regr.rpart")；mlr_measures_regr.mse 变成 msr("regr.mse")。在本书中，我们将用这种缩写形式指代所有对象。

字典（Dictionaries）

mlr3 用字典（dictionaries）存储 R6 类，字典将键（key，唯一标识符）与对象（R6 对象）关联起来。字典中的值通常通过从相应字典中检索对象的糖函数来访问，例如 lrn("regr.rpart") 是 mlr_learners$get("regr.rpart") 的一个包装器，因而是一种从 mlr_learners 加载决策树学习器的更简单方式。我们用字典来归组大量相关的对象，以便轻松地列出和检索它们。例如，你可以用 as.data.table(mlr_learners) 查看可用学习器（即在已加载包中的学习器）及其属性的概览，也可以不带任何参数调用糖函数，例如 lrn()。

背景与解释（译者注）：「字典（Dictionary）」是 mlr3 借鉴了设计模式（design pattern）中"注册表（Registry）"思想的做法：把一大群同类对象（所有任务、所有学习器、所有度量、所有重采样）用字符串键组织成一张可查询的注册表。以 tsk()/lrn()/msr()/rsmp() 四个糖函数对应 tasks/learners/measures/resamplings 四类字典，是 mlr3 入门最重要的记忆口诀。相比 caret 只把算法当作函数参数（method = "rf"），字典允许以字符串键动态加载、列出、检索对象，配合 as.data.table() 还可以表格形式查看对象属性，为自动化和可扩展性提供了基础。

mlr3viz

mlr3viz 包含 mlr3 中全部的绘图功能，底层使用 ggplot2。我们在所有图中都用 theme_minimal() 来统一美学风格，但与所有 ggplot 输出一样，用户可以完全自定义。mlr3viz 扩展了 fortify 和 autoplot，用于处理常见的 mlr3 输出，包括 Prediction、Learner 和 BenchmarkResult 对象（这些对象我们将在接下来的章节中介绍和讲解）。我们将贯穿全书介绍主要的绘图类型。学习 mlr3viz 的最佳方式是亲手实验：加载这个包，看看对某个 mlr3 对象运行 autoplot 会发生什么。绘图类型记录在相应的帮助页中，可以通过 ?autoplot.<class> 访问，例如运行 ?autoplot.TaskRegr 可以找到回归任务的不同绘图类型。

1.7 设计原则（Design Principles）

本节涉及高级 ML 或技术细节。

在从 mlr 到 mlr3 的十多年设计与演进中，我们在 mlr3 生态系统中遵循以下设计原则：

  • 面向对象编程（Object-oriented programming）。我们采用 R6，以获得清晰、面向对象的设计、对象状态更改和引用语义。这意味着常见对象（例如任务（task, 第 2.1 节）和学习器（learner, 第 2.2 节））的状态都封装在对象内部，例如跟踪模型是否已训练，而无需用户操心。我们还使用继承（inheritance）来特化对象，例如所有学习器都派生自一个提供基础功能的共同基类。
  • 表格数据（Tabular data）。采用 data.table，因为它有顶尖的计算性能，并且表格数据是一种易于进一步处理的结构。
  • 统一的表格化输入输出数据格式（Unified tabular input and output data formats）。这大大简化了 API，并允许轻松进行选择和「拆分-应用-合并（split-apply-combine）」（聚合）操作。我们把 data.table 与 R6 结合起来，在表中放置对非原子和复合对象的引用，并大量使用列表列（list columns）。
  • 防御式编程与类型安全（Defensive programming and type safety）。所有用户输入都用 checkmate (Lang 2017) 检查。我们使用 data.table，它的行为比若干 base R 方法更一致（例如，对 data.frame 索引时，如果省略 drop 参数，结果会"降维简化"）。而且我们还有大量的单元测试（unit tests）！
  • 精简依赖（Light on dependencies）。mlr 的主要维护负担之一，就是要跟上它所依赖的众多包的算法接口和行为变化。mlr3 需要的包少得多，这使得安装和维护更加容易。我们仍然提供相同的功能，但把它拆分到更多包中，每个包各自依赖较少。
  • 计算与呈现分离（Separation of computation and presentation）。mlr3 生态系统的大多数包专注于处理和变换数据、应用 ML 算法以及计算结果。我们的核心包不提供可视化，因为它们的依赖会使安装变得不必要地复杂，尤其是在无头服务器（headless servers，即没有显示器的计算机，图形库未安装）上。因此，数据和结果的可视化由 mlr3viz 提供。

背景与解释（译者注）：这六条设计原则是理解 mlr3 哲学的钥匙，与老一代 mlr 及 caret 形成明显对照：caret 的接口相对"扁平"（函数调用为主），而 mlr3 强调对象状态封装（R6）、统一数据格式（data.table + 行号引用）、类型检查（checkmate，可在错误参数传入时就报错而非藏在模型内部）、依赖最小化（故安装轻量，也兼容无图形库的服务器）以及"呈现与计算分离"（故可视化统一在 mlr3viz）。这种设计的代价是需要先理解抽象概念（任务/学习器/重采样/度量），收益是可组合性、可扩展性和生产环境鲁棒性都更强。对于有 scikit-learn 经验的中文读者，可粗略把 Task 比作 sklearn 的 Dataset + target，Learner 比作 Estimator，Resampling 比作 cross_val_score 的 cv 参数，Measure 比作 scorer。
