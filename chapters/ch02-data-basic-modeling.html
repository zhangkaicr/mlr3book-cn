在本章中，我们将介绍 mlr3 中实现机器学习基本构件的对象，以及相应的 R6 类。这些构件包括：数据（以及创建训练集和测试集的方法）、机器学习算法（及其训练与预测过程）、通过超参数（hyperparameters）对机器学习算法进行配置，以及用于评估预测质量的评价度量（evaluation measures）。

最简单地说，机器学习（machine learning, ML）就是从数据中学习"关系模型"的过程。监督学习（supervised learning）是 ML 的一个子领域，其中的数据集由带标签的观测组成，也就是说，每个数据点都由特征（features，即用来做出预测的变量）和一个目标（target，即我们试图预测的量）构成。例如，根据汽车的属性（特征），如马力和档位数，来预测汽车的每加仑行驶英里数（目标）就是一个监督学习问题，本书将多次回到这个问题上。在 mlr3 中，我们把数据集及其相关元数据称为任务（tasks, 第 2.1 节）。「任务」一词指我们要解决的预测问题。任务由用于预测的特征和待预测的目标定义，因此任意给定的数据集都可能有多个任务。例如，从马力预测每加仑行驶英里数（mpg）是一个任务，从 mpg 预测马力是另一个任务，而从汽车型号预测档位数又是一个任务。

机器学习/监督学习（Machine Learning/Supervised Learning）

监督学习可以进一步分为回归（regression）——预测数值型目标值，例如预测汽车的 mpg——以及分类（classification）——预测类别型值/标签，例如预测汽车的型号。第 13 章还讨论其他任务，包括代价敏感分类（cost-sensitive classification）和无监督学习（unsupervised learning）。对于任何监督学习任务，目标都是构建一个能捕捉特征与目标之间关系的模型，其目往往是训练模型学习数据中的关系，以便对新的、之前从未见过的数据做出预测。严格来说，模型是「从特征向量到预测结果」的一个映射。根据任务的不同，预测可以采取多种形式；例如，在分类中，预测可以是预测的标签，也可以是一组预测的概率或分数。模型是通过把训练数据送入机器学习算法（如决策树、支持向量机、神经网络等）归纳而来的。机器学习算法在 mlr3 中被称为学习器（learners, 第 2.2 节），因为它们给定数据后即可学习模型。每个学习器都有一个参数化空间，潜在的模型从该空间中抽取；在训练过程中，这些参数被拟合以最好地匹配数据。例如，当训练线性回归模型时，参数可以是用于各个特征的系数。在训练期间，大多数机器学习算法通过优化一个损失函数（loss function）来完成「拟合/训练」，该函数量化训练数据中真实目标值与模型预测之间的失配程度。

回归（Regression）分类（Classification）模型（Model）损失函数（Loss Function）

模型要想最为有用，就应该在训练数据之外泛化（generalize），对新的、模型此前「未见过的」数据也能做出「好」的预测（第 2.2.2 节）。检验这一点最简单的方法，就是把数据分成训练数据和测试数据——模型在训练数据上训练，然后用独立的测试数据评估模型，以无偏的方式考核模型在多大程度上学会了数据背后的真实关系（第 3 章）。这一评估过程估计的是模型的泛化误差（generalization error），即我们预期模型在一般情况下表现如何。估计泛化误差的模型评估方式与数据划分方式有很多种（第 3.2 节）。

训练/测试数据（Train/Test Data）泛化误差（Generalization Error）

背景与解释（译者注）：本节是全书「问题定义」的起点。需要注意几个术语：特征（feature）也称自变量/解释变量/（传统统计中）协变量，目标（target）也称响应变量（response variable）/因变量；「标签（label）」专指分类问题中的目标取值。"训练/测试划分"本质上是用一个暂时"扣住"不放的真值子集来模拟未来数据，从而无偏地估计泛化误差。文中推荐的经典教材分别对应 ESL（The Elements of Statistical Learning《统计学习基础》，Hastie 等）、ISLR（An Introduction to Statistical Learning《统计学习导论》，James 等）以及 Bishops 的《模式识别与机器学习》（PRML）；三者由浅入深，ISLR 最适合作入门读物。这与中国读者常读的《统计学习方法》（李航）可互为对照。

在接下来的几节中，我们将以回归为例来看 mlr3 的各个构件，然后在第 2.5 节考虑如何将其扩展到分类。

2.1 任务（Tasks）

任务（Task）是包含（通常为表格形式的）数据以及定义机器学习问题的附加元数据的对象。元数据中例如包含监督学习问题的目标特征名。这些信息在需要时会被自动提取，因此用户不必在每次训练模型时都指定预测目标。

UTF8 列名（UTF8 Column Names）

由于许多机器学习模型无法正确处理任意的 UTF8 名称，mlr3 默认会在传入 as_task_regr()（以及其他任务构造函数）的列名包含非 ASCII 字符，或不符合 R 变量命名规范时抛出错误。因此，我们建议尽可能用 make.names() 转换名称。你也可以通过设置 options(mlr3.allow_utf8_names = TRUE) 绕过此检查（但如果在后面出现错误请不要惊讶，尤其是把对象传给其他包的时候）。

背景与解释（译者注）：「行 ID（row_ids）≠ 行号（row number）」是 mlr3 设计中容易让新手困惑、却又非常重要的一个点。在 base R 中，df[3, ] 靠"位置"取行；一旦过滤、合并后位置就变了。mlr3 借鉴数据库"主键"思想，给每个观测一个稳定的、唯一的行 ID（通常来自原数据框的行名），$filter()、$data()、$train(row_ids = ...)、$predict(row_ids = ...) 都按主键对接。好处是：你可以把同样的 splits$train 行 ID 集合传给任意任务/学习器，训练集与测试集的划分与数据行本身的物理顺序无关；也便于将来对接数据库后端。注意 $data(rows = task$row_ids[2]) 中 task 指的是上文被过滤后只剩 3 行的那个随机任务，因此取到的是它"当前第 2 行"对应的行 ID（4），而非 tsk_mtcars 的。

2.1.3 任务修改器（Task Mutators）

任务创建之后，你可能需要对任务执行一些操作，比如过滤到行和列的子集，这在手动创建训练/测试划分，或在给定特征子集上拟合模型时经常有用。上面我们看到了如何用 $data() 访问底层数据集的子集，但是，这不会改变底层任务本身。因此，我们提供修改器（mutators），它们会原地（in place）修改给定 Task，这可以在下面的例子中看到。

修改器（Mutators）

按特征（列）取子集可以用 $select()，把想要的特征名作为字符向量传入；按观测（行）取子集则用 $filter()，把行 ID 作为数值向量传入。

tsk_mtcars_small = tsk("mtcars") # initialize with the full task
tsk_mtcars_small$select("cyl") # keep only one feature
tsk_mtcars_small$filter(2:3) # keep only these rows
tsk_mtcars_small$data()
    mpg cyl
1: 21.0   6
2: 22.8   4

tsk_mtcars_wrong = tsk_mtcars

背景与解释（译者注）：$select()/ $filter()/ $rbind()/ $cbind() 这四个"修改器"会原地修改任务对象（R6 引用语义）。这是与 tidyverse "返回新对象、不修改原对象"哲学的最大差异：dplyr 中 df %>% filter() 得到新对象，原对象不动；而 mlr3 的 task$filter() 直接改源对象。如果你习惯了 dplyr，一定要警惕：需要保留原任务时务必先 $clone()（深拷贝）。此外 $filter(2:3) 传入的是行 ID 2 和 3，而不是"第 2、3 行"——再次体现行 ID 语义。实际项目中常见的正确用法是：训练前用 task$clone 构造 task_train，对它做特征工程（如只保留部分特征），再用另一克隆保存测试所需全特征。

2.2 学习器（Learners）

要运行一个机器学习实验，学习器要经历两个阶段（图 2.3）：

  • 预测（Predicting）：把新数据（可能是原始数据集的不同划分）传给已训练学习器的 $predict() 方法，以预测目标值。

2.2.3 超参数（Hyperparameters）

Learner 封装一个机器学习算法及其超参数，超参数影响算法的运行方式，可以由用户设置。超参数可能影响模型如何训练或如何做出预测，而决定如何设置超参数可能需要专业知识。超参数可以被自动优化（第 4 章），但在本章中，我们将专注于如何手动设置它们。

ParamSet

在我们的决策树示例中，可以从 ParamSet 输出推断出：

  • cp 必须是「double」（ParamDbl），取值在 0（lower）和 1（upper）之间，默认值为 0.01（default）。
  • keep_model 必须是「logical」（ParamLgl），取值为 TRUE 或 FALSE，默认为 FALSE。

用 list 设置超参数（Setting Hyperparameters Using a list）

[1] 1

$maxdepth
[1] 1

lrn("regr.rpart", cp = 2, maxdepth = 2)
Error in `self$assert()`:
! Assertion on 'xs' failed: cp: Element 1 is not <= 1.

背景与解释（译者注）：paradox 是 mlr3 生态的"参数系统"包，负责描述一个学习器有哪些超参数、每个参数的类型与合法范围、彼此的依赖关系。它的 ParamDbl/ParamInt/ParamFct/ParamLgl/ParamUty 对应 Python 里 scikit-learn 的 _validate_params 与 scipy.stats 搜索空间（如 randint、rvs），或 tidymodels 中 tune() + parameters() 的对象。理解 $param_set$values 只是"已设置参数清单"这一关键点，就能避免踩坑：直接整表覆盖 $values 会清空其余设置。rpart 的 xval 默认被 mlr3 改为 0 是出于性能考虑（内部 10 折 CV 纯属浪费），这种"与底层包默认值不同"的改动都会记录在帮助页中，值得留意。

2.2.3.3 超参数依赖（Hyperparameter Dependencies）

本节涉及高级 ML 或技术细节。

更复杂的超参数空间可能包含依赖关系，即设置某个超参数以另一超参数的取值为条件；这在模型调优（model tuning）语境下最为重要（第 4 章）。一个例子是支持向量机（lrn("regr.svm")）。$deps 字段返回一个 data.table，列出 Learner 中的超参数依赖。例如，可以看到 cost（id 列）参数依赖于 type（on 列）参数。

2.2.4 基线学习器（Baseline Learners）

在我们继续学习学习器评估之前，我们先强调一类重要的学习器。这些是极其简单或「弱」的学习器，称为基线（baselines）。基线的价值在于模型比较（第 3 章）以及作为回退学习器（fallback learners）（第 5.1.1 节、第 10.2.2 节）。对于回归，我们实现了基线 lrn("regr.featureless")，它总是把新值预测为训练数据中目标值的平均数（如果 robust 超参数设为 TRUE，则为中位数）：

背景与解释（译者注）：「基线（baseline）」在机器学习里指"最朴素直白的预测器"：回归基线永远预测训练目标均值/中位数，分类基线永远预测最频繁类（或按频率随机抽）。它回答的问题是"你的模型到底学到东西没有"——如果你的模型连"永远猜平均值"都打不过，那说明模型（或训练过程、数据预处理）出了问题。这与统计学中"空模型/截距模型（null model / intercept-only model）"、以及 ISLR 中的"可减少误差 vs 不可减少误差"（irreducible error）思想一脉相承。在信用卡（german_credit）等不平衡数据上，基线甚至能拿到高"准确率"，正因如此，仅看精度是不足信的（见 2.5.4 节）。

可以同时计算多个度量，方法是向 $score() 传入多个度量。例如，下面我们同时计算均方误差（"regr.mse"）和平均绝对误差（"regr.mae"）的性能——注意我们使用 msrs() 一次加载多个度量。

msrs()

prediction$score(measures)
regr.mse regr.mae 
  14.603    2.937

本节涉及高级 ML 或技术细节。

  • msr("time_train") —— 训练一个模型所花的时间。

2.4 我们的第一个回归实验（Our First Regression Experiment）

我们现在已经看到了如何训练模型、做出预测并给它们打分。我们还没有尝试的，是判断我们的预测是否「好」。所以，在我们看 mlr3 的构件如何扩展到分类之前，我们先短暂停顿一下，把上面所有内容组合到一个评估预测质量的小实验中。我们将通过比较一个无特征（featureless）回归学习器和一个改了超参数的决策树的性能来做这件事。

library(mlr3)
set.seed(349)
# load and partition our task
tsk_mtcars = tsk("mtcars")
splits = partition(tsk_mtcars)
# load featureless learner
lrn_featureless = lrn("regr.featureless")
# load decision tree and set hyperparameters
lrn_rpart = lrn("regr.rpart", cp = 0.2, maxdepth = 5)
# load MSE and MAE measures
measures = msrs(c("regr.mse", "regr.mae"))
# train learners
lrn_featureless$train(tsk_mtcars, splits$train)
lrn_rpart$train(tsk_mtcars, splits$train)
# make and score predictions
lrn_featureless$predict(tsk_mtcars, splits$test)$score(measures)
regr.mse regr.mae 
  63.288    6.409 
lrn_rpart$predict(tsk_mtcars, splits$test)$score(measures)
regr.mse regr.mae 
  21.806    3.664

实验开始前，我们加载了 mlr3 库并设置了一个种子（seed）。我们用 tsk() 加载 mtcars 任务，然后用默认的 2/3 划分比例的 partition 来切分。接下来，我们用一个 lrn() 函数加载了无特征基线学习器（"regr.featureless"）。然后，我们加载了一个决策树（lrn("regr.rpart")）但把复杂度参数和树的最大深度从默认值改掉。我们接着用 msrs() 一次加载多个度量：均方误差（MSE：regr.mse）和平均绝对误差（MAE：regr.mae）。所有对象加载完毕后，我们训练了模型，确保把相同的训练数据传给二者。最后，我们从训练好的模型做出预测并打分。对 MSE 和 MAE 来说，数值越小越「好」（Minimize: TRUE），因此我们可以得出结论：我们的决策树比无特征基线表现更好。在第 3.3 节中，我们将看到如何用 benchmark() 以更高效的方式形式化模型之间的比较。

现在我们把所有东西组合起来之后，你可能会注意到，我们的学习器和度量都带有 "regr." 前缀，这是一个便捷的提醒：我们正在处理一个回归任务，因此必须使用为回归构建的学习器和度量。在下一节中，我们将把 mlr3 的构件扩展到分类任务，分类任务使用带有 "classif." 前缀的学习器和度量。

背景与解释（译者注）：这个"第一个实验"串联了 Task → Learner → Resampling(partition) → Prediction → Measure 完整链路。两点值得留意：① set.seed(349) 固定了随机划分与采样，保证结果可复现；② 代码中 `lrn("regr.rpart", cp = 0.2, maxdepth = 5)` 把决策树的复杂度参数提升到 0.2（默认 0.01），相当于给树"剪枝"，避免过拟合（对应决策树的 bias-variance 权衡，参见 ESL 第 9 章/ISLR 第 8 章）。在「基线 vs 模型」比较中，MSE 由 63.29 降到 21.81 是很明显的提升。前缀体系 `regr.*`/`classif.*` 是 mlr3 命名空间约定，与 sklearn 文档中 `classifier/regressor` 的模块划分作用类似。

2.5 分类（Classification）

分类问题是这样一类问题：模型预测的是离散的、类别型的目标，而不是连续的数值量。例如，根据企鹅的物理特征预测企鹅的物种就是一个分类问题，因为物种有确定的范围。mlr3 确保所有任务的接口尽可能相似（甚至完全相同），因此我们不会重复上一节的内容，只专注于那些让分类成为一个独特机器学习问题的差异。我们将首先通过一个与第 2.4 节非常相似的实验来展示回归与分类的相似之处，所用的代码你现在应该已经熟悉了。然后我们转向任务、学习器和预测的差异，最后看阈值化（thresholding）——一种分类特有的方法。

2.5.4 PredictionClassif、混淆矩阵（Confusion Matrix）与阈值化（Thresholding）

PredictionClassif 对象与其回归对应的对象相比有两个重要差异。第一，增加了 $confusion 字段；第二，增加了 $set_threshold() 方法。

PredictionClassif

混淆矩阵（Confusion matrix）

混淆矩阵是一种展示分类（response）预测质量的热门方式，通过它可以看到模型是否擅长（误）分类某个特定类的观测。对于二分类和多分类，混淆矩阵存放在 PredictionClassif 对象的 $confusion 字段中：

混淆矩阵（Confusion Matrix）$confusion
prediction$confusion

response    Adelie Chinstrap Gentoo
  Adelie        48         2      0
  Chinstrap      4        14      1
  Gentoo         0         0     45

混淆矩阵的行是预测类，列是真实类。所有非对角线元素都是被错误分类的观测，所有对角线元素都是正确分类的。mlr3 在数据被分析时自动检测每个观测属于哪个类。在本例中，分类器对所有企鹅的分类都做得相当好，但也有可能我们发现它只把 Adelie 种分类得好，却经常把 Chinstrap 和 Gentoo 混淆，等等。

我们将在第 3.4 节更详细地回到二分类（误）分类的概念上。

背景与解释（译者注）：混淆矩阵（confusion matrix）是"分类体检表"。二分类下四个格子构成两个主要尺度：① 精确率（precision）= TP/(TP+FP)，"预测为正的里面有多少是真的正"；② 召回率/灵敏度（recall/sensitivity）= TP/(TP+FN)，"真正的正类里被找出多少"。真正例率 TPR = 召回率，假正例率 FPR = FP/(FP+TN)。这些量是 ROC 曲线与 PR 曲线的原料（第 3 章）。注意"正类"必须明确：你把 M 还是 R 当 positive，混淆矩阵解读就完全不同。文中 'M' 作为正类的例子里，FP=13 意味着把 13 个真岩石误报为矿，FN=13 则意味着漏掉了 13 个矿。医疗场景常要求高灵敏度（少漏诊），金融反欺诈则常要求高精确率（少误伤）。

阈值化（Thresholding）

我们将讨论的与回归相比的最后一个重要差异是阈值化。我们之前看到，默认的 response 预测类型就是预测概率最高的类。对于预测概率为 \(p_1,\dots,p_k\) 的 \(k\) 个类，这等价于说 response = argmax\(\{p_1,\dots,p_k\}\)。如果最大概率不唯一，即多个类被预测为具有最高的概率，则从这些类中随机选择作为 response。在二分类中，这意味着如果预测正类的概率大于 50%，就选正类，否则选负类。

阈值化（Thresholding）

这个 50% 的值被称为阈值（threshold），在以下情形改变这个阈值可能有用：存在类别不平衡（class imbalance，即数据集中某一类过代表或欠代表）、不同类别有不同的成本，或者仅仅是因为偏好在某个类别上「过度」预测。举例来说，我们取 tsk("german_credit")，其中有 700 个信用良好客户和 300 个信用不佳客户。我们很容易就能造出一个准确率约「70%」的模型——只要总是预测客户信用良好：

task_credit = tsk("german_credit")
lrn_featureless = lrn("classif.featureless", predict_type = "prob")
split = partition(task_credit)
lrn_featureless$train(task_credit, split$train)
prediction = lrn_featureless$predict(task_credit, split$test)
prediction$score(msr("classif.acc"))
classif.acc 
     0.6576 
autoplot(prediction)

虽然这个模型的性能表面上看似乎不错，但实际上它只是忽略了所有「bad」客户——这在金融例子中会引发大问题，在医疗保健任务以及其他假正例（false positive）比假反例（false negative）代价更高的场景中同样如此（关于代价敏感分类，见第 13.1 节）。

阈值化允许以不同的概率阈值来选择类别，因此，我们不再是在 P(good) < 50% 时预测客户信用不佳，而是可能在 P(good) < 70% 时就预测信用不佳——注意我们是如何用正类的措辞来表达的，本任务中的正类是 'good'。让我们看看实际效果：

prediction$set_threshold(0.7)
prediction$score(msr("classif.acc"))

prediction = lrn_rpart$predict(task_credit, split$test)
prediction$score(msr("classif.acc"))

虽然我们的模型总体上表现得「更差」，即准确率更低，但它仍然是一个「更好」的模型，因为它更准确地捕捉了类之间的关系。

在二分类设置下，$set_threshold() 只需要一个数值参数，它对应正类的阈值——因此确保你的任务中正确设置正类至关重要。

在多分类中，阈值化的运作方式是：先给 \(n\) 个类各分配一个阈值，把每个类的预测概率除以各自的阈值，得到 \(n\) 个比值，然后选择比值最高的那个类。例如，假设我们在预测一个新观测将属于 A、B、C 还是 D 类，并且已预测 \(P(A = 0.2), P(B = 0.4), P(C = 0.1), P(D = 0.3)\)。假设所有类的阈值都相同，都是 1：

probs = c(0.2, 0.4, 0.1, 0.3)
thresholds = c(A = 1, B = 1, C = 1, D = 1)
probs/thresholds
  A   B   C   D 
0.2 0.4 0.1 0.3

因此我们会预测这个观测属于 B 类，因为它的比值最高。然而，我们可以改变阈值，让 D 的阈值最低、最容易被预测到，A 的阈值最高，而 B 和 C 的阈值相等：

thresholds = c(A = 0.5, B = 0.25, C = 0.25, D = 0.1)
probs/thresholds
  A   B   C   D 
0.4 1.6 0.4 3.0

现在我们的观测将被预测为 D 类。

在 mlr3 中，这是通过把命名列表（named list）传给 $set_threshold() 实现的。下面用 tsk("zoo") 演示。在改变阈值之前，有些类从未被预测到，而有些类的被预测次数超过了它们的真实出现次数。

library(ggplot2)
library(patchwork)

tsk_zoo = tsk("zoo")
splits = partition(tsk_zoo)
lrn_rpart = lrn("classif.rpart", predict_type = "prob")
lrn_rpart$train(tsk_zoo, splits$train)
prediction = lrn_rpart$predict(tsk_zoo, splits$test)
before = autoplot(prediction) + ggtitle("Default thresholds")
new_thresh = proportions(table(tsk_zoo$truth(splits$train)))
new_thresh

      0.38235       0.20588       0.07353       0.11765       0.05882

我们再次看到，阈值化之后模型能更好地代表所有类别。在这个例子中，我们把新阈值设为训练集中各类别的比例。这被称为逆向加权（inverse weighting），因为我们在选择比值最高的标签之前，用这些类别比例去除预测概率。

在第 13.1 节中，我们将研究代价敏感分类（cost-sensitive classification），其中的混淆矩阵每个格子都有不同的相关代价。

背景与解释（译者注）：阈值化是分类中最实用也最容易忽略的"免费杠杆"。核心思想：概率模型给的 \(p\) 只是"信心分数"，把它切成哪两类取决于业务。二分类时默认 0.5 阈值隐含假设"两类误判代价对称、类别大致平衡"，一旦类别不平衡或误判代价不对称（如癌症漏诊 vs 误诊、风控放款损失 vs 拒贷损失），0.5 就未必最优。调高阈值（如只在 P(good)≥0.7 才放款）会降低假正例（误放给坏客户）但损失部分好客户，通常伴随准确率下降——本书因此强调"性能指标要与业务目标对齐"。多分类的推广是"比值法"：\(\hat{y} = \arg\max_i p_i / t_i\)；把阈值设成类别先验比例（逆向加权）会让稀有类更容易被"选上"。注意 set_threshold 也有原文一个印刷问题，见下节正文。

2.6 任务列角色（Task Column Roles）

本节涉及高级 ML 或技术细节。

既然我们已经覆盖了回归和分类，我们简要回到任务，特别是列角色（column roles），它们用于进一步定制任务。列角色被 Task 对象使用，用来定义能被学习器和其他对象用于与任务交互的重要元数据。名副其实，它们把特定的角色分配给数据中的列，我们已经看到了一些正在发挥作用的角色，例如目标和特征。共有七种列角色：

  1. "feature"：用于预测的特征。
  2. "target"：待预测的目标变量。
  3. "name"：行名/观测标签，例如对 mtcars 而言，就是 "model" 列。
  4. "order"：用于对 $data() 返回的数据进行排序的变量；必须能用 order() 排序。
  5. "group"：用于在重采样（resampling）时保持观测在一起的变量。
  6. "stratum"：用于在重采样时进行分层（stratify）的变量。
  7. "weights_learner"：训练时学习器使用的权重。只能有一个数值列承担该角色。
  8. "weights_measure"：打分时度量使用的权重。只能有一个数值列承担该角色。

背景与解释（译者注）：原文此处列出了 8 项却声称"七种（seven）列角色"，属于原文的笔误——第 7、8 项 weights_learner/weights_measure 实际是互相关联的"行权重"角色；按类别划分，这 8 项分别覆盖 feature/target/name/order/group/stratum/weights。正确理解应以实际列出的 8 种为准。特殊的是 order、group、stratum、weights_* 这几类"非特征"角色：它们不会作为 x 进入模型，而是向数据添加结构语义（排序、随机化约束、样本权重）。ISLR 第 5 章讨论交叉验证时提到的"分组/分层抽样"在本框架下就对应 group 与 stratum 角色，第 3 章 3.2.6 节会详述。

我们在第 2.1 节中已经看到特征和目标如何工作，它们也是每个任务必须拥有的仅有的列角色。在第 3.2.6 节中，我们将研究 stratum 和 group 列角色。所以，现阶段我们只看 order 和 weight。我们不会深入讨论 name，它主要用于绘图，并且几乎总是底层数据的 rownames()。

列角色用 $set_col_roles() 更新。当我们设置 "order" 列角色时，数据会按该列（或多列）排序。在下面的例子中，我们设置 "order" 列角色，然后通过包含 ordered = TRUE 让数据按该列排序：

df = data.frame(mtcars[1:2, ], idx = 2:1)
tsk_mtcars_order = as_task_regr(df, target = "mpg")
# original order
tsk_mtcars_order$data(ordered = TRUE)
   mpg am carb cyl disp drat gear  hp idx  qsec vs    wt
1:  21  1    4   6  160  3.9    4 110   2 16.46  0 2.620
2:  21  1    4   6  160  3.9    4 110   1 17.02  0 2.875
# order by "idx" column
tsk_mtcars_order$set_col_roles("idx", roles = "order")
tsk_mtcars_order$data(ordered = TRUE)
   mpg am carb cyl disp drat gear  hp  qsec vs    wt
1:  21  1    4   6  160  3.9    4 110 17.02  0 2.875
2:  21  1    4   6  160  3.9    4 110 16.46  0 2.620

在这个例子中，我们可以看到，通过把 "idx" 设置为 "order" 列角色，当我们运行 $data() 时它不再被用作特征，而是按其值对观测进行排序。这个元数据不会传给学习器。

weights_learner 列角色用于给数据点赋予不同的权重。这样做的原因之一是严重类别不平衡的分类任务，此时给少数类赋予更大的权重可能提高模型对该类的预测性能。例如在 breast_cancer 数据集中，良性肿瘤的实例多于恶性肿瘤，因此如果我们想更好地预测恶性肿瘤，就可以对数据偏向该类进行加权：

cancer_unweighted = tsk("breast_cancer")
summary(cancer_unweighted$data()$class)
malignant    benign 
      239       444 
# add column where weight is 2 if class "malignant", and 1 otherwise
df = cancer_unweighted$data()
df$weights = ifelse(df$class == "malignant", 2, 1)

# create new task and role
cancer_weighted = as_task_classif(df, target = "class")
cancer_weighted$set_col_roles("weights", roles = "weights_learner")

# compare weighted and unweighted predictions
split = partition(cancer_unweighted)
lrn_rf = lrn("classif.ranger")
lrn_rf$train(cancer_unweighted, split$train)$
  predict(cancer_unweighted, split$test)$score()
classif.ce 
   0.05333 
lrn_rf$train(cancer_weighted, split$train)$
  predict(cancer_weighted, split$test)$score()
classif.ce 
      0.04

在这个例子中，加权提升了整体模型性能（但更严格全面的比较方法见第 3 章）。并非所有模型都能处理任务中的权重，所以请检查学习器的属性，确保这个列角色按预期被使用。

背景与解释（译者注）：「样本权重（sample weights）」是处理类别不平衡与"不等重要性样本"的通用技术。注意两个角色：weights_learner 把权重传给训练算法（如 ranger 里对应 case.weights，xgboost 里对应 w），weights_measure 在打分时让不同样本的误差权重不同。支持的算法才能在 $properties 里看到 weights（如 ranger 支持），否则会报错。handler: 在 as_task_classif 之后调用 $set_col_roles 把它标为权重列，该列不会进入特征集合。相比"过采样/欠采样（oversampling/undersampling）"，加权不改变样本本身，只是改变损失贡献，更"温和"；classif.ranger 在此例中把分类误差从 0.053 降到 0.04。注意必须给两个任务传相同的划分（这里 split 来自 unweighted 任务，因为映射到行 ID 一致才可比）。

2.7 支持的机器学习算法（Supported Learning Algorithms）

mlr3 以 Learner 的形式支持许多机器学习算法（有些有多个实现）。它们主要由 mlr3、mlr3learners 和 mlr3extralearners 包提供。不过，所有实现新任务（第 13 章）的包也会附带少数简单算法。

mlr3 中内置的学习器列表刻意保持很小，以避免庞大的依赖集：

  • 无特征学习器（"regr.featureless"/"classif.featureless"），它们是基线学习器（第 2.2.4 节）。
  • 调试学习器（"regr.debug"/"classif.debug"），用于调试代码（第 10.2 节）。
  • 分类与回归树（也称 CART："regr.rpart"/"classif.rpart"）。

mlr3learners 包包含 mlr 团队挑选的一组算法（和一些实现），我们建议把它们作为大多数实验的良好起点：

  • 线性回归（"regr.lm"）和逻辑回归（"classif.log_reg"）。
  • 惩罚广义线性模型（penalized generalized linear models），惩罚要么作为超参数暴露（"regr.glmnet"/"classif.glmnet"），要么被自动优化（"regr.cv_glmnet"/"classif.cv_glmnet"）。
  • 加权 \(k\) 近邻（Weighted k-Nearest Neighbors）（"regr.kknn"/"classif.kknn"）。
  • 克里金 / 高斯过程回归（Kriging / Gaussian process regression）（"regr.km"）。
  • 线性判别分析（"classif.lda"）和二次判别分析（"classif.qda"）。
  • 朴素贝叶斯分类（"classif.naive_bayes"）。
  • 支持向量机（"regr.svm"/"classif.svm"）。
  • 梯度提升（Gradient boosting）（"regr.xgboost"/"classif.xgboost"）。
  • 随机森林回归与分类（"regr.ranger"/"classif.ranger"）。

其余大多数受支持的学习器都在 mlr3extralearners 中。你可以在 https://mlr-org.com/learners.html 找到最新的学习器列表。

2.8 结论（Conclusion）

在本章中，我们覆盖了 mlr3 的基本构件。我们先介绍了基础的 ML 方法论，然后展示了它在 mlr3 中如何实现。我们首先看了 Task 类，它用于定义机器学习任务或要解决的问题。然后我们看了 Learner 类，它封装机器学习算法、超参数和其他元信息。最后，我们考虑了如何用 Measure 类的对象评估机器学习模型。在看回归实现之后，我们把以上全部扩展到分类设置，最后又看了一些关于任务及 mlr3 中实现的学习算法的额外细节。本书其余部分将基于本章见到的基本元素进一步展开，首先在第 3 章介绍更高级的模型比较方法，然后在第 4 章用自动化超参数调优来提高模型性能。
