一个有监督的机器学习模型只有在具有良好的泛化性能（generalization performance）时才能实际部署使用，所谓泛化性能是指它对新的、未见过的数据也能很好地泛化。准确地估计泛化性能对于机器学习应用与研究的许多方面都至关重要——无论我们是想公平地将一个新算法与既有算法比较，还是想为某个特定任务找到最佳算法。性能估计（performance estimation）的概念提供了关于模型在新数据上泛化得有多好的信息，并在模型比较（3.3 节）、模型选择与超参数调优（第 4 章）中扮演着重要角色。

泛化性能（Generalization Performance）

评估模型的泛化性能，首先要选择一个适合当前任务与评估目标的性能度量（performance measure）。正如我们在2.3 节中所见，性能度量通常计算一个数值得分，用于表示模型预测与真实标签（ground truth）的匹配程度（当然在2.3.3 节中也看到了一些技术性度量）。一旦我们确定了性能度量，下一步就是采用一种策略，规定如何利用现有数据来估计泛化性能。用同一份数据既训练又测试模型是一个糟糕的策略，因为它会导致过于乐观的性能估计。例如，一个过拟合（overfitted，拟合数据拟合得过于紧密）的模型可能仅仅通过死记硬背就在训练数据上作出完美预测，而对新数据只能随机猜测。在2.2.1.1 节中我们介绍了partition()，它把数据集划分成训练数据——用于训练模型的数据——和测试数据——用于测试模型并估计泛化性能的数据，这被称为留出法（holdout strategy，3.1 节），也是本章的起点。随后我们将考虑更先进的泛化性能评估策略（3.2 节），研究比较模型的稳健方法（3.3 节），最后讨论针对二分类（binary classification）的专业化性能度量（3.4 节）。关于度量与性能估计的深入综述，我们推荐参考 Japkowicz 和 Shah（2011）的著作。

重采样并不能避免模型过拟合（Resampling Does Not Avoid Model Overfitting）

一个常见的误解是：留出法和其他更先进的重采样策略能够防止模型过拟合。事实上，这些方法只是让过拟合变得可见，因为我们可以分别评估训练集与测试集上的性能。重采样策略还使我们能够对泛化误差作出（近乎）无偏的估计。

背景与解释（译者注）：这里点出了机器学习评估中一个极易混淆的核心概念：重采样（交叉验证、留出法等）的作用是估计泛化性能，而不是消除过拟合。过拟合是由模型复杂度与数据量、噪声之间的失衡造成的，属于学习算法与数据本身的属性；重采样只是通过把训练与评估数据分开，让我们能"看见"训练性能与测试性能之间的差距，从而诊断出过拟合。这一点在后续章节的超参数调优中尤为重要：如果只在训练集上选超参数，就会选择到过拟合的模型；而通过重采样估计出的性能来选模型，才能缓解这一问题。

3.1 留出法与打分（Holdout and Scoring）

机器学习的一个重要目标是学习一个模型，以便用它对新数据作出预测。为了让这个模型尽可能准确，理想情况下我们应当用尽可能多的数据来训练它。然而数据是有限的，而且正如我们讨论过的，不能用同一份数据既训练又测试模型。在实践中，人们通常会创建一个中间模型（intermediate model），它用可用数据的一个子集训练，然后用剩余的数据测试。这个中间模型的性能——通过将模型预测与真实标签比较获得——就是对最终模型的泛化性能的估计，这里的最终模型指在所有数据上拟合的模型。

中间模型（Intermediate Model）

留出法（holdout strategy）是创建这种训练/测试数据集划分的简单方法：按一个设定比例把原始数据分成两份。理想情况下，训练数据集应尽可能大，以便中间模型尽可能好地代表最终模型。如果训练数据太小，中间模型不太可能表现得和最终模型一样好，从而导致带悲观偏倚（pessimistically biased）的性能估计。另一方面，如果训练数据太大，那么由于测试数据太少导致的高方差，我们将无法获得可靠的泛化性能估计。作为一种经验法则（rule of thumb），通常用 2/3 的数据训练、1/3 的数据测试，这在泛化性能估计的偏差与方差之间提供了合理的权衡 (Kohavi 1995; Dobbin and Simon 2011)。

留出法（Holdout）

在第 2 章中，我们用partition()对Task对象应用留出法。回顾一下，让我们以 2/3 留出（默认划分比例）来切分 tsk("penguins")：

tsk_penguins = tsk("penguins")
splits = partition(tsk_penguins)
lrn_rpart = lrn("classif.rpart")
lrn_rpart$train(tsk_penguins, splits$train)
prediction = lrn_rpart$predict(tsk_penguins, splits$test)

现在我们可以通过评估中间模型预测的质量来估计最终模型的泛化性能。正如我们在2.3 节所见，这只需选择一个或多个度量并把它们传给 $score() 函数。因此，要估计最终模型的准确率，我们就把准确率度量传给中间模型：

prediction$score(msr("classif.acc"))
classif.acc 
     0.9386
为性能估计打乱观测（Permuting Observations for Performance Estimation）

切分数据时，至关重要的是先对观测进行打乱（permute），以去除数据排序中编码的任何信息。在真实世界的数据集中，数据顺序往往具有信息量，例如医院数据很可能按病人入院时间排序。在 tsk("penguins") 中，数据是有序排列的：前 152 行的标签都是 'Adelie'，接下来 68 行是 'Chinstrap'，最后 124 行是 'Gentoo'；因此如果我们不打乱数据，最终得到的模型可能只在某一个或两个物种上训练过。

partition() 以及下文讨论的所有重采样策略都会自动随机切分数据以防止这类偏倚（所以别忘了设置随机种子以保证可复现性）。每个集合内部的数据由于实现细节可能仍然有序，但只要集合之间的数据被洗牌过，这就没有问题。

许多性能度量基于"可分解损失"（decomposable losses），这意味着它们先在观测级别上计算预测值与真实标签值之间的差异，然后把测试集上的个体损失值聚合成一个数值得分。例如，分类准确率比较的是Prediction对象中 response 列的预测值与 truth 列的真实标签值是否相同。因此，对每个观测而言，可分解损失取值为 1（当 response 与 truth 相同）或 0（否则）。$score() 方法把这些个体损失值汇总成一个平均值——即我们预测正确的百分比。其他不可分解的性能度量则作用于一组观测整体，我们会在 3.4 节讨论 AUC 度量时再详细回到这一点。 图 3.1 展示了 $score() 方法的输入-输出行为，我们会在转向更复杂的评估策略时再回到此图。

3.2 重采样（Resampling）

重采样策略反复地把所有可用数据切分成多个训练集与测试集，其中一次重复对应 mlr3 中所说的一个"重采样迭代"（resampling iteration）。然后在每个训练集上训练一个中间模型，并用测试集度量每一次重采样迭代中的性能。最后通过在多次重采样迭代上聚合性能得分来估计泛化性能（图 3.2）。通过重复数据切分过程，数据点被反复用于训练和测试，从而能更高效地利用全部可用数据来估计性能。此外，较多的重采样迭代次数可以降低得分的方差，从而得到更可靠的性能估计。这意味着性能估计更不容易受到"运气不好"的划分（例如一个不能反映原始数据分布的划分）的影响。

存在多种重采样策略，各有利弊，具体取决于可用样本的数量、任务的复杂度以及模型的类型。

一种非常常见的策略是 k 折交叉验证（k-fold cross-validation, CV），它把数据随机划分成 \(k\) 个不重叠的子集，称为"折"（folds，图 3.3）。这 \(k\) 个模型总是在其中 \(k-1\) 折上训练，剩下的一折作为测试数据；这个过程重复进行，直到每一折恰好都充当过一次测试集。最后把每一折得到的 \(k\) 个性能估计聚合起来，通常采用取平均的方式。CV 保证每个观测恰好会在某个测试集中出现一次，从而能高效利用可用数据进行性能估计。\(k\) 的常见取值为 5 和 10，分别意味着每个训练集由原始数据的 4/5 或 9/10 组成。CV 有若干变体，包括重复 k 折交叉验证（repeated k-fold cross-validation，把 k 折过程重复多次），以及留一交叉验证（leave-one-out cross-validation, LOO-CV），其中折数等于观测数，因此每一折的测试集只包含一个观测。

交叉验证（Cross-validation）

子采样（subsampling）和自助法（bootstrapping）是两种相关的重采样策略。子采样从原始数据集中以无放回（without replacement）的方式随机抽取一定比例（常见为 4/5 和 9/10）的数据作为训练集。模型在这份数据上训练，然后在剩余数据上测试，这个过程重复 \(k\) 次。它与 k 折 CV 的不同之处在于，测试数据的子集可能重叠。自助法遵循与子采样相同的过程，但数据是从原始数据集中有放回（with replacement）地抽取的。通常自助法样本的数量等于原始数据集的大小。这意味着一个观测可能在训练数据中被选中多次（从而被重复），（但每个测试数据集中至多出现一次）。平均而言，自助法过程中约 \(1 - e^{-1} \approx 63.2\%\) 的数据点会出现在训练集中，称为"袋内"（in-bag）样本（其余 36.8% 称为"袋外"（out-of-bag）样本）。

子采样（Subsampling）

请注意，文献中关于重采样策略的术语并不一致，例如，子采样有时被称为"重复留出"（repeated holdout）或"蒙特卡洛交叉验证"（Monte Carlo cross-validation）。

重采样策略的选择通常取决于手头的具体任务以及性能评估的目标，不过也有一些经验法则。如果可用数据相当少（\(N \leq 500\)），可以使用大重复次数的重复交叉验证来保持性能估计的方差较低（10 折 10 次重复是一个不错的起点）。传统上，LOO-CV 也曾被推荐用于这种小样本场景，但这种估计方案相当昂贵（除非存在计算捷径的特殊情况），而且（反直觉地）方差相当高。此外，LOO-CV 在不平衡的二分类任务中也有问题，因为像分层（stratification，3.2.6 节）这样的概念无法应用。对于 \(500 \leq N \leq 50000\) 的范围，通常推荐 5 到 10 折 CV。总的来说，数据集越大，需要的划分次数越少，但样本量问题仍然可能出现，例如由于数据不平衡。对于那些更关注严谨推断（如通过统计性能检验或置信区间）而不是单纯性能点估计的场景，通常会考虑自助法和子采样，并且通常使用较多的迭代次数。自助法已变得不那么常用，因为训练数据中的重复观测在一些机器学习设定下会带来问题，尤其是与模型选择方法和嵌套重采样（nested resampling）结合时（因为重复的观测可能会同时出现在嵌套方案的训练集和测试集中）。还要注意，在所有上述常见而简单的方案中，重采样性能估计之间并不是独立的，因为模型是在重叠的训练数据上拟合的，这使得严谨的推断并非易事，不过对这些问题的严谨处理超出了本书的讨论范围。更多细节与批判性讨论可参考相关文献，如 Molinaro, Simon, and Pfeiffer（2005）、Kim（2009）以及 Bischl et al.（2012）。

背景与解释（译者注）：这里涉及机器学习性能估计中两个最核心的权衡。其一是偏差-方差权衡（bias-variance tradeoff）：训练集太小会让中间模型远差于最终模型，产生"悲观偏倚"；测试集太小又会让估计结果受偶然划分影响，产生"高方差"。2/3 训练、1/3 测试的留出比例正是在二者之间取折中。其二是为何 CV 通常优于单次留出：单次留出只使用一次划分，估计的方差大；而 CV 让每个观测恰好充当一次测试，使全部数据都被利用，再通过平均多折结果降低方差。LOO-CV 反直觉地方差高，是因为相邻折的模型高度相似、相互重叠的训练数据使各折结果高度相关；而重复 CV 通过多次随机划分进一步稳定估计。另外，第 3 章正文还提示：小样本（N≤500）推荐重复 10 折×10 次的 CV，中等规模推荐 5~10 折 CV，这一经验法则与 Kohavi（1995）等经典研究的结论一致。

在本节的其余部分，我们将介绍如何在 mlr3 中查询和构造重采样策略、实例化训练-测试划分，然后对学习器执行重采样。

评估训练集（Evaluating Train Sets）

默认情况下，$score() 评估的是每次迭代测试集中的性能，不过你也可以评估训练集的性能，参见 ?sec-valid-tuning。

$score() 返回每次评估中的性能，而 $aggregate() 返回所有重采样迭代上的聚合得分。

$aggregate()
rr$aggregate(msr("classif.ce"))
classif.ce 
   0.06107

默认情况下，大多数度量使用宏平均（macro average）来聚合得分，即先在每次重采样迭代中分别计算度量，然后对所有迭代的这些得分取平均。不过也可以使用微平均（micro average）来聚合得分，它把各重采样迭代的预测汇集到一个 Prediction 对象中，然后直接在该对象上计算度量：

rr$aggregate(msr("classif.ce", average = "micro"))
classif.ce 
   0.06105

我们可以看到两种方法之间存在微小的差异。分类误差是一种可分解损失（3.1 节），事实上，如果所有测试集大小相同，那么微平均和宏平均方法将完全相同（见下方提示框）。对于像 AUC 这样定义在整个观测集合上的误差，微平均与宏平均之间的差异会更大。默认的聚合方法可以通过查询 Measure 对象的 $average 字段找到。

宏平均与微平均（Macro- and Micro-Averaging）

用一个简单例子来解释宏平均与微平均：考虑取一个向量的均值（微）与取两个分组均值的均值（宏）之间的差别：

# macro
mean(mean(c(3, 5, 9)), mean(c(1, 5)))
[1] 5.667
# micro
mean(c(3, 5, 9, 1, 5))
[1] 4.6

在正文中使用 tsk("penguins") 的例子中，微平均与宏平均的分类误差存在差异，因为该数据集有 344 行，不能整除 3（折数），因此测试集大小并不相等。

注意，"宏平均"与"微平均"这两个术语在文献中的用法并不一致，有时指不同的概念，例如在多分类任务中跨类别聚合性能的方式。

背景与解释（译者注）：宏平均（macro）与微平均（micro）的区别值得仔细体会。宏平均"先逐折打分再平均"，每一折无论大小权重相同；微平均"先合并全部预测再统一打分"，样本数多的折贡献更大。对于可分解损失（如分类误差），两种方式只在各折测试集大小不等时出现微小差别；而对于 AUC、AUC 这类"基于整组观测排序"的度量，两种方式的差别会更明显。在多分类度量中，"宏/微平均"一词还可能指按类别平均（macro-averaged precision）而非按样本平均（micro-averaged precision）——在类别不平衡时这两个值会相差很大，中文资料与论文中常说的"宏平均 F1 / 微平均 F1"就是这个含义，阅读文献时要注意区分语境。

$aggregate() 返回的聚合得分，就是使用 Resampling 对象中定义的重采样策略，在给定任务上对我们所选学习器的泛化性能的估计。虽然我们通常关注这个聚合得分，但查看每次重采样迭代的个体性能值（由 $score() 方法返回）也可能有用，例如看看是否有某次迭代产生了非常不同的性能结果。图 3.4 基于 "penguins" 任务的小例子可视化了 $score() 与 $aggregate() 之间的关系。

要可视化重采样结果，可以使用 autoplot.ResampleResult() 函数，把各折的得分绘制成箱线图（boxplot）或直方图（histogram，图 3.5）。直方图有助于直观判断重采样迭代之间性能结果的方差，而箱线图常用于并排比较多个学习器（见3.3 节）。

3.2.3 置信区间（Confidence Intervals，+）

除了仅仅依赖点估计（point estimates），置信区间（confidence intervals, CIs）还提供了这个估计的不确定性度量，使我们能够理解性能测量的可靠性。由于推断问题本身的复杂性，为泛化误差构造 CI 颇具挑战性，但已有一些方法在实践中表现良好 (Schulz-Kümpel et al. 2024)。使用这类方法时，重要的是要知道它们在有些情况下可能失效——例如存在离群值或不稳定的学习过程时——并且要知道由此得到的 CI 可能过于保守或过于宽松。

mlr3inferr 包为 mlr3 生态扩展了推断方法与新的重采样策略。推断方法以 Measure 对象的形式实现，它们接收另一个度量，为其计算 CI。下面我们演示如何使用 Bayle et al.（2020）提出的推断方法来为上一节交叉验证的结果计算 CI。与其他 mlr3 度量不同，这里的结果不是标量，而是一个包含点估计以及指定 alpha 水平下 CI 上下界的向量。

library(mlr3inferr)
# alpha = 0.05 is also the default
msr_ci = msr("ci.wald_cv", msr("classif.acc"), alpha = 0.05)
rr$aggregate(msr_ci)
      classif.acc classif.acc.lower classif.acc.upper 
           0.9448            0.9206            0.9689

我们也可以使用 msr("ci")，它会针对给定的重采样策略自动选择合适的推断度量。可用推断方法的列表可以在该包的网站上找到：https://mlr3inferr.mlr-org.com/。

rr$aggregate(msr("ci", msr("classif.acc")))
      classif.acc classif.acc.lower classif.acc.upper 
           0.9448            0.9206            0.9689

背景与解释（译者注）：为交叉验证估计构造置信区间在统计上并不平凡。直观的"把各折得分取均值再套用 t 分布"会低估不确定性，因为各折的模型在重叠的训练数据上拟合，得分之间并不独立（这正是前文强调的）。mlr3inferr 提供的 Wald 型 CV 推断（ci.wald_cv）基于 Bayle 等（2020）的理论结果，它把 CV 估计量的方差分解为"折内误差"与"折间因训练集重叠带来的协方差"两部分，从而得到渐近正确的区间。若训练过程不稳定（如小样本上的复杂模型），此类区间可能失效。读者在使用时可对比不同推断方法的结果，避免只报告单一方法的区间。

3.2.6 分层与分组（Stratification and Grouping）

本节涉及高级机器学习或技术细节。

利用列角色（column roles，2.6 节），可以根据数据中的某个特定列对观测进行分组或分层。我们依次来看这两种方式。

分组重采样（Grouped Resampling）

在数据切分时把同一组的观测保持在一起可能很有用，有时甚至是必不可少的——空间分析（13.5 节）就是一个典型的例子，因为观测属于自然分组（例如国家）。当观测属于某个组时，我们需要确保同一组的所有观测要么全部在训练集中，要么全部在测试集中，以防止训练与测试之间的潜在信息泄漏（leakage）。例如，在纵向研究（longitudinal study）中，对同一个体在多个时间点进行测量。如果我们不把这些观测分组，就可能高估模型对未见个体的泛化能力，因为同一个体的观测可能同时出现在训练集和测试集中。在这种情境下，留一交叉验证策略可以粗化为"留一对象交叉验证"（leave-one-object-out cross-validation），即把与某个组相关的所有观测都留下（图 3.6）。

"group" 列角色允许我们指定数据中定义观测组结构的列。在下面的代码中，我们构造一个留一重采样策略，把 "group" 角色赋给 tsk("penguins") 的 'year' 列，实例化该重采样策略，最后展示在第一折中年份是如何被干净地分开的。

分层抽样（Stratified Sampling）

分层抽样（stratified sampling）确保训练集和测试集中一个或多个离散特征具有与包含所有观测的原始任务相似的分布。当一个离散特征高度不平衡，而我们希望确保该特征的分布（图 3.7）在每次重采样迭代中相似时，这一点尤其有用。我们也可以对目标特征进行分层，以确保每个中间模型都在训练数据上拟合，而训练数据中目标的类别分布能代表真实任务；这有助于防止目标类别在个别重采样迭代中因随机偶然而严重代表性不足，从而避免产生退化的泛化性能估计。

与分组不同，使用 "stratum" 列角色（2.6 节）可以对多个离散特征进行分层。这种情况下，分层单元（strata）由被分层特征的每一种组合构成，例如两个被分层特征 A 和 B 分别有水平 Aa、Ab 和 Ba、Bb，那么创建的分层单元将有水平 AaBa、AaBb、AbBa、AbBb。

背景与解释（译者注）：分层（stratification）与分组（grouping）是两个容易被混用的概念。分层解决的是分布代表性问题：在类别不平衡时，随机切分可能让少数类在某折中占比畸高或缺失，导致性能估计失真；分层让每折的类别比例与总体一致。分组解决的是数据依赖/泄漏问题：当同一对象（病人、地块、用户、时间序列段）有多条观测时，若不把同一对象的全部观测归入同一侧，模型就可能在测试时"见过"训练时同一对象的信息，从而高估泛化能力。判别要点：分层针对"类别标签"，分组针对"观测之间的关联结构"。在多标签或多层结构数据（如嵌套的纵向数据）中，二者可同时使用。

3.3 基准测试（Benchmarking）

有监督机器学习中的基准测试（benchmarking）指在一个或多个任务上比较不同的学习器。当在单个任务上或由多个相似任务组成的域（domain）上比较多个学习器时，主要目标通常是按预先定义的性能度量对学习器排序，并找出在所考虑任务或域上表现最好的学习器。当在多个任务上比较多个学习器时，主要目标通常更具科学性，例如了解不同学习器在不同数据情境下的表现，或者是否存在某些数据属性会严重影响某些学习器（或学习器的某些超参数）的表现。算法设计者在基准实验中分析新提出的学习算法相对于既有学习器的泛化性能或运行时间，是常见且良好的做法。由于基准测试通常由许多可以彼此独立运行的评估组成，mlr3 提供了自动并行化它们的能力，我们在10.1.2 节中演示这一点。在本节中，我们将专注于适用于大多数用例的基本基准实验设置，在第 11 章中我们将研究更复杂、更大规模的基准实验。

3.3.1 benchmark()

mlr3 中的基准实验通过 benchmark() 进行，它只是在每个任务和学习器上分别运行 resample()，然后收集结果。提供的重采样策略会在每个任务上自动实例化，以确保所有学习器都针对相同的训练和测试数据进行比较。

要使用 benchmark() 函数，我们首先调用 benchmark_grid()，它构造一个穷举式的设计（design），描述基准实验中要使用的学习器、任务和重采样策略的全部组合，并实例化重采样策略。例如，下面我们建立一个设计，来看随机森林、决策树或无特征基线（featureless baseline，2.2.4 节）谁在两个分类任务上表现最好。

tasks = tsks(c("german_credit", "sonar"))
learners = lrns(c("classif.rpart", "classif.ranger",
  "classif.featureless"), predict_type = "prob")
rsmp_cv5 = rsmp("cv", folds = 5)

design = benchmark_grid(tasks, learners, rsmp_cv5)

背景与解释（译者注）：基准测试（benchmarking）中的一个常见陷阱是"跨任务平均性能"。当各任务的难度与数据分布差异很大时，把性能直接平均会掩盖"在简单任务上谁更好、在困难任务上谁更好"这类重要信息。更稳健的做法是先按任务排序（rank），再平均每个学习器的秩。这样做等价于在任务内先做相对比较，消去了任务本身的难度差异。但代价是丢失数值差异信息：两个学习器在某个任务上相差 0.01 还是 0.1，在排序中并无区别。第 11 章还会引入 Friedman 检验、临界差图（critical difference diagrams）等正式的统计比较方法。此外，mlr3 的基准设计是"任务 × 学习器 × 重采样"的穷举笛卡尔积，也可以用 data.table 手工构造或删减行，这为实现非对称设计（例如不同学习器用不同重采样）提供了灵活性。

由于 $score() 和 $aggregate() 的结果以 data.table 形式返回，你可以以任何想要的方式对结果进行后处理和分析。一个常见的错误是当各任务差异显著时，把所有任务上的学习器性能取平均。这样做是错误的，因为平均性能会遗漏关于学习器在"较容易"或"较困难"的预测问题中如何比较的重要洞见。一种更稳健的、用于跨多个任务比较整体算法性能的替代方法是：在每个任务上分别计算每个学习器的排名，然后计算平均排名。这能提供更好的比较，因为在跨任务比较之前先在任务内部比较学习器，从而把任务特有的"怪癖"考虑进去。然而，使用排名会丢失关于计算所得性能得分之间数值差异的信息。基准实验的分析（包括统计检验）在11.3 节有更详细的讨论。

3.4 二分类器的评估（Evaluation of Binary Classifiers）

在2.5.3 节中我们接触了混淆矩阵（confusion matrix）的概念，以及如何用它更细致地分解分类错误。在本节中，我们将更详细地考察针对二分类的专业化性能度量。我们首先回到混淆矩阵，讨论可以从中推导出的度量，然后考察建立在这些度量之上的 ROC 分析。关于 ROC 度量的更详细介绍，可参考 Provost 和 Fawcett（2013）著作的第 7 章和第 8 章。

3.4.1 混淆矩阵（Confusion Matrix）

回顾一下，混淆矩阵在二维列联表（contingency table）中汇总以下数量（另见图 3.10）：

  • 真正例（True positives, TPs）：被正确分类为正类的正类实例。
  • 真负例（True negatives, TNs）：被正确分类为负类的负类实例。
  • 假正例（False positives, FPs）：被错误分类为正类的负类实例。
  • 假负例（False negatives, FNs）：被错误分类为负类的正类实例。

不同的应用可能对上述某一（或某几个）数量特别关注。例如，tsk("spam") 分类任务关心的是判断邮件是垃圾邮件（正类）还是不是（负类）。在这种情况下，我们很可能愿意接受 FNs（一些垃圾邮件被分类为正常邮件），只要 FPs 数量低（正常且可能重要的邮件被分类为垃圾邮件）。在另一个例子中，假设我们要预测在机场安检中旅行包内是否装有武器（正类）或没有（负类）。这个分类器必须有非常高的 TPs（因为 FNs 完全不可接受），即使以更多的 FPs（误报警）为代价。

正如我们在2.5.3 节中所见，分类器可能有很好的分类准确率，却忽略完整混淆矩阵所提供的细微信息，如下面的 tsk("german_credit") 例子所示：

单独来看，当存在类别不平衡时，混淆矩阵中的绝对数字可能不那么有用。相反，可以推导出几个归一化的度量（图 3.10）：

  • 真正例率（True Positive Rate, TPR），灵敏度（Sensitivity）或召回率（Recall）：真正的正类中，我们预测为正类的比例是多少？
  • 真负例率（True Negative Rate, TNR）或特异度（Specificity）：真正的负类中，我们预测为负类的比例是多少？
  • 假正例率（False Positive Rate, FPR），或 \(1 -\) 特异度（Specificity）：真正的负类中，我们预测为正类的比例是多少？
  • 阳性预测值（Positive Predictive Value, PPV）或精确率（Precision）：如果我们预测为正类，它真正是正类的可能性有多大？
  • 阴性预测值（Negative Predictive Value, NPV）：如果我们预测为负类，它真正是负类的可能性有多大？
  • 准确率（Accuracy, ACC）：正确分类的实例占全部实例的比例。
  • F1 分数（F1-score）：精确率与召回率的调和平均，它平衡了精确率与召回率之间的权衡。计算公式为 \(2 \times \frac{Precision \times Recall}{Precision + Recall}\)。

背景与解释（译者注）：混淆矩阵派生的四个核心比率可以从"行"与"列"两个视角记忆。按列（以真实类别为条件）看：TPR = TP/(TP+FN) 回答"正类里抓回了多少"，TNR = TN/(TN+FP) 回答"负类里放对了多少"，二者也称召回率/特异度。按行（以预测类别为条件）看：PPV = TP/(TP+FP) 回答"说它是正类，准不准"，即精确率；NPV = TN/(TN+FN) 对称地回答"说它是负类，准不准"。准确率 ACC 与 F1 是两个综合指标：ACC 在所有类别均衡时直观易用，但在类别高度不平衡时会被多数类主导；F1 是精确率与召回率的调和平均，对少数类更敏感，在信息检索、异常检测等"关注正类"的场景更常用。F1 用调和平均而非算术平均，是因为它惩罚精确率与召回率之间的悬殊差距——只有当二者都高时 F1 才高。

3.4.2 ROC 分析（ROC Analysis）

ROC（受试者工作特征，Receiver Operating Characteristic）分析被广泛用于通过可视化 TPR 与 FPR 之间的权衡来评估二分类器。

ROC 曲线是以 TPR 为纵轴、FPR 为横轴的线图。要理解这条曲线的用处，首先考虑硬标注分类器（hard labeling classifier，predict_type = "response"）的简单情形，它把观测分为正类或负类。这个分类器在 ROC 空间中表示为单个点（见图 3.11面板 (a)）。最好的分类器位于左上角，那里 TPR 为 \(1\)、FPR 为 \(0\)。位于对角线上的分类器是随机预测类别标签的（按不同类别比例）。例如，如果每个正类实例（忽略特征）以 25% 的概率被随机分类为正类，我们会得到 0.25 的 TPR。如果我们把每个负类实例随机指派给正类，就会得到 0.25 的 FPR。在实践中，我们永远不应该得到对角线以下的分类器，ROC 空间中位于对角线以下的点可能表明该分类器把正类和负类的标签弄反了。

现在考虑预测概率而非离散类别的分类器。使用不同的阈值来截断预测概率并把它们归入正类与负类，会产生不同的 TPR 和 FPR；通过把所有阈值下这些值绘制出来，我们可以刻画一个二分类器的行为——这就是 ROC 曲线。例如，我们可以用之前的 Prediction 对象，通过在全部可能阈值上对预测概率设阈值，计算所有可能的 TPR 和 FPR 组合；这恰恰就是 mlr3viz::autoplot.PredictionClassif 在选定 type = "roc" 时要做的事：

autoplot(prediction, type = "roc")

背景与解释（译者注）：ROC 空间的几个关键点值得牢记。左上角 (0,1) 是理想点（TPR=1、FPR=0，分类完全正确）；右下角 (1,0) 是最差情形；对角线（y=x）代表随机猜测。两个"基线分类器"很有意思：总是预测正类的分类器位于 (1,1)，从不预测正类的位于 (0,0)——它们都表现"差"，但位于对角线上方。一个位于对角线以下的点通常提示标签被反了（把正类当负类、负类当正类），简单翻转预测即可纠正。ROC 曲线本质上是把连续概率输出在 \([0,1]\) 的所有阈值上扫描，把每个阈值对应的 (FPR, TPR) 连成曲线：阈值越高，被判为正的样本越少，FPR 与 TPR 同时下降。正因如此，ROC 曲线完整刻画了分类器"在不牺牲太多 TPR 的情况下能压到多低 FPR"的能力。

从 ROC 曲线自然推导出的性能度量是曲线下面积（area under the curve, AUC），在 msr("classif.auc") 中实现。AUC 可以解释为：随机选取一个正类实例，其被预测属于正类的概率高于随机选取一个负类实例的概率。因此，更高的值（更接近 \(1\)）表示更好的性能。随机分类器（如无特征基线）的 AUC 总是（在经验评估时近似）0.5（见图 3.11面板 (b)）。

多分类 ROC 与 AUC（Multiclass ROC and AUC）

存在面向多分类器的 ROC 分析扩展 (参见例如 Hand and Till 2001)，但本书只讨论更常见的二分类情形。AUC 度量到多分类的推广已在 mlr3 中实现，参见 msr("classif.mauc_au1p")。

我们还可以绘制精确率-召回率曲线（precision-recall curve, PRC），它可视化 PPV/精确率与 TPR/召回率的关系。ROC 曲线与 PR 曲线的主要区别在于，后者忽略了真负例的数量。这在正类稀有的不平衡总体中很有用，在这种情形下，即使 TPR 很高的分类器也可能信息量不大且 PPV 很低。关于 PRC 与 ROC 曲线关系的详细讨论，参见 Davis 和 Goadrich（2006）。

精确率-召回率曲线（Precision-recall Curve）
autoplot(prediction, type = "prc")

背景与解释（译者注）：ROC 曲线与 PR 曲线在类别不平衡时结论可能完全不同，这是实践中最常踩的坑。ROC 曲线同时使用 TPR（分母是全部正类）与 FPR（分母是全部负类），当负类占绝大多数时，FPR 被大量真负例"稀释"，曲线看起来仍然很好；而 PR 曲线只用 PPV（分母是预测的正类）与召回率，在正类稀少时，哪怕少量假正例也会让精确率暴跌。因此在欺诈检测、罕见病诊断、异常检测等正类稀少的任务中，PR 曲线（以及 PR-AUC）往往比 ROC-AUC 更能反映真实性能。Davis 与 Goadrich（2006）证明：对同一个分类器，若在 ROC 空间中一条曲线占优，其在 PR 空间中未必占优，反之亦然。

另一个思考分类器性能的有用方式是可视化某个性能度量随阈值变化的关系，例如，参见图 3.14，检查所有可能阈值下的 FPR 与准确率：

autoplot(prediction, type = "threshold", measure = msr("classif.fpr"))
autoplot(prediction, type = "threshold", measure = msr("classif.acc"))

这个可视化会告诉我们：把阈值从默认的 0.5 提高到例如 0.7，将大幅降低 FPR，而准确率只下降几个百分点。取决于手头的问题，这可能是一个完全理想的权衡。

这些可视化同样适用于 ResampleResult 对象。在这种情况下，各重采样迭代的预测在计算 ROC 或 PR 曲线之前会被合并（微平均）：

rr = resample(
  task = tsk("german_credit"),
  learner = lrn("classif.ranger", predict_type = "prob"),
  resampling = rsmp("cv", folds = 5)
)
autoplot(rr, type = "roc")
autoplot(rr, type = "prc")

3.5 结论（Conclusion）

在本章中，我们学习了如何通过重采样策略（从留出法到交叉验证和自助法）估计模型的泛化性能，以及如何在基准实验中自动化地比较多个学习器。我们还覆盖了二分类性能度量的基础，包括混淆矩阵、ROC 分析与精确率-召回率曲线。这些主题在有监督学习中至关重要，并将在本书中不断被深化。特别是，第 4 章会在自动化模型调优中利用评估来提升性能，第 11 章会研究大型基准测试及其统计分析，而在第 13 章中我们将考察需要不同重采样策略的专门任务。
