机器学习算法通常都包含参数（parameters）和超参数（hyperparameters）。参数是模型的系数、权重或其他信息，由学习算法根据训练数据确定。与之相对，超参数由用户配置，决定模型将如何拟合其参数，即模型是如何被构建的。例如：随机森林中的树的数量、支持向量机中的惩罚设置、或神经网络中的学习率。

超参数（Hyperparameters）

超参数优化（hyperparameter optimization, HPO），又称模型调优（model tuning），其目标是为给定任务找到机器学习算法的最优超参数配置。与模型无关的 HPO 没有封闭形式的数学表示（也没有解析梯度信息）。相反，我们采用一种黑箱优化（black box optimization）的方法：先为机器学习算法选择一个或多个超参数的值进行配置，然后（用重采样方法）对配置后的算法进行评估并度量其性能，这个过程用多个配置反复进行，最后选出性能最好的配置（图 4.1）。HPO 与模型评估（第 3 章）密切相关，因为其目标正是寻找一个能使泛化性能最优的超参数配置。宽泛地说，我们可以把寻找最优模型配置的方式，想象成从基准测试实验中选择模型：只不过这里的每个"模型"变成同一个算法配以不同的超参数配置。例如，我们可以对三个不同的 cost 值的支持向量机（SVM）做基准测试。然而，人工试错既费时、主观且常有偏差，又易出错，计算效率也低。因此，在过去几十年中，人们开发了许多成熟的超参数优化方法（或称"调优器 tuner"，见4.1.4 节）以实现稳健高效的 HPO。除了随机搜索（random search）和网格搜索（grid search）这类简单方法之外，大多数超参数优化方法都采用迭代技术，随时间不断提出新配置，通常表现出自适应行为，被引导向可能最优的超参数配置。关于 HPO 的更一般介绍和更多理论背景，我们推荐 Bischl 等（2023）和 Feurer 与 Hutter（2019）。

超参数优化（Hyperparameter Optimization）

请注意：mlr3 绝不会在用户未显式要求的情况下自动执行任何超参数优化。

背景与解释（译者注）：先厘清一组容易混淆的概念。模型的参数（如线性回归的系数、神经网络的权重）是在训练过程中由数据自动"学习"出来的；而超参数（如随机森林的树数、SVM 的惩罚系数 cost）是在训练开始前由人设定的，它们控制参数学习的方式。HPO 要解决的就是"如何自动地、高效地找到好的超参数配置"这一问题。由于"配置→性能"这种映射通常没有解析表达式、也无法求梯度（例如改变树的数量并不会给出一条平滑可微的性能曲线），所以只能把它当作黑箱：输入一个配置，返回一个（带随机扰动的）性能值，然后借助各类优化算法去探索。图 4.1 中的循环就是这一思路的具象化。

4.1 模型调优

mlr3tuning 是 mlr3 生态系统的超参数优化包。该包的核心是两个 R6 类：

  • TuningInstanceBatchSingleCrit：一个调优"实例（instance）"，用于描述优化问题并存储结果；以及
  • TunerBatch：用于配置和运行优化算法。

在本节中，我们将介绍这些类以及其他辅助函数与类。本节将全程以在 tsk("sonar") 上调优来自 e1071 的 SVM 分类器作为贯穿始终的示例。

4.1.1 学习器与搜索空间（Learner and Search Space）

如果资源无限，我们可以联合调优所有超参数，但现实中这不可能（也未必必要），所以通常只调优一部分超参数。这部分可供调优的超参数取值集合就称为搜索空间（search space）或调优空间（tuning space）。在本例中，我们将调优数值型的正则化与核宽度超参数 cost 和 gamma；有关细节参见 svm() 的帮助页面。在实践中，搜索空间通常更复杂，可能需要专业知识来定义。4.4 节将更深入地介绍调优空间的创建，包括使用 mlr3tuningspaces 加载预定义的搜索空间。

搜索空间（Search Space）
不可调优的超参数（Untunable Hyperparameters）

在少数情况下，参数集合中可能包含不应调优的超参数。这些通常是"技术性"（或称"控制性"）参数。提供关于模型如何拟合的信息，但并不控制训练过程本身，例如 lrn("classif.ranger") 中的 verbose 超参数控制训练期间向用户显示多少信息。

对于数值型的超参数（其他类型稍后讨论），必须指定要调优的范围。方法是：先构造一个学习器，再用 to_tune() 为想要调优的参数设置下界与上界。该函数让我们能够将某个超参数标记为需要在指定范围内调优。关于 to_tune() 函数的更多信息参见16.5.1 节。

learner = lrn("classif.svm",
  type  = "C-classification",
  kernel = "radial",
  cost  = to_tune(1e-1, 1e5),
  gamma = to_tune(1e-1, 1)
)

背景与解释（译者注）：在定义搜索空间时有一个常见的思考起点：哪些超参数值得调？一般来说，应优先调优对模型复杂度影响大的超参数（如树的深度、SVM 的 cost、正则化强度），因为这些参数直接控制偏差-方差权衡（bias-variance trade-off）。与之相对，像 verbose 这类"技术性"参数只影响运行细节、不影响泛化性能，不应放入搜索空间。还需注意数值超参数的取值范围设计：范围过窄会漏掉好配置，范围过宽则浪费计算资源。对于 cost、学习率这类跨越多个数量级的参数，直接在线性尺度上均匀采样通常很低效，应使用对数尺度（见 4.1.5 节）。

现在我们已经决定了要调优哪些超参数，接下来指定调优过程的停止条件。

4.1.2 终止器（Terminator）

mlr3tuning 提供了许多指定算法何时终止的方法（表 4.1），这些方法以 Terminator 类的形式实现。终止器存储在 mlr_terminators 字典中，并通过糖函数 trm() 构造。

Terminatortrm()

最常用的终止器是最佳时间（trm("run_time")）或给定评估次数（trm("evals")）后停止调优的终止器。选择运行时长通常基于实际考虑与直觉。在使用计算集群时，时间限制可能很重要，因为集群通常要求为一个计算任务指定最大运行时间。trm("perf_reached") 在达到指定性能水平时停止调优，如果某一性能已足以满足模型的实务用途，这会很有帮助；但如果该水平设得过于乐观，调优可能永远无法终止。trm("stagnation") 在没有取得超过 threshold 阈值的进展并持续了设定的 iterations 轮数时停止。阈值的选择可能很困难，因为对于复杂的搜索空间，即使仍有（可能很显著的）改进空间，优化也可能过早停止。trm("none") 用于那些自身控制终止的调优器，因此这个终止器不做任何事。最后，任何终止器都可以通过 trm("combo") 自由组合，可以指定 HPO 是在任意（any = TRUE）一个终止器触发时结束，还是在全部（any = FALSE）终止器触发时结束。

4.1.3 用 ti 创建调优实例（Tuning Instance with ti）

调优实例收集优化模型所需的、与调优算法无关的信息，即关于调优过程的全部信息，唯独不包括调优算法本身。这些信息包括：要调优的任务、待调优的学习器、用于分析比较超参数优化配置的重采样方法与度量，以及用于判断"度量已优化得足够充分"的终止器。这隐含地定义了一个待优化的"黑箱"目标函数，它将超参数配置映射到（随机的）性能值上。这一概念将在第 5 章中再次讨论。

可以显式地用 ti() 函数构造调优实例，也可以用 tune() 函数调优学习器，后者会隐式地创建一个调优实例，如4.2 节所示。我们首先介绍 ti() 方式，因为它允许更精细地控制调优，也便于更细致地讨论 mlr3tuning 的设计与使用。

继续我们的示例，我们将通过 ti() 函数构建一个单目标调优问题（即只对一个度量调优），从而创建一个 TuningInstanceBatchSingleCrit；多目标调优将在5.2 节中讨论。

在本例中，我们将使用三折交叉验证并优化分类误差度量。请注意，在下一节中我们继续示例时使用的网格搜索调优器，因此下面选择 trm("none")，因为我们希望遍历整个网格而不过早停止。

搜索策略（Search strategies）

网格搜索和随机搜索 (Bergstra and Bengio 2012) 是最基础的算法，通常在最初实验中最先被选用。网格搜索的思想是穷举评估给定的超参数取值的每一种组合。类别型超参数通常在其所有可能取值上评估。数值型和整数型超参数的取值则依据给定的分辨率（resolution，即每个超参数要尝试的不同取值个数）在其盒子约束（上界与下界）内等距排列。随机搜索则是为每个超参数独立地从预先指定的分布（通常是均匀分布）中随机取值。这两种方法都是非自适应的，意味着每个新提出的配置都不会参考此前配置的性能。由于简单，网格搜索和随机搜索都能处理混合搜索空间（即超参数可以是数值型、整数型或类别型），以及层次化搜索空间（4.4 节）。

自适应算法（Adaptive algorithms）

自适应算法从先前评估过的配置中学习，以快速找到好的配置，mlr3 中的例子包括：贝叶斯优化（又称基于模型的优化）、协方差矩阵自适应进化策略（Covariance Matrix Adaptation Evolution Strategy, CMA-ES）、迭代竞速（Iterated Racing）和 Hyperband。

贝叶斯优化 (例如，Snoek, Larochelle, and Adams 2012) 描述了一族迭代优化算法，它们使用代理模型（surrogate model）来逼近待优化的未知函数——在 HPO 中即"超参数配置 → 泛化性能估计值"的映射。如果选择了合适的代理模型，例如随机森林，贝叶斯优化可以相当灵活，甚至能处理混合与层次化搜索空间。贝叶斯优化的完整细节见5.4 节。

CMA-ES (Hansen and Auger 2011) 是一种进化策略，它在候选点上维持一个概率分布，该分布由均值向量与协方差矩阵表示。通过对该分布采样生成一组新的候选点，每个候选点的入选概率与其性能成正比。协方差矩阵随时间更新，以反映性能的景观（performance landscape）。mlr3 还通过 miesmuschel 包提供更多的进化策略，但本书不涉及这些。

竞速（racing）算法通过迭代地丢弃表现不佳的配置（由统计检验判定）来工作。迭代竞速 (López-Ibáñez et al. 2016) 首先"竞速"一个从参数化密度中随机采样的初始配置种群，然后用竞速中存活下来的配置随机更新下一轮竞速的密度，使其聚焦到搜索空间中更有希望的区域，如此反复。

多保真度（multi-fidelity）HPO 是一种自适应方法，它利用计算廉价、保真度较低的评估（即质量较差的预测，例如由训练轮数很少的神经网络产生的预测）的预测能力来提高整体优化效率。这一思想被用于 Hyperband (Li et al. 2018)——一种流行的多保真度超参数优化算法，它动态地将越来越多的资源分配给有希望的配置，并终止表现不佳的配置。Hyperband 的完整细节见5.3 节。

针对数值搜索空间的其他已实现算法包括广义模拟退火 (Xiang et al. 2013; Tsallis and Stariolo 1996) 和各种非线性优化算法。

选择策略（Choosing strategies）

作为经验法则，如果搜索空间很小或结构不复杂，网格搜索或许能在合理时间内穷举评估整个搜索空间。然而，由于维数灾难（curse of dimensionality）——网格规模会随着待调参数数量的增加而迅速"爆炸"——以及网格搜索对数值搜索空间的覆盖不足，通常并不推荐用它。从构造上讲，网格搜索不可能为每个超参数评估大量不同的取值，而当有些超参数对性能影响很小时、另一些影响很大时，这是次优的。在这种情形下，随机搜索往往是更好的选择，因为与网格搜索相比，它在每个超参数上会尝试更多不同的取值。

对于更高维度的搜索空间或结构更复杂的搜索空间，进化策略或贝叶斯优化这类更受引导的优化算法往往表现更好，更有可能取得最佳性能。在进化策略与贝叶斯优化之间做选择时，函数评估的成本非常关键。如果超参数配置可以被快速评估，进化策略通常表现良好。另一方面，如果模型评估耗时且优化预算有限，贝叶斯优化通常更受青睐，因为它与其他算法相比样本效率较高，即找到好配置所需的函数评估较少。因此，通常推荐用贝叶斯优化进行 HPO。虽然贝叶斯优化的优化开销相对较大（例如每一轮迭代中都需要训练代理模型并优化采集函数），但在诸如 ML 模型重采样这类函数评估相对昂贵的背景下，这种开销的影响较小。

最后，在超参数优化问题涉及有意义的保真度参数（例如训练轮数、树的数量、提升轮数）且需要高效地使用优化预算的情况下，Hyperband 这类多保真度超参数优化算法值得考虑。关于不同调优器的更多细节与实际建议，我们推荐参考 Bischl et al. (2023)。

$param_classes 与 $properties

Tuner 的 $param_classes 和 $properties 字段分别提供如下信息：该调优器能处理哪些类的超参数，以及该调优器具备哪些属性（例如超参数依赖，见4.4 节；或多准则优化，见5.2 节）：

背景与解释（译者注）：为什么随机搜索常常优于网格搜索？Bergstra 和 Bengio（2012）有一句经典论断：在许多实际问题中，超参数对性能的影响往往是"少数几个起决定性作用，其余作用甚微"。网格搜索给所有参数分配相同的格子数，导致关键维度上被尝试的取值很少；而随机搜索让每个维度都能在不同取值上"展开"，因此覆盖到关键维度的更多不同值，找到好配置的概率更高。这也是"维数灾难"的又一体现：网格搜索的评估次数随参数数量指数增长，而随机搜索的评估次数与维度基本无关。因此，在不确定哪些超参数重要时，随机搜索通常是比网格搜索更稳妥的起点。

对于我们的 SVM 示例，出于运行时间的考虑，我们这里使用分辨率为 5 的网格搜索（在实践中应优先更大的分辨率）。分辨率是每个超参数要尝试的不同取值个数，这意味着在本例中调优器将构建一个 5 × 5 的网格，即在指定上下界之间等距取点的 25 个配置。调优器将以（随机顺序）尝试所有这些配置，直到所有配置都被评估完，或终止器（4.1.2 节）发出预算耗尽的信号。对于网格与随机搜索调优器，batch_size 参数控制启用并行化时同时评估多少个配置（见10.1.3 节），同时也决定在终止器检查终止条件是否达到之前，应评估多少个配置。

过度自信的性能估计（Overconfident Performance Estimates）

调优时一个常见错误是：把调优所在重采样集上估计出的性能（instance$result$classif.ce）作为模型性能的无偏估计来报告，而忽略了它的乐观偏差。正确的方法是在更多未见过的数据上测试模型，这可以通过嵌套重采样（nested resampling）高效完成，我们将在4.3.2 节中讨论。

4.1.5 对数变换（Logarithmic Transformations）

对于许多上界很大的非负超参数，在对数尺度上调优比在线性尺度上调优更高效。举例来说，考虑在区间 \([\log(1e-5), \log(1e5)]\) 内均匀采样，然后再对结果取指数。图 4.2 中的直方图展示了：我们最初在一个较窄的区间（\([-11.5, 11.5]\)）内采样，但取指数后，结果中大多数点相对较小，而少数点却非常大。

cost = runif(1000, log(1e-5), log(1e5))
exp_cost = exp(cost)

要把这种变换加入某个超参数，只需向 to_tune() 传入 logscale = TRUE 即可。

  cost  = to_tune(1e-5, 1e5, logscale = TRUE),
  gamma = to_tune(1e-5, 1e5, logscale = TRUE),
  kernel = "radial",
  type = "C-classification"
)

  task = tsk_sonar,
  learner = learner,

背景与解释（译者注）：为什么对数尺度能改善搜索？对于 SVM 的 cost 或神经网络的 learning_rate 这类参数，其"好"的取值常常覆盖多个数量级（例如 0.001 与 1000 都可能合理）。若在线性尺度 [0, 10⁵] 上均匀采样，绝大多数采样点都将落在 10⁴～10⁵ 这样的大数值区间，而真正有区分度的取值（如 0.1、1、10）几乎不会被采到。取对数后，区间变为 [-11.5, 11.5]，整段范围的每一部分都被等价对待，等价于在原尺度上按 数量级 来分配采样权重。实践中一条经验是：对于只能取正值、且合理范围跨越多个数量级的参数（正则化强度、学习率、SVM 的 cost/gamma、xgboost 的 eta 等），一律优先考虑对数尺度。

4.3 嵌套重采样（Nested Resampling）

HPO 需要额外的重采样层，以减少估计模型性能时的偏差。如果用同一份数据既确定最优配置、又评估由此得到的模型，那么实际的性能估计会是有偏的 (Simon 2007)。这与 James 等（2014）所描述的训练误差乐观性（optimism of the training error）相似——当把训练误差当作样本外性能的估计时就会发生这种情况。

嵌套重采样通过在现有重采样之外再增加一层重采样，将模型优化与调优后模型的性能估计分离开来：也就是说，模型性能以"通常的方式"用某种重采样方法来估计，而调优则是对这些（重采样得到的）数据再做一次重采样来进行的（图 4.5）。关于嵌套重采样的更多细节与形式化介绍，读者可参阅 Bischl et al. (2023) 与 Simon (2007)。

背景与解释（译者注）：嵌套重采样是为了解决一个隐蔽但十分严重的统计问题——调优/选择导致的乐观偏差。当我们用一个数据集反复比较许多超参数配置或模型后，"最好"的那个配置的性能（在调优用的同一批数据上）往往是被高估的：我们相当于在这一批数据上做了多重比较，选择了对这批数据最有利的配置。若再把这个性能对外报告，就会过于乐观。嵌套重采样的思路是：把"选配置"这件事本身也放到重采样内部去完成——外层数据的测试折从不参与调优，因此每个外层测试折给出的性能是对"调优后模型"的真实样本外估计。这也是为何任何严肃的模型对比研究都必须使用嵌套重采样。

图 4.5 表示的嵌套重采样示例由以下步骤组成：

  1. 外层重采样开始——实例化三折 CV，创建不同的测试集与训练集。
  2. 内层重采样——在外层训练数据内部实例化四折 CV，创建不同的内层测试集与训练集。
  3. HPO——利用内层数据划分，在外层训练集（大的浅蓝色块）上调优超参数。
  4. 训练——用内层重采样（小块）得到的最优超参数配置，在外层训练数据集上拟合学习器。
  5. 评估——在外层测试数据（大的深蓝色块）上评估学习器的性能。
  6. 外层重采样重复——对其余的每个外层折重复步骤（2）—（5）。
  7. 汇总——取三次性能值的样本均值，得到无偏的性能估计。

内层重采样为每个配置生成泛化性能估计，并选出要在外层重采样上评估的最优配置。外层重采样随后为这些最优配置生成泛化估计。外层重采样的结果可以用来与在同一外层折上训练、测试的其他模型进行比较。

嵌套重采样与并行化（Nested Resampling and Parallelization）

嵌套重采样计算开销很大：三个外层折、四个内层折，配合分辨率为 5、用于调优两个参数的网格搜索，结果是 \(3*4*5^2 = 300\) 次模型训练/测试迭代。如果你的资源允许，我们建议在调优时利用并行化（10.1 节）。

一个常见误解是把嵌套重采样当作选择最优模型配置的方法。嵌套重采样是用来比较模型、并估计调优后模型泛化性能的方法；但是，它给出的性能建立在多个不同配置之上（每个外层折一个），而不是建立在单一配置之上（4.3.2 节）。如果你关心的是找出最优配置，那么应使用 tune()/ti() 或 auto_tuner() 并在完整数据集上调用 $train()。

4.4 更高级的搜索空间（More Advanced Search Spaces）

到目前为止，我们只考虑了局限于少数数值型超参数的简单搜索空间。在本节中，我们将首先看看如何用 to_tune() 调优不同的标量参数类型，然后用 ParamSet 定义自己的搜索空间，以创建更高级的搜索空间——其中可能包括对向量、变换的调优，以及处理参数依赖。最后，我们将讨论如何访问文献中标准化的搜索空间数据库。

4.4.1 标量参数调优（Scalar Parameter Tuning）

to_tune() 函数可用于调优任何类型的参数，无论标量还是向量。为更好地理解这个函数，我们来考察它背后发生的事。当 to_tune() 被用于学习器时，它隐含地只为调优搜索空间创建一个 ParamSet：

learner = lrn("classif.svm",
  cost  = to_tune(1e-1, 1e5),
  gamma = to_tune(1e-1, 1),
  kernel = "radial",
  type = "C-classification"
)

learner$param_set$search_space()
<ParamSet(2)>
      id    class lower upper nlevels        default  value
1:  cost ParamDbl   0.1 1e+05     Inf <NoDefault[0]> [NULL]
2: gamma ParamDbl   0.1 1e+00     Inf <NoDefault[0]> [NULL]

回顾 2.2.3 节，class 字段对应 paradox 中定义的超参数类型。在本例中，可以看到 gamma 超参数的类是 ParamDbl，其 lower = 0.1、upper = 1；这个参数是 to_tune() 在我们传入两个数值时自动创建的。如果我们想调优非数值型的超参数，仍然可以使用 to_tune()，它会推断出应该在结果参数集合中构建的正确类型。例如，假设我们想调优 SVM 中的数值型 cost、因子型 kernel 和逻辑型 scale 超参数：

learner = lrn("classif.svm",
  cost  = to_tune(1e-1, 1e5),
  kernel = to_tune(c("radial", "linear")),
  shrinking = to_tune(),
  type = "C-classification"
)

learner$param_set$search_space()
<ParamSet(3)>
          id    class lower upper nlevels        default  value
1:      cost ParamDbl   0.1 1e+05     Inf <NoDefault[0]> [NULL]
2:    kernel ParamFct    NA    NA       2 <NoDefault[0]> [NULL]
3: shrinking ParamLgl    NA    NA       2           TRUE [NULL]

这里 kernel 超参数是因子型，因此我们只需传入一个向量，对应要调优的水平。shrinking 超参数是逻辑型，它只可能取两个值，因此我们不必向 to_tune() 传任何东西，它会自动从 learner$param_set 识别出这是逻辑型，并把这个细节传给 learner$param_set$search_space()。类似地，对于因子型参数，如果我们想在其所有可能取值上调优，也可以不带任何参数地使用 to_tune()。最后，如果我们想把数值型参数离散化成一小部分可能的取值，也可以用 to_tune() 把数值型参数当作因子处理。例如，如果我们想找出随机森林的最佳树数，可能只考虑三种情形：100、200 或 400 棵树：

lrn("classif.ranger", num.trees = to_tune(c(100, 200, 400)))
有序超参数（Ordered Hyperparameters）

把整数当作因子来调优会造成"无序"的超参数。因此，利用顺序信息的算法在顺序被忽略时会表现更差。对这些算法而言，更合理的做法是定义一个 ParamDbl 或 ParamInt（4.4.2 节）并配以自定义变换（4.4.3 节）。

4.4.2 用 ps 定义搜索空间（Defining Search Spaces with ps）

正如我们所见，to_tune() 是一个辅助函数，它创建一个参数集合，供调优过程中的 tune()、ti() 或 auto_tuner() 使用。不过，有些使用场景下你需要用 ps() 手动创建参数集合。该函数接受 Domain 类的命名参数，这些参数可用 表 16.1 中的糖函数创建。

有关使用 paradox 包的更高级超参数规范的更多信息，将在第 16 章中给出。

作为简单示例，我们来看如何再次创建一个调优 cost 与 gamma 的搜索空间：

search_space = ps(
  cost  = p_dbl(lower = 1e-1, upper = 1e5),
  kernel = p_fct(c("radial", "linear")),
  shrinking = p_lgl()
)

然后把这个搜索空间传给 auto_tuner() 的 search_space 参数：

ti(tsk_sonar, lrn("classif.svm", type = "C-classification"), rsmp_cv3,

有界搜索空间（Bounded Search Spaces）

手动创建搜索空间时，请确保搜索空间中的所有数值型超参数都是有界的。例如，如果你试图调优一个取值范围为 \((-\infty, \infty)\) 的超参数，而你又没有向 p_dbl() 或 p_int() 传入上下界，那么几乎所有调优器在调优过程中都会抛出错误。如果拿不准，可以对构造好的 ParamSet 使用 $is_bounded：

ps(cost = p_dbl(lower = 0.1, upper = 1))$is_bounded

4.4.3 变换与向量调优（Transformations and Tuning Over Vectors）

本节涉及高级 ML 或技术细节。

在4.1.5 节中，我们看到了如何用 to_tune() 快速应用对数变换。如你所知，to_tune() 只是创建 ParamSet 对象的一个包装器，那么让我们看看设置 logscale = TRUE 时实际发生了什么：

lrn("classif.svm", cost = to_tune(1e-5, 1e5, logscale = TRUE))$
  param_set$search_space()
<ParamSet(1)>
     id    class  lower upper nlevels        default  value
1: cost ParamDbl -11.51 11.51     Inf <NoDefault[0]> [NULL]
Trafo is set.

注意现在 lower 和 upper 字段对应的是变换后的边界，即 \([\log(1e-5), \log(1e5)]\)。要手动创建同样的变换，我们可以把变换传给 p_dbl() 的 trafo 参数并设置边界：

search_space = ps(cost = p_dbl(log(1e-5), log(1e5),
  trafo = function(x) exp(x))) # alternatively: 'trafo = exp'
search_space
<ParamSet(1)>
     id    class  lower upper nlevels        default  value
1: cost ParamDbl -11.51 11.51     Inf <NoDefault[0]> [NULL]
Trafo is set.

我们可以利用 $trafo() 方法来确认它被正确设置了。该方法接收一个命名列表并应用指定的变换：

search_space$trafo(list(cost = 1))
$cost
[1] 2.718

变换最强大之处在于：可以传入任意函数，作用于单个参数甚至整个参数集合。作为例子，考虑一个简单的变换：在我们的范围上加"2"：

search_space = ps(cost = p_dbl(0, 3, trafo = function(x) x + 2))
search_space$trafo(list(cost = 1))
$cost
[1] 3

像这样的简单变换甚至可以把它所在的 Param 对象传给 to_tune()，从而直接加到学习器上：

lrn("classif.svm",
  cost = to_tune(p_dbl(0, 3, trafo = function(x) x + 2)))

需要多个参数的更复杂变换，应传给 ps() 的 .extra_trafo 参数。.extra_trafo 接受一个带 x 和 param_set 参数的函数；在调优过程中，x 将是包含当前被测试配置的列表，param_set 是整个参数集合。下面我们先把 cost 的值取指数，然后如果 kernel 是 "polynomial"，再加"2"：

search_space = ps(
  cost = p_dbl(-1, 1, trafo = function(x) exp(x)),
  kernel = p_fct(c("polynomial", "radial")),
  .extra_trafo = function(x, param_set) {
    if (x$kernel == "polynomial") {
      x$cost = x$cost + 2
    }
    x
  }
)
search_space$trafo(list(cost = 1, kernel = "radial"))
$cost
[1] 2.718

$kernel
[1] "radial"
search_space$trafo(list(cost = 1, kernel = "polynomial"))
$cost
[1] 4.718

$kernel
[1] "polynomial"

向量变换（Vector transformations）

任何函数都可以传给 trafo 和 .extra_trafo，这使得调优 ParamUty 类的"无类型"参数成为可能，这类参数可以是向量、函数或任何非原子类。举例来说，考虑 SVM 的 class.weights 参数：它接受一个命名向量，为每个目标类别给定一个类权重值。要调优这个参数，我们可以调优一个标量，然后把它变换成向量。下面的代码会对 0.1 到 0.9 之间的一个值 x 采样，然后把结果变换为（x, 1 - x），再传给 Learner。

search_space = ps(
  class.weights = p_dbl(lower = 0.1, upper = 0.9,
    trafo = function(x) c(M = x, R = 1 - x))
)

在其他情况下，我们可能需要调优两个或更多"伪参数（pseudoparameters）"——它们并不存在于学习器的参数集合中，但却是调优向量参数所必需的。例如，假设我们要调优神经网络的架构，需要决定层数与每层的节点数——mlr3torch 包中 lrn("classif.mlp") 的 neurons 超参数就属于这种情况：该学习器期望一个向量，其中每个元素对应一层中的神经元数目，而向量的长度就是层数。我们可以如下进行调优：

search_space = ps(
  num_layers = p_int(lower = 1, upper = 20),
  num_neurons_per_layer = p_int(4, 64),
  .extra_trafo = function(x, param_set) {
    x$neurons= rep(x$num_neurons_per_layer, x$num_layers)
    x$num_layers = NULL
    x$num_neurons_per_layer = NULL
    x
  }
)

这里我们在 1 到 20 之间调优伪参数 num_layers，在 4 到 64 之间调优伪参数 num_neurons_per_layer，然后把它们组合成一个名为 neurons 的向量（真正的超参数）并删除这两个伪参数。

search_space$trafo(list(num_layers = 4, num_neurons_per_layer = 12))
$neurons
[1] 12 12 12 12

尽管这个变换看起来很复杂，但它只影响其中一个超参数（并且不需要访问其他超参数），因此我们可以把整个 ParamSet 对象传给 to_tune()，从而把它整合进学习器：

library(mlr3torch)
learner = lrn("classif.mlp")
learner$param_set$set_values(neurons = to_tune(search_space))

4.4.4 超参数依赖（Hyperparameter Dependencies）

本节涉及高级 ML 或技术细节。

超参数依赖是指：某个超参数只有在另一个超参数取特定值时，才应当被设置。例如，SVM 的 degree 参数只有在 kernel 为 "polynomial" 时才有效。在 ps() 函数中，我们用 depends 参数来指定这一点，它接受形如 <param> == value 或 <param> %in% <vector> 的命名参数：

ps(
  kernel = p_fct(c("polynomial", "radial")),
  degree = p_int(1, 3, depends = (kernel == "polynomial")),
  gamma = p_dbl(1e-5, 1e5,
    depends = (kernel %in% c("polynomial", "radial")))
)
<ParamSet(3)>
       id    class lower upper nlevels        default parents  value
1: degree ParamInt 1e+00 3e+00       3 <NoDefault[0]>  kernel [NULL]
2:  gamma ParamDbl 1e-05 1e+05     Inf <NoDefault[0]>  kernel [NULL]
3: kernel ParamFct    NA    NA       2 <NoDefault[0]>  [NULL] [NULL]

上面我们规定了：只有 kernel 是（==）"polynomial" 时 degree 才应被设置；只有 kernel 是（%in%）"polynomial" 或 "radial" 之一时 gamma 才应被设置。在实践中，有些底层实现会忽略未使用的参数，另一些则会抛出错误；无论如何，在调优时这都成问题——例如，如果内核不是 polynomial 却仍在浪费时间调优 degree。因此，设置依赖关系会告诉调优过程：当 kernel 为 "polynomial" 时调优 degree，否则忽略它。

依赖也可以借助 to_tune() 直接传入学习器：

  kernel = to_tune(c("polynomial", "radial")),

)$param_set$search_space()

  3. 调优 XGBoost 模型，并将其与逻辑回归（后者不做调优）做基准测试，判断哪个模型的 Brier 分数更好。使用 mlr3tuningspaces 和嵌套重采样，尝试选择能在计算效率与结果稳定性之间取得平衡的合适内层与外层重采样策略。
  4. (*) 编写一个函数，实现一种迭代随机搜索过程：通过对越来越小的搜索空间应用随机搜索，逐步聚焦到最优配置上。你的函数应有七个输入：task、learner、search_space、resampling、measure、random_search_stages 和 random_search_size。你只需针对完全数值型、有界且没有依赖的搜索空间编程实现。用伪代码表示：
    1. 从给定搜索空间创建一个大小为 random_search_size 的随机设计，并在其上评估学习器。
    2. 找出最佳配置。
    3. 在最佳配置周围创建一个更小的搜索空间，其中每个参数的新范围定义为：new_range[i] = (best_conf[i] - 0.25 * current_range[i], best_conf[i] + 0.25*current_range[i])。通过取新、旧下界的 max() 以及新、旧上界的 min()（即"剪裁 clipping"），确保这个 new_range 不超出原始 search_space 的初始边界。
    4. 把前几步迭代 random_search_stages 次，最终返回你评估过的最佳配置。作为进阶目标，可研究 mlr3tuning 的内部源码，把你的函数改造成一个继承自 TunerBatch 类的 R6 类——在你选择的学习器上测试它。
