5.1 错误处理与内存管理（Error Handling and Memory Management）

在本节中，我们将了解如何使用 mlr3 来确保调优工作流高效且稳健。具体来说，我们将考虑如何启用一些特性，以预防在实验中途出现导致不可恢复数据丢失的致命错误，以及如何管理可能占用大量计算机内存的调优实验。

5.1.1 封装（Encapsulation）与回退学习器（Fallback Learner）

错误处理在 第 10.2 节 中有详细讨论，但它在调优语境中非常重要，因此这里我们将实际演示如何使用封装和回退学习器，并解释为什么它们在超参数优化（HPO）过程中必不可少。

即使在简单的机器学习问题中，也有很多可能出错的地方。例如，当学习器不收敛、内存耗尽，或由于底层数据的问题而以错误终止时。一个常见的问题是：当测试数据中出现了训练数据中不存在的因子水平（factor level）时，学习器会失败——因为针对这些新的因子水平没有训练过权重/系数，模型在这种情况下就会出错：

tsk_pen = tsk("penguins")
# 移除含缺失值的行
tsk_pen$filter(tsk_pen$row_ids[complete.cases(tsk_pen$data())])
# 创建自定义重采样：测试数据中含新的因子水平
rsmp_custom = rsmp("custom")
rsmp_custom$instantiate(tsk_pen,
  list(tsk_pen$row_ids[tsk_pen$data()$island != "Torgersen"]),
  list(tsk_pen$row_ids[tsk_pen$data()$island == "Torgersen"])
)
msr_ce = msr("classif.ce")
tnr_random = tnr("random_search")
learner = lrn("classif.lda", method = "t", nu = to_tune(3, 10))

tune(tnr_random, tsk_pen, learner, rsmp_custom, msr_ce, 10)
Error in `lda.default()`:
! variable 6 appears to be constant within groups

在上面的例子中，我们可以看到调优过程中断了，我们丢失了关于超参数优化过程的所有信息。在嵌套重采样（nested resampling）或基准测试（benchmarking）中，这种情况更糟，因为错误可能导致我们在多个配置、甚至多个学习器和任务上的所有进度都丢失。

封装（Encapsulation，见第 10.2.1 节）允许隔离并处理错误，而不会中断调优过程。我们可以通过 $encapsulate() 方法告知学习器封装错误，如下所示：

learner$encapsulate(method = "evaluate", fallback = lrn("classif.featureless"))

请注意，传入 "evaluate" 即告知学习器在训练和预测两个阶段都建立封装（其他封装选项见 第 10.2 节）。

另一个 HPO 中难以轻易解决的常见问题是学习器不收敛，进程无限期地运行下去。我们可以通过设置学习器的 timeout 字段来防止这种情况发生——该字段指示学习器在运行达到该时长（以秒为单位）时停止。同样，训练和预测的时限可以分别设置：

learner$timeout = c(train = 30, predict = 30)

现在，如果发生错误或达到模型超时阈值，学习器不会中断，而是在发现错误时不进行预测，对于出错的重采样迭代，结果为 NA。当这种情况发生时，由于我们无法跨重采样迭代聚合结果，超参数优化实验将会失败。因此，选择一个回退学习器（Fallback Learner，见第 10.2.2 节）至关重要——回退学习器是在目标学习器失败时将拟合的学习器。

一种常见做法是使用无特征基线（featureless baseline，lrn("regr.featureless") 或 lrn("classif.featureless")）。我们使用 lrn("classif.featureless")，它总是预测众数类别。

现在我们可以运行实验，并在归档（archive）中查看调优期间发生的错误。

  10)

背景与解释（译者注）：这里的「学习器失败」场景在真实数据分析中非常常见：测试/验证集中出现了训练集从未见到的类别水平，例如训练时 island 变量只有两个取值、而验证集出现了第三个岛名。对线性判别分析（LDA）这类需要为每个因子水平估计系数的模型来说，这会导致无法预测。用 $encapsulate(method = "evaluate", fallback = ...) 之后，出错的那次迭代会被记录、并使用回退学习器补预测，最终调优仍能给出总体结果；而若不做封装，整个 tune() 会直接崩溃。折中的代价是：出错迭代的性能值来自回退模型而不是真正的学习器，解读结果时要留意日志中的 errors 列。

5.1.2 内存管理（Memory Management）

运行大型调优实验会消耗大量内存，尤其是使用嵌套重采样时。大部分内存被模型占用，因为每次重采样迭代都会创建一个新模型。因此，默认情况下存储模型是被禁用的，而且在大多数情况下也没有必要。函数 ti() 和 auto_tuner() 中的 store_models 选项允许我们启用模型的存储。

归档为每个被评估的超参数配置存储一个 ResampleResult。其中包含的 Prediction 对象也可能占用大量内存，尤其是当数据集很大、重采样迭代很多时。我们可以通过将 store_benchmark_result = FALSE 设置在 ti() 和 auto_tuner() 函数中来禁用重采样结果的存储。注意，没有重采样结果，就无法再用另一个度量给配置打分。

当我们在外部重采样迭代很多的情况下运行嵌套重采样时，在 auto_tuner() 函数中设置 store_tuning_instance = FALSE 可以节省额外的内存。但是，函数 extract_inner_tuning_results() 和 extract_inner_tuning_archives() 将不再可用。

选项 store_models = TRUE 会把 store_benchmark_result 和 store_tuning_instance 都设为 TRUE，因为模型被存储在基准结果中，而基准结果又是实例的一部分。这也意味着 store_benchmark_result = TRUE 会把 store_tuning_instance 设为 TRUE。

最后，我们可以在 resample() 或 benchmark() 函数中设置 store_models = FALSE，以在运行嵌套重采样时禁用自动调优器（auto tuner）的存储。这样我们仍然可以访问聚合性能（rr$aggregate()），但会丢失关于内部重采样的信息。

5.2 多目标调优（Multi-Objective Tuning）

到目前为止，我们都只考虑了针对一个度量来优化模型，但多准则（multi-criteria），即多目标优化（multi-objective optimization），也是可行的。多目标优化的一个简单例子是优化一个分类器，使其同时最大化真阳性（true positive）预测并最小化假阴性（false negative）预测。另一个例子：考虑一个单目标问题——调优神经网络以最小化分类误差。性能最好的模型很可能是相当复杂的，可能有多个层，这会带来诸如在资源受限的设备上难以部署等缺点。在这种情况下，我们可能希望同时最小化分类误差和模型复杂度。

多目标（Multi-objective）

根据定义，对多个度量的优化意味着这些度量之间会存在竞争（否则我们只会优化其中一个），因此一般来说不存在能同时优化所有度量的单一配置。因此，我们转而关注帕累托最优性（Pareto optimality）这一概念。如果某个超参数配置所得到的模型在所有度量上都不差于另一个配置，并且至少在某一度量上严格更优，那么就说该配置帕累托支配（Pareto-dominate）另一个配置。例如，假设我们为配置 A 和 B 最小化分类误差 CE 和复杂度 CP，其中 CE 分别为 \(CE_A\) 和 \(CE_B\)，CP 分别为 \(CP_A\) 和 \(CP_B\)。那么，如果：1）\(CE_A \leq CE_B\) 且 \(CP_A < CP_B\)；或 2）\(CE_A < CE_B\) 且 \(CP_A \leq CP_B\)，则 A 帕累托支配 B。所有不被任何其他配置帕累托支配的配置称为帕累托有效（Pareto-efficient）配置，所有这些配置的集合称为帕累托集（Pareto set）。与帕累托集相对应的度量值被称为帕累托前沿（Pareto front）。

帕累托前沿（Pareto front）

多目标超参数优化的目标是找到一组非支配解，使得它们对应的度量值逼近帕累托前沿。我们现在将演示多目标超参数优化：在 tsk("sonar") 上调优一个决策树，目标为分类误差（作为模型性能的度量）和所选特征的数量（作为模型复杂度的度量；在决策树中，所选特征数量可以直接通过计算不同分裂变量的个数得到）。多目标超参数优化的方法学细节可参见 Karl et al. (2022) 和 Morales-Hernández, Van Nieuwenhuyse, and Rojas Gonzalez (2022)。

我们将调优 cp、minsplit 和 maxdepth：

learner = lrn("classif.rpart", cp = to_tune(1e-04, 1e-1),
  minsplit = to_tune(2, 64), maxdepth = to_tune(1, 30))

measures = msrs(c("classif.ce", "selected_features"))

5.3 通过超带进行多保真度调优（Multi-Fidelity Tuning via Hyperband）

越来越大的数据集、搜索空间，以及越来越复杂的模型，使得超参数优化成为一项耗时且计算代价高昂的任务。为了应对这一问题，一些 HPO 方法利用在多个保真度水平（fidelity level）上评估配置的做法。多保真度 HPO 背后的动机是：低保真度模型的性能可以指示全保真度模型的性能，因此可以用它来使 HPO 更高效（我们很快会在超带中看到这一点）。

多保真度 HPO（Multi-fidelity HPO）

为了解释这些术语的含义并说明多保真度调优的动机，假设我们认为一个最多 1000 轮的梯度提升算法将非常适合我们的训练数据。但是，我们担心这个模型的调优和训练耗时太长。因此，我们想用一个训练更快的相似模型（设置更少的轮数）来估测这个模型的性能。在这个例子中，控制轮数的超参数就是保真度参数（fidelity parameter），因为它控制着模型性能与速度之间的权衡。该参数的不同配置被称为保真度水平。我们把有 1000 轮的模型称为处于全保真度（full-fidelity）的模型，并希望用不同保真度水平的模型来逼近它的性能。较低的保真度水平会产生训练更快的低保真度模型，但可能对全保真度模型的性能预测不佳。另一方面，较高的保真度水平会产生训练较慢的高保真度模型，但可能更好地指示全保真度模型的性能。

其他具有天然保真度参数的常见模型包括神经网络（轮数 epochs）和随机森林（树的数目）。在任何算法运行前对数据进行子采样的比例，也可以看作是与模型无关的保真度参数，我们将在 第 8.4.4 节 中回到这一点。

5.3.1 超带与连续减半（Hyperband and Successive Halving）

一种流行的多保真度 HPO 算法是超带（Hyperband）(Li et al. 2018)。在低保真度下评估了随机采样的配置之后，超带迭代地将更多资源分配给有希望的配置，并提前终止表现不佳的配置。超带建立在 Jamieson and Talwalkar (2016) 提出的连续减半（Successive Halving）算法之上。连续减半算法需要初始化起始配置的数量 \(m_0\)、每个阶段丢弃配置的比例 \(\eta\)、以及单次评估的最小预算（budget，即保真度）\(r{_{0}}\) 和最大预算 \(r{_{max}}\)。算法首先采样 \(m_0\) 个随机配置，并为它们分配最小预算 \(r{_{0}}\)。评估这些配置后，丢弃表现最差的 \(\frac{\eta - 1}{\eta}\) 比例的配置。剩余配置被提升到下一阶段（即下一个「括号」bracket），并用更大的预算进行评估。这个过程持续进行，直到一个或多个配置在最大预算 \(r{_{max}}\) 下被评估，然后选择表现最好的配置。总阶段数是这样计算的：让每个阶段消耗大约相同的总预算。该方法的一大缺点是：尚不清楚是应该从大量配置（大的 \(m_0\)）和较小预算开始更好，还是从较少配置（小的 \(m_0\)）但更大预算开始更好。

超带通过在不同预算水平 \(r_{0}\) 下运行具有不同起始配置数量的连续减半来解决这个问题。算法使用相同的 \(\eta\) 和 \(r_{max}\) 参数进行初始化（但不使用 \(m_0\)）。每个括号都以不同的预算 \(r_0\) 开始，其中较小的值意味着可以评估更多的配置，因此探索性最强的括号（即阶段数最多的那个）被分配全局最小预算 \(r_{min}\)。在每个括号中，起始预算按 \(\eta\) 的因子递增，直到最后一个括号本质上是用全预算 \(r_{max}\) 进行随机搜索。总括号数 \(s_{max} + 1\) 计算为 \(s_{max} = {\log_\eta \frac{r_{max}}{r_{min}}}\)。每个括号的起始配置数 \(m_0\) 是这样计算的：每个括号使用大约相同的预算量。每个括号中的最优超参数配置是该括号最后阶段表现最好的配置。调优结束时全局的最优超参数配置，是所有括号中表现最好的配置。

表 5.1 给出了一个超带调度的示例，其中 \(s = 3\) 是探索性最强的括号，而 \(s = 0\) 本质上是用全预算进行随机搜索。表 5.2 展示了如果我们调优 20 个不同的超参数配置，这个调度看起来是什么样子；注意表中每个条目都是一个唯一 ID，指代一个由多个待调优超参数组成的可能配置。

背景与解释（译者注）：理解超带的关键是「预算」与「括号」这两个概念。预算指单次评估所能消耗的资源（如 XGBoost 的轮数、神经网络的 epoch 数），括号则对应一组连续减半过程的运行。表 5.1 中，当 \(\eta = 2\) 时每进入下一阶段，配置数减半而预算倍增：\(s = 3\) 括号从 8 个配置、每配置预算 1 开始，逐轮淘汰，最终留下 1 个配置用满预算 8 评估。与普通连续减半相比，超带的核心改进是不再需要人为决定「初始配置数 vs 初始预算」的取舍：它一次性并行运行多个不同初始预算的括号，既能充分探索（小预算、多配置），也能精细利用（大预算、少配置）。最后在跨括号比较时，表 5.2 中 \(HPC^* = \{15\}\) 恰来自 \(s = 2\) 而非全预算的 \(s = 1\) 或 \(s = 0\)，这正说明多括号同时进行是有价值的。

5.3.2 mlr3hyperband

连续减半和超带算法在 mlr3hyperband 中分别实现为 tnr("successive_halving") 和 tnr("hyperband")；在本节中，我们只演示超带方法。

通过例子，我们将在 tsk("sonar") 上优化 lrn("classif.xgboost")，并使用提升迭代数（nrounds）作为保真度参数——这是一个合适的选择，因为增加迭代次数会增加模型训练时间，但通常也会提升性能。超带会将越来越多的提升迭代分配给表现良好的超参数配置。

5.4 贝叶斯优化（Bayesian Optimization）

在本节中，我们将深入探讨贝叶斯优化（Bayesian Optimization，BO），也称为基于模型的优化（Model Based Optimization，MBO）。BO 的设计比我们到目前为止看到的其他调优方法更复杂，因此为了帮助说明动机，本节我们将在理论与方法上花费更多的时间。

在超参数优化（第 4 章）中，学习器被传入一个超参数配置，并通过重采样技术在给定任务上进行评估，以估计其泛化性能，目标是找到最优的超参数配置。一般来说，超参数配置到性能的映射不存在解析描述，梯度信息也不可得。因此，HPO 是黑箱优化（black box optimization）的典型例子——黑箱优化考虑的函数的数学结构与解析描述是未知的或不可利用的。因此，唯一可观测的信息是给定输入值（即超参数配置）时函数的输出值（即泛化性能）。事实上，由于评估一个学习器的性能可能花费大量时间，HPO 是一个相当昂贵的黑箱优化问题。黑箱优化问题在现实世界中广泛存在，例如在工程中经常遇到：诸如碰撞测试或化学反应等模拟实验就属于这一类。

黑箱优化（Black Box Optimization）

存在许多可用于黑箱优化的优化算法类，它们在处理此问题的方式上各不相同；例如我们在第 4 章中看到了网格/随机搜索等方法，并简要讨论了进化策略（evolutionary strategies）。贝叶斯优化指的是一类样本高效（sample-efficient）的迭代式全局黑箱优化算法，它们依赖在观测数据上训练的「代理模型」（surrogate model）来建模黑箱函数。该代理模型通常是一个非线性回归模型，试图在有限观测数据下刻画未知函数。在每次迭代中，BO 算法都使用「采集函数」（acquisition function）来确定下一个待评估的候选点。该函数基于代理模型的预测来度量搜索空间中每个点的期望「效用」（utility）。算法随后选择采集函数值最好的候选点，在该点评估黑箱函数，然后更新代理模型。这个迭代过程持续进行，直到满足某个终止标准，例如达到预设的最大评估次数或达到期望的性能水平。BO 是一种强大的方法，通常能得到良好的优化性能，尤其是在黑箱评估成本昂贵且优化预算紧张的情况下。

在本节剩余部分，我们将首先通过 bbotk 包介绍黑箱优化，然后介绍 BO 算法的构成模块，考察它们在优化过程中的相互作用，之后我们用 mlr3mbo 将这些构建模块组装成一个现成可用的黑箱优化器。主要对如何利用 BO 做 HPO 感兴趣、而不想深究底层构建模块的读者，可以跳到 第 5.4.4 节。黑箱优化和 BO 的详细介绍见 Bischl et al. (2023)、Feurer and Hutter (2019) 和 Garnett (2022)。

作为本节贯穿始末的运行示例，我们将优化正弦函数 \(f: [0, 1] \rightarrow \mathbb{R}, x \mapsto 2x * \sin(14x)\)（见图 5.2），该函数具有两个局部最小值和一个全局最小值。

5.4.1 黑箱优化（Black Box Optimization）

bbotk（black box optimization toolkit，黑箱优化工具箱）包是 mlr3 生态系统中通用黑箱优化的主力包。该包的核心是以下 R6 类：

  • OptimInstanceBatchSingleCrit 和 OptimInstanceBatchMultiCrit，用于构造描述优化问题并存储结果的优化实例（optimization instance）
  • OptimizerBatch，用于构造和配置优化算法。
优化实例（Optimization Instance）

在阅读了第 4 章之后，这些类可能看起来很眼熟。事实上，TuningInstanceBatchSingleCrit 和 TuningInstanceBatchMultiCrit 继承自 OptimInstanceBatchSingle/MultiCrit，而 TunerBatch 紧密地基于 OptimizerBatch。

OptimInstanceBatchSingleCrit 依赖于一个 Objective 函数，它封装了从域（domain，所有可能的函数输入）到余域（codomain，所有可能的函数输出）的实际映射。

Objective

目标函数可以使用不同的类来创建，所有这些类都继承自 Objective。这些类提供了定义和评估目标函数的不同方式，选择正确的类会减少类型转换的开销：

  • ObjectiveRFun 包装一个以列表为输入的函数，该列表描述单个配置，元素可以是任何类型。当底层函数评估机制是每次评估一个配置时，它很适用。
  • ObjectiveRFunMany 包装一个以多个配置的列表为输入的函数，元素可以是任何类型甚至混合类型。当多个配置的评估可以并行化时，它很有用。
  • ObjectiveRFunDt 包装一个在 data.table 上操作的函数。它允许直接在 data.table 对象上进行高效的向量化或批量评估，避免不必要的数据类型转换。

为了开始将我们的问题转化为代码，我们将使用 ObjectiveRFun 类来接收单个配置作为输入。Objective 需要指定要优化的函数及其域和余域。通过用 "minimize" 或 "maximize" 标记余域，我们指定了优化方向。注意下面我们的优化函数接收一个 list 作为输入，其中只有一个名为 x 的元素。

5.4.2 贝叶斯优化的构建模块（Building Blocks of Bayesian Optimization）

贝叶斯优化（BO）是一种全局优化算法，通常遵循以下流程（见图 5.3）：

  1. 生成并评估初始设计（initial design）
  2. 循环：
    1. 在所有迄今观测结果的归档上拟合一个代理模型，以建模未知的黑箱函数。
    2. 优化一个采集函数，以确定搜索空间中哪些点是有前景的候选点，应在下一步中被评估。
    3. 评估下一个候选点，并更新所有迄今观测结果的归档。
    4. 检查给定的终止标准是否满足，若未满足则回到 (a)。

采集函数依赖于代理模型的均值与标准差预测，不需要评估真正的黑箱函数，因此优化它相对便宜。一个好的采集函数会平衡两种行为：一是利用（exploiting）已知性能良好且代理模型不确定性低的区域的先验知识；二是探索（exploring）尚未评估点的区域——这些区域的代理模型不确定性较高。

我们把这些要素称为 BO 的「构建模块」，因为它是一种高度模块化的算法：只要上述结构到位，代理模型、采集函数和采集函数优化器都可以在一定程度上互换。mlr3mbo 的设计反映了这种模块化，其基类 OptimizerMbo 持有所有关键要素：BO 算法循环结构（loop_function）、代理模型（Surrogate）、采集函数（AcqFunction）和采集函数优化器（AcqOptimizer）。在本节中，我们将更详细地解释这些构建模块，并探讨它们在优化过程中的相互作用。

背景与解释（译者注）：图 5.3 展示了 BO 单次迭代的四要素循环：先出新手村——用随机/LHS/Sobol 等设计生成并评估若干初始点，为后续代理模型积累第一批「观测数据」；随后进入循环：① 用代理模型拟合已知观测，② 在此之上优化采集函数②，③ 评估选出的候选点并归档，④ 判断是否终止。注意代理模型与真实函数是两个不同对象：真实函数昂贵（eval 一次可能要训练一个完整模型），而代理函数便宜，能给出任意输入点的预测均值与不确定性；采集函数则在「均值低（好）」与「不确定性高（值得一试）」之间折中。

5.4.2.1 初始设计（The Initial Design）

在拟合代理模型来建模未知黑箱函数之前，我们需要数据。在拟合代理模型之前被评估的初始点集称为初始设计。

mlr3mbo 允许你手动构造初始设计，或者让一个 loop_function 替你构造并评估它。在本节中，我们将演示第一种方法，它需要更多用户输入，但因此也允许对初始设计有更多控制。

构造初始设计的一种简单方法，是使用 paradox 中的四个设计生成器之一：

  • generate_design_random()：均匀随机地生成点
  • generate_design_grid()：在均匀大小的网格上生成点
  • generate_design_lhs()：拉丁超立方采样（Latin hypercube sampling）(Stein 1987)
  • generate_design_sobol()：Sobol 序列（Sobol sequence）(Niederreiter 1988)

图 5.4 展示了这四种方法生成的设计之间的差异，假设初始设计大小为 9，域是两个从 \(0\) 到 \(1\) 的数值变量。我们已经在 第 4.1.4 节 中讨论了网格设计与随机设计的区别。LHS 设计将每个输入变量划分为大小相等的区间（见 图 5.4 中水平和垂直虚线），并确保每个区间恰好由一个样本点代表，从而得到均匀的边缘分布。此外，LHS 设计中两点之间的最小距离通常被最大化，从而实现对空间的充满填充（space-filling）覆盖。Sobol 设计的工作方式与 LHS 类似，但当维度数较大时，Sobol 能提供比 LHS 更好的覆盖。因此，通常推荐在 BO 中使用 LHS 或 Sobol 设计，但通常初始设计的影响会比 BO 的其他设计选择要小。随机设计可能已经足够好，但网格设计通常不被推荐。

无论你选择这些方法中的哪一种，结果都是一个 Design 对象，它主要只是围绕一个 data.table 的包装器：

5.4.2.2 代理模型（Surrogate Model）

代理模型包装一个回归学习器，该学习器基于观测数据建模未知的黑箱函数。在 mlr3mbo 中，SurrogateLearner 是一个继承自基类 Surrogate 的更高层 R6 类，用于构造和管理代理模型，包括在 BO 循环的每次迭代中自动构造学习器应在其上训练的 TaskRegr。

任何 mlr3 中的回归学习器都可以使用。然而，大多数采集函数同时依赖于代理模型的均值与标准差预测，后者要求支持 "se" 的 predict_type。因此并不是所有学习器都适合所有场景。典型的用于代理模型的回归学习器选择包括：用于低到中等维度数值搜索空间的高斯过程（Gaussian process，lrn("regr.km")），以及用于更高维混合（和/或分层）搜索空间的随机森林（如 lrn("regr.ranger")）。高斯过程的详细导论见 Williams and Rasmussen (2006)，对 BO 中作为代理模型的高斯过程的深入聚焦见 Garnett (2022)。在本例中，我们使用带 Matérn 5/2 核（Matérn 5/2 kernel）的高斯过程，它使用 BFGS 作为优化器来寻找最优核参数，并设置 trace = FALSE 以避免拟合时输出过多内容。

lrn_gp = lrn("regr.km", covtype = "matern5_2", optim.method = "BFGS",
  control = list(trace = FALSE))

5.4.2.3 采集函数（Acquisition Function）

粗略地说，采集函数依赖于代理模型的预测，它量化了搜索空间中每个点如果在下一次迭代被评估的话，其期望的「效用」有多大。

一个流行的例子是期望提升（expected improvement，EI）(Jones, Schonlau, and Welch 1998)，它告诉我们，给定代理模型的性能预测，一个候选点相对于到目前为止观测到的最佳函数值（即「在位者」（incumbent））能期望改进多少：

\[ \alpha_{\mathrm{EI}}(\mathbf{x}) = \mathbb{E} \left[ \max \left( f_{\mathrm{min}} - Y(\mathbf{x}), 0 \right) \right] \]

这里，\(Y(\mathbf{x)}\) 是代理模型在给定点 \(\mathbf{x}\) 处的预测（一个随机变量；当使用高斯过程时服从正态分布），\(f_{\mathrm{min}}\) 是到目前为止观测到的最佳函数值（假设最小化）。计算期望提升需要来自模型的均值和标准差预测。

在 mlr3mbo 中，采集函数（类 AcqFunction）存储在 mlr_acqfunctions 字典中，可以用 acqf() 构造，传入你想使用的方法的键以及我们的代理学习器。在我们的运行示例中，我们将使用期望提升（acqf("ei")）来选择下一个要评估的候选点。在此之前，我们必须更新（$update()）AcqFunction 对在位者的认识，以确保它仍然使用到目前为止观测到的最佳值。

背景与解释（译者注）：期望提升公式的含义：\(Y(\mathbf{x})\) 是代理模型在点 \(\mathbf{x}\) 处以随机变量形式给出的预测（高斯过程下即正态分布），\(f_{\mathrm{min}}\) 是目前为止的最佳观测值。若候选点的预测之下 \(Y(\mathbf{x})\) 有可能低于 \(f_{\mathrm{min}}\)，就把能超出的部分当作「提升」，对全部可能性取期望。于是 EI 天然包含两项：均值项（越低越好——利用）与标准差项（越大越可能再下降——探索）。图 5.5 中 EI 峰值的两处，一处是均值预测最低的区域（利用），另一处是远离已有观测、不确定性带很宽的区域（探索）。

5.4.2.4 采集函数优化器（Acquisition Function Optimizer）

采集函数优化器（类 AcqOptimizer）被用来优化采集函数，方法是在有限的计算预算内，高效地搜索潜在候选点所在的搜索空间。

AcqOptimizer

由于大多数常用采集函数具有非凸性质 (Garnett 2022)，通常采用全局优化技术来进行采集函数优化。广泛使用的采集函数优化方法包括：无导数全局优化方法，如分支定界（branch and bound）算法——例如 DIRECT 算法 (Jones, Perttunen, and Stuckman 1993)；以及多起点局部优化方法——例如从各种不同起点多次运行 L-BFGS-B 算法 (Byrd et al. 1995) 或局部搜索 (Kim and Choi 2021)。因此，采集函数的优化问题本身可以当作一个黑箱优化问题来处理，但它比原始问题便宜得多。

5.4.2.5 使用与构建循环函数（Using and Building Loop Functions）

my_simple_ego = function(
    instance,
    surrogate,
    acq_function,
    acq_optimizer,
    init_design_size
  ) {

  # 设置构建模块
  surrogate$archive = instance$archive # 归档
  acq_function$surrogate = surrogate # 代理模型
  acq_optimizer$acq_function = acq_function # 采集函数

  search_space = instance$search_space

  # 初始设计
  design = generate_design_sobol(
    search_space, n = init_design_size)$data
  instance$eval_batch(design)

  # MBO 循环
  repeat {
    candidate = tryCatch({
      # 更新代理模型
      acq_function$surrogate$update()
      # 更新采集函数
      acq_function$update()
      # 优化采集函数以产生一个新候选点
      acq_optimizer$optimize()
    }, mbo_error = function(mbo_error_condition) {
      generate_design_random(search_space, n = 1L)$data
    })

    # 评估候选点并将其加入归档
    tryCatch({
      instance$eval_batch(candidate)
    }, terminated_error = function(cond) {
      # 如果实例已终止，例如因为超时，$eval_batch() 会抛出 terminated_error
    })
    if (instance$is_terminated) break
  }

  return(instance)
}

5.4.5 噪声贝叶斯优化（Noisy Bayesian Optimization）

到目前为止，我们隐式地假设我们要优化的黑箱函数是确定性的，即重复评估同一点总会返回相同的目标函数值。然而，现实世界中的黑箱函数通常是有噪声的（noisy），这意味着由于黑箱函数之上的背景噪声，重复评估同一点会返回不同的目标函数值。例如，如果你为工厂里的一台机器建模以估计生产率，即使机器的所有参数都被控制了，由于不可控的背景因素（如环境条件），我们仍会预期在不同时间点看到不同的性能。

在 bbotk 中，你可以通过在 properties 参数中传入 "noisy" 标记一个 Objective 对象为有噪声的，这允许我们使用能以不同方式处理此类目标的方法。

sinus_1D_noisy = function(xs) {
  y = 2 * xs$x * sin(14 * xs$x) + rnorm(1, mean = 0, sd = 0.1)
  y
}
domain = ps(x = p_dbl(lower = 0, upper = 1))
codomain = ps(y = p_dbl(tags = "minimize"))
objective_noisy = ObjectiveRFun$new(sinus_1D_noisy,
  domain = domain, codomain = codomain, properties = "noisy")

有噪声的目标函数可以用不同的方式处理：

  1. 用代理模型来吸收噪声
  2. 用尊重噪声的采集函数
  3. 优化结束后的最佳点（即实例的 $result 字段）可以以一种反映噪声性的方式选择

在第一种情况下，我们可以不用插值型高斯过程，而是用通过设置 nugget.estim = TRUE 来估计测量误差的高斯过程回归：

srlrn(lrn("regr.km", nugget.estim = TRUE))

这将导致高斯过程不会完美插值训练数据，与训练数据关联的标准差预测将非零，从而反映由测量误差引起的观测函数值的不确定性。在噪声 vs. 无噪声观测背景下对高斯过程的更深入讨论可参见 Williams and Rasmussen (2006) 的第 2 章。

对于第二种选项，一个尊重噪声的采集函数示例是增强期望提升（Augmented expected improvement）(Huang et al. 2012)（acqf("aei")），它本质上是对期望提升进行了重新缩放，把测量误差考虑在内。

最后，mlr3mbo 允许通过结果分配器（result assigner）显式指定优化结束后最终结果如何被赋给实例（即会保存到 instance$result 中的内容），结果分配器可以在构造 OptimizerMbo 或 TunerMbo 时指定。ResultAssignerSurrogate 使用代理模型预测所有被评估点的均值，并选择均值预测最好的点作为最终优化结果。相比之下，默认方法 ResultAssignerArchive 只根据记录在 archive 中的评估值选择最佳点。结果分配器存储在 mlr_result_assigners 字典中，可以用 ras() 构造。

结果分配器（Result Assigner）
opt("mbo",
  loop_function = bayesopt_ego,
  surrogate = surrogate,
  acq_function = acq_function,
  acq_optimizer = acq_optimizer,
  result_assigner = ras("surrogate")
)

背景与解释（译者注）：为什么噪声黑箱需要专门处理？因为在有噪声时，「观测到的最小值」很可能是噪声造成的假象——一个点可能只是「运气好」地低了一次，再评估一次就反弹了。此时若直接采用归档中最好的原始观测值（ResultAssignerArchive 的默认行为）就可能选错。三种处理途径正好对应 BO 的三个环节：① 代理层面，用带 nugget（块金项）的高斯过程估计随机噪声，使训练点处的预测方差不为零；② 采集层面，AEI 把 EI 重新缩放，避免被噪声误导；③ 结果层面，用去噪后的代理模型均值代替原始观测来选择最终点。这个思路与经典统计学中「均值回归」的思想相通——估计的是期望而非单次观测。

5.4.6 贝叶斯优化的实践考量（Practical Considerations in Bayesian Optimization）

mlr3mbo 尝试在代理模型、采集函数、采集函数优化器甚至循环函数的选择上使用合理的默认值。例如，在纯数值搜索空间的情况下，mlr3mbo 默认使用高斯过程作为代理模型、随机森林作为回退学习器，并把学习器封装起来（第 5.1.1 节）。在混合或分层搜索空间的情况下，mlr3mbo 将使用随机森林作为代理模型。因此，用户可以不指定任何偏离默认值的设置就能进行 BO，并获得合理的优化性能。要查看这些默认值的最新概述，请查看 mbo_defaults 的帮助页面。我们将在本节的最后讨论一些使用 BO 时应考虑的实践要点。

错误处理（Error Handling）

在 BO 的语境中，构建模块的失败有大量空间，都可能破坏整个过程。例如，如果训练数据中有两个点彼此太靠近，拟合高斯过程代理模型可能会失败。

mlr3mbo 有多个内置安全网来捕获错误。Surrogate 包含 catch_errors 配置控制参数，如果设为 TRUE，会捕获代理模型训练或更新过程中发生的所有错误。AcqOptimizer 也有 catch_errors 配置控制参数，可用于捕获采集函数优化过程中发生的所有错误——无论是由于代理模型预测失败还是采集函数优化器出错。如果在任何这些步骤中捕获到错误，任何 loop_function 的标准行为都是触发回退方案：均匀随机地提出下一个候选点。注意，当为 AcqOptimizer 设置 catch_errors = TRUE 时，通常没有必要再显式地为 Surrogate 设置 catch_errors = TRUE，尽管在调试时这可能有用。

在最坏的情况下，如果所有迭代都出错了，BO 算法将退化成简单的随机搜索。理想情况下，也应该使用回退学习器（第 5.1.1 节），它会在随机提出下一个候选点之前使用。采集函数的值也总是记录在优化实例的归档中，因此检查它是确保算法行为符合预期的好办法。

代理模型（Surrogate Models）

在实践中，用户可能更喜欢更稳健的 BO 变体，而不是潜在性能更好但不稳定的变体。即使 catch_errors 参数已打开且从未被触发，也不能保证 BO 算法按预期运行。例如，高斯过程对核和核参数的选择很敏感，这些参数通常通过极大似然估计得到，次优的参数值可能导致得到一个均值与标准差预测都为常量的白噪声模型。在这种情况下，代理模型将无法提供有用的均值与标准差预测，导致 BO 算法整体性能欠佳。关于代理模型选择的另一个实践考量是开销。拟合一个朴素高斯过程的复杂度与数据点数量的立方成正比，因此 BO 算法的开销随迭代次数增长。此外，朴素高斯过程天生无法处理分类输入变量或搜索空间中的依赖关系（回想在 HPO 中我们经常处理混合分层空间的情况）。相比之下，随机森林——在 SMAC (Lindauer et al. 2022) 中被广泛用作代理模型——训练便宜、相当稳健（对自身超参数不像高斯过程那样敏感），并且能轻松处理混合分层空间。缺点是，随机森林并不是真正的贝叶斯（即没有后验预测分布），不确定性估计和插值外推能力较差。

热启动（Warmstarting）

热启动（Warmstarting）是优化中的一种技术，利用之前的优化运行来提高新的、同类优化运行的收敛速度和最终解。在 BO 中，热启动可以通过在初始设计中提供一组预计表现良好的配置来实现 (例如见 Feurer, Springenberg, and Hutter 2015)。这种方法尤其有利，因为它让代理模型能够在相关区域带着对优化地形的先验知识开始。在 mlr3mbo 中，通过指定自定义初始设计可以轻松实现热启动。此外，mlr3mbo 的一个便利特性是，即使在优化运行已终止之后，也可以在线继续优化。OptimizerMbo 和 TunerMbo 都支持这个特性，即使优化之前被中断或终止，也允许优化在给定的实例上恢复。

终止（Termination）

常见的终止标准包括：在固定次数的评估后停止，在达到给定墙钟时间（walltime）预算后停止，在性能达到某一水平时停止，或者当性能改进停滞时停止。在 BO 的语境中，如果最优采集函数值低于某个阈值就停止优化也可能是合理的。例如，如果下一个候选点的期望提升可以忽略不计，就终止优化是一种合理的方法。在本书出版时，基于采集函数的终止器尚未实现，但这个特性即将推出。

并行化（Parallelization）

大多数 BO 算法的标准行为是顺序地提出下一个应该被评估的单个候选点。用户可能希望使用并行化来更高效地计算候选点。如果你把 BO 用于 HPO，那么最有效的方法是对嵌套重采样做并行化，见 第 10.1.4 节。或者，如果循环函数支持批量提出候选点（例如 bayesopt_parego()），那么循环函数的 q 参数可以被设置：如果 Objective 被正确实现，每次迭代提出 q 个候选点，这些候选点可以并行评估。

背景与解释（译者注）：本节几个「实践考量」提醒读者 BO 并非万能银弹。最容易被忽略的两点：① catch_errors 捕获的是「运行时报错」，但代理模型「不报错却失败」更隐蔽——例如高斯过程在次优超参数下可能退化成恒值白噪声模型，此时 BO 的每一步都在浪费预算，所以检查归档里采集函数值的变化很有必要；② 高斯过程的拟合开销是 \(O(n^3)\)，随评估次数增长飞快，而随机森林训练快、对参数鲁棒、还能处理分类/分层搜索空间，代价是缺乏严格的贝叶斯后验（没有可解释的方差）。这与「探索-利用」的权衡类似，都是工程上的取舍：与其迷信算法的理论优雅，不如关注默认配置加兜底机制是否适合你的问题规模。

5.5 结论（Conclusion）

在本章中，我们研究了高级调优方法。我们首先思考了调优过程中可能发生的错误类型，以及如何处理这些错误以确保你的 HPO 过程不会崩溃。我们介绍了多目标调优，它可以同时优化多个性能度量。然后我们研究了多保真度调优，其中超带调优器通过利用低保真度评估来逼近全保真度模型的性能，从而高效地调优算法。我们将在 第 8.4.4 节 中回到超带，届时我们将学习如何利用流水线（pipelines）来用超带调优任何算法。最后，我们深入研究了贝叶斯优化，看看 bbotk、mlr3mbo 和 mlr3tuning 如何协同工作，在 mlr3 中实现复杂的 BO 调优算法，从而获得高度灵活且样本高效的算法。在下一章中，我们将研究特征选择，看看 mlr3filters 和 mlr3fselect 如何采用与 mlr3tuning 非常相似的设计接口。
