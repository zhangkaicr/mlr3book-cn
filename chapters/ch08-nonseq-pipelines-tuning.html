在第 7 章中，我们学习了如何使用 Graph 类和若干 PipeOp 对象构建简单的顺序管道（sequential pipeline）。在本章中，我们将进一步学习非顺序管道（non-sequential pipeline），它能执行更复杂的操作。接着，我们将结合 mlr3tuning 与 mlr3pipelines 的方法来调优管道，并考虑一些具体例子，包括多保真度调优（multi-fidelity tuning，5.3 节）和特征选择（第 6 章）。

在第 7 章中，我们见识了 %>>% 运算符的强大之处：它可以把多个 PipeOp 和 Learner 组合起来装配成图（graph）。给定单个 PipeOp 或 Learner 时，%>>% 运算符会把这些对象排列成线性的 Graph，其中每个 PipeOp 依次执行。然而，通过使用 gunion() 函数，我们可以把多个 PipeOp、多个 Graph、或两者的混合组合成并行的 Graph。

在下面的例子中，我们创建一个 Graph：首先把输入居中（po("scale")），然后把居中后的数据复制到两个并行分支：一个分支用表示数据是否为缺失值的列来替换数据（po("missind")），另一个分支使用中位数填补缺失值（po("imputemedian")），后者我们将在9.3 节再次讨论。两个分支的输出最后用 po("featureunion") 合并为一个数据集。

library(mlr3pipelines)

graph = po("scale", center = TRUE, scale = FALSE) %>>%
  gunion(list(
    po("missind"),
    po("imputemedian")
  )) %>>%
  po("featureunion")

graph$plot(horizontal = TRUE)

当应用到 "diabetes" 任务的前三行时，我们可以看到它如何填补缺失数据，并添加一列来指示哪些位置的值为缺失。

tsk_diabetes_head = tsk("diabetes")$filter(1:3)
tsk_diabetes_head$data(cols = c("diabetes", "insulin", "triceps"))

2:      pos      NA      NA
3:      neg      NA      42
result = graph$train(tsk_diabetes_head)[[1]]
result$data(cols = c("diabetes", "insulin", "missing_insulin", "triceps",
  "missing_triceps"))

1:      neg       0         missing     1.5         present
2:      pos       0         missing     0.0         missing
3:      neg       0         missing    -1.5         present

背景与解释（译者注）：gunion()（graph union 的缩写）的作用是把多个 PipeOp/Graph/学习器"并联"起来——它们共享同一个输入，各自独立处理，最后生成多个输出。这与顺序管道 %>>%（把上一个的输出作为下一个的输入）形成对照。并联结果通常用 po("featureunion") 把各分支产生的特征列合并成一个数据集。这是 mlr3pipelines 构建非顺序管道的两个最基本的"积木"。

8.1 选择器与并行管道（Selectors and Parallel Pipelines）

在 Graph 中，操作只作用于一部分特征是很常见的。在 mlr3pipelines 中有两种方式可以实现这一点（图 8.2）：要么把列子集传给某个 PipeOp 的 affect_columns 超参数（假定该 PipeOp 有这个超参数），该参数控制哪些列应受该 PipeOp 影响；要么使用 PipeOpSelect 算子，在指定的特征子集上并行地创建操作，然后用 PipeOpFeatureUnion 合并结果。

两种方法都使用了 Selector 函数。这些辅助函数告知 PipeOp 应当作用于哪些特征。Selector 可以按正则表达式匹配列名（selector_grep()），也可以按列类型匹配（selector_type()）。Selector 还可以用来合并变量（selector_union()）、返回其集合差（selector_setdiff()），或者选择另一个 Selector 所选特征的补集（selector_invert()）。

Selector

例如，在7.1 节中，我们对 tsk("penguins_simple") 的企鹅喙长和喙深应用了 PCA——先使用 Task 的 $select() 方法选择这些列，然后再应用 PipeOp。现在我们用 selector_grep 可以更简单地做到这一点，并且还可以继续用 selector_invert 对其它特征应用别的 PipeOp。下面我们使用 po("scale")，并利用 affect_columns 超参数：

sel_bill = selector_grep("^bill")
sel_not_bill = selector_invert(sel_bill)

graph = po("scale", affect_columns = sel_not_bill) %>>%
  po("pca", affect_columns = sel_bill)

result = graph$train(tsk("penguins_simple"))
result[[1]]$data()[1:3, 1:5]
   species    PC1     PC2 body_mass flipper_length
1:  Adelie -5.015  1.0717   -0.5676        -1.4246
2:  Adelie -4.495 -0.1853   -0.5055        -1.0679
3:  Adelie -3.755  0.4868   -1.1886        -0.4257

这种方法最大的优点是它能创建非常简单的顺序 Graph。不过，affect_columns 方法的一个缺点是：如果 PipeOp 的顺序搞混，就比较容易得到出乎意料的结果。例如，如果我们把上面的 po("pca") 和 po("scale") 对调，那么我们会先创建 "PC1" 和 "PC2" 两列，然后错误地对它们进行缩放，因为它们的名字不以 "bill" 开头，因而会被 sel_not_bill 匹配到。用 po("select") 创建并行路径则有助于缓解这类错误：它按 Selector 选出的特征进行选择，并在给定的特征子集上创建独立的数据处理流。下面我们把并行的管道作为 list 传给 gunion() 以确保它们收到相同的输入，然后用 po("featureunion") 合并输出。

po_select_bill = po("select", id = "s_bill", selector = sel_bill)
po_select_not_bill = po("select", id = "s_notbill",
  selector = sel_not_bill)

path_pca =  po_select_bill %>>% po("pca")
path_scale = po_select_not_bill %>>% po("scale")

graph = gunion(list(path_pca, path_scale)) %>>% po("featureunion")
graph$plot(horizontal = TRUE)

po("select") 方法还有一个显著优势：它允许同一组特征同时用于多个操作，或者既转换特征又保留其未转换的版本（通过在其中一条路径中使用 po("nop")）。PipeOpNOP 对输入不做任何操作，因此当你只想对一部分特征做变换而让其余特征保持不变时非常有用：

graph = gunion(list(
  po_select_bill %>>% po("scale"),
  po_select_not_bill %>>% po("nop")
)) %>>% po("featureunion")
graph$plot(horizontal = TRUE)
graph$train(tsk("penguins_simple"))[[1]]$data()[1:3, 1:5]
   species bill_depth bill_length body_mass flipper_length
1:  Adelie     0.7796     -0.8947      3750            181
2:  Adelie     0.1194     -0.8216      3800            186
3:  Adelie     0.4241     -0.6753      3250            195

背景与解释（译者注）：这里区分了两种让 PipeOp 只作用于部分特征的方式：affect_columns 直接在已有 PipeOp 上做"过滤"（管道结构保持顺序线性）；而 po("select") 则把"选列"本身变成一个显式的算子，可以配合 gunion()/po("featureunion") 构建真正的并行结构。后者的好处是逻辑清晰、不易因算子顺序造成意外（例如这里的 PCA 与缩放对调会出错），也便于复用同一组特征。选择器函数一族（selector_grep/type/invert/union/setdiff）相当于一套灵活的"列选择 DSL"。

8.2 常见模式与 ppl()（Common Patterns and ppl()）

现在你已经掌握了创建顺序和非顺序管道的方法，可以对 Task、Learner 和 Prediction 对象进行无穷无尽的变换。在8.3.1 节和8.3.2 节中，我们将通过两个例子演示如何用我们已经介绍过的方法和类构造复杂而强大的图。不过，机器学习中许多常见问题都可以用同样的管道很好地解决，因此为了方便使用，我们把这类管道实现并保存到了 mlr_graphs 字典中；字典中的管道可以通过 ppl() 糖函数获取。

ppl()

截至写作此书时，该字典包含七个 Graph（必需的参数列在下面）：

  • ppl("bagging", graph)：在 mlr3pipelines 中，bagging 指的是将一个 graph 在不同数据样本上多次运行、然后对结果取平均的过程。这在8.3.1 节中有详细讨论。
  • ppl("branch", graphs)：使用 PipeOpBranch 从给定的 graphs 创建不同的路径分支，其中只有一条分支会被求值。8.4.2 节会更详细地讨论它。
  • ppl("greplicate", graph, n)：创建一个把 graph（也可以是单个 PipeOp）复制 n 次的 Graph。该管道通过给每个 PipeOp 加后缀来避免 ID 冲突，我们会在8.3.1 节中看到它的用法。
  • ppl("ovr", graph)：一对多（One-versus-rest）分类，把多分类任务转换为多个二分类任务，原始任务中的每个类别对应一个二分类任务。这些任务随后由给定的 graph 来评估，其中 graph 应当是一个学习器（或包含能产生预测的学习器的管道）。在各二分类任务上做出的预测会被合并成原始任务所需的多分类预测。
  • ppl("robustify")：执行常见的预处理步骤，使任何 Task 都能与给定的 Learner 兼容。该管道在9.4 节中演示。
  • ppl("stacking", base_learners, super_learner)：Stacking（8.3.2 节会详细讨论）即把一个或多个模型（base_learners）的预测作为后续模型（super_learner）的特征。
  • ppl("targettrafo", graph)：创建一个 Graph，在训练过程中转换任务的预测目标（使用传给 targetmutate.trafo 超参数的函数），并确保这些变换在最终预测中会被反转（使用传给 targetmutate.inverter 超参数的函数）；9.5 节给出了一个例子。

背景与解释（译者注）：ppl() 是一个"配方库"：mlr3pipelines 把常见的高层管道（bagging、stacking、branch、greplicate、ovr、robustify、targettrafo）预先封装成可复用模板，用户只需传入必要参数即可。它相当于给 po()（单个算子）和 %>>%（顺序拼接）之上再加了一层"打包好的整体方案"，类似 scikit-learn 的 make_pipeline 与集成方法之间关系的进阶版本。

8.3 实战示例（Practical Pipelines by Example）

在本节中，我们将通过演示如何使用 bagging 和 stacking 把弱学习器变成强大的机器学习模型，从而把管道付诸实践。

8.3.1 用 "greplicate" 与 "subsample" 实现 Bagging

Bagging（来自 bootstrapp aggregating，自助聚合）的基本思想由 Breiman 提出 Breiman (1996)：把多个预测器聚合成一个更强大的预测器（图 8.5）。预测通常通过回归任务的算术平均或分类任务的多数投票来聚合。Bagging 背后的直觉是：对一组不稳定的、多样化的（即仅弱相关的）预测器取平均，可以降低整体预测的方差。每个学习器在原始数据的一个不同的随机样本上训练。

虽然我们已经看到可以用 ppl("bagging") 获得预先构建好的 bagging 管道，但本节我们将从头构建自己的管道，以展示如何构造复杂的 Graph，它将看起来像图 8.5 那样。

首先，我们用 po("subsample") 对数据进行一定比例（这里为 70%）的抽样，然后传给一个分类树（注意默认情况下 po("subsample") 是不放回抽样）。

gr_single_pred = po("subsample", frac = 0.7) %>>% lrn("classif.rpart")

接下来，我们使用 ppl("greplicate") 把图 gr_single_pred 复制 10 次（n = 10），最后用 po("classifavg") 对所有的预测做多数投票。注意我们给 "classifavg" 传了 innum = 10，告诉该 PipeOp 预期接收 10 个输入。

gr_pred_set = ppl("greplicate", graph = gr_single_pred, n = 10)
gr_bagging = gr_pred_set %>>% po("classifavg", innum = 10)
gr_bagging$plot()

现在让我们看看，在 tsk("sonar") 上做基准测试时，我们的 bagging 管道与单棵决策树和随机森林相比表现如何。

# turn graph into learner
glrn_bagging = as_learner(gr_bagging)
glrn_bagging$id = "bagging"

lrn_rpart = lrn("classif.rpart")
learners = c(glrn_bagging, lrn_rpart, lrn("classif.ranger"))

bmr = benchmark(benchmark_grid(tsk("sonar"), learners,
  rsmp("cv", folds = 3)))
bmr$aggregate()[, .(learner_id, classif.ce)]
       learner_id classif.ce
1:        bagging     0.2498
2:  classif.rpart     0.2739
3: classif.ranger     0.1973

Bagged 学习器的表现优于决策树，但逊于随机森林。为了自动重建这一管道，你可以通过指定要"装袋"的学习器、迭代次数、抽样数据比例以及用于对预测取平均的 PipeOp 来构造 ppl("bagging")，如下面的代码所示。注意我们设置了 collect_multiplicity = TRUE，它会跨各路径收集预测，这些路径在技术上使用了 Multiplicity 方法，这里我们不展开讨论，感兴趣的读者可以查阅文档。

ppl("bagging", lrn("classif.rpart"),
  iterations = 10, frac = 0.7,
  averager = po("classifavg", collect_multiplicity = TRUE))

我们的管道与随机森林的主要区别在于：后者还会做特征子采样——在每个分裂点只考虑可用特征的随机子集。虽然我们不能直接用 mlr3pipelines 实现这一点，但可以使用自定义的 Selector 方法来近似。我们将通过传一个"以任务为输入、返回特征样本"的函数来创建这个 Selector——我们对特征数量的平方根进行抽样，以模仿 ranger 中的实现。为了提高效率，现在我们用 ppl("bagging") 重建上面的步骤：

# custom selector
selector_subsample = function(task) {
  sample(task$feature_names, sqrt(length(task$feature_names)))
}

# bagging pipeline with our selector
gr_bagging_quasi_rf = ppl("bagging",
  graph = po("select", selector = selector_subsample) %>>%
    lrn("classif.rpart", minsplit = 1),
  iterations = 100,
  averager = po("classifavg", collect_multiplicity = TRUE)
)

# bootstrap resampling
gr_bagging_quasi_rf$param_set$values$subsample.replace = TRUE

# convert to learner
glrn_quasi_rf = as_learner(gr_bagging_quasi_rf)
glrn_quasi_rf$id = "quasi.rf"

# benchmark
design = benchmark_grid(tsks("sonar"),
  c(glrn_quasi_rf, lrn("classif.ranger", num.trees = 100)),
  rsmp("cv", folds = 5)
)
bmr = benchmark(design)
bmr$aggregate()[, .(learner_id, classif.ce)]
       learner_id classif.ce
1:       quasi.rf     0.1826
2: classif.ranger     0.1590

仅用几行代码，我们就从较弱的学习器造出了一个强大的模型，可以看到它的表现与 ranger::ranger 的实现不相上下。在下一节中，我们将看第二个例子，它在管道内部使用交叉验证。

8.3.2 用 po("learner_cv") 实现 Stacking

Stacking（堆叠）(Wolpert 1992) 是另一种非常流行的集成（ensembling）技术，可以显著提升预测性能。Stacking 的基本思想是：把多个模型（通常称为 0 层模型，level 0 models）的预测作为后续模型（1 层模型，the level 1 model）的特征，由后者来组合这些预测（图 8.7）。一个简单的组合可以是线性模型（如果你有很多 0 层模型，则可以用正则化），因为 0 层模型的加权和通常既合理又够用。不过，也可以使用非线性的 1 层模型，而且 1 层模型也完全有可能同时访问输入特征和 0 层预测。Stacking 可以构建两层以上（无论从概念上还是在 mlr3 中），但我们这里只限于这个更简单的结构，在实践中它也常常表现良好。

与 bagging 一样，我们将演示如何手动创建一个 stacking 管道，尽管用 ppl("stacking") 已经可以得到预先构建好的管道。

Stacking 管道依赖于 0 层学习器在 $train() 阶段就返回预测。在 mlr3pipelines 中，这可以通过 PipeOpLearnerCV 实现。在训练过程中，该算子会执行交叉验证，并把样本外预测传给 1 层模型。推荐使用交叉验证得到的预测，以降低过拟合风险。

我们先创建 0 层学习器，产生将用作特征的预测。在这个例子中，我们使用分类树、k 近邻（KNN）和一个正则化 GLM。每个学习器都被包在 po("learner_cv") 中，后者会在输入数据上做交叉验证，然后把 Learner 的预测输出为一个新的 Task 对象。

lrn_rpart = lrn("classif.rpart", predict_type = "prob")
po_rpart_cv = po("learner_cv", learner = lrn_rpart,
  resampling.folds = 2, id = "rpart_cv"
)

lrn_knn = lrn("classif.kknn", predict_type = "prob")
po_knn_cv = po("learner_cv",
  learner = lrn_knn,
  resampling.folds = 2, id = "knn_cv"
)

lrn_glmnet = lrn("classif.glmnet", predict_type = "prob")
po_glmnet_cv = po("learner_cv",
  learner = lrn_glmnet,
  resampling.folds = 2, id = "glmnet_cv"
)

这些学习器用 gunion() 组合起来，并用 po("featureunion") 合并它们的预测。这在 $train() 的输出中体现出来：

gr_level_0 = gunion(list(po_rpart_cv, po_knn_cv, po_glmnet_cv))
gr_combined = gr_level_0 %>>% po("featureunion")

保留原始特征（Retaining Features）

在这个例子中，原始特征被移除了，因为每个 PipeOp 只返回各自学习器做出的预测。要保留原始特征，请在传给 gunion() 的列表中加入 po("nop")。

得到的任务包含来自每个 0 层学习器的、两个类别的预测概率。不过，由于概率总和总是 \(1\)（这是二分类任务），我们只需要其中一个类别的预测即可，所以可以用 po("select") 只保留一个类别的预测（本例中选 "M"）。

gr_stack = gr_combined %>>%
  po("select", selector = selector_grep("\\.M$"))

最后，我们可以把管道与最终的模型组合起来，由该模型把这些预测作为输入。下面我们使用逻辑回归，它以加权线性和的方式来组合 0 层的预测。

gr_stack = gr_stack %>>% po("learner", lrn("classif.log_reg"))
gr_stack$plot(horizontal = TRUE)

由于最终模型是易于解释的逻辑回归，我们可以通过查看最终训练好的模型来检查各 0 层学习器的权重：

glrn_stack = as_learner(gr_stack)

glrn_stack$id = "stacking"

  list(lrn_rpart, lrn_knn, lrn_glmnet, glrn_stack), rsmp("repeated_cv"))

这个实验证实：在单个模型中，KNN 学习器表现最好，不过我们的 stacking 管道胜过它们全部。既然我们已经看到了这个管道的内部机制，下次你可能想用 ppl("stacking") 更高效地创建它。要复现上面的例子，你可以运行：

ppl("stacking",
  base_learners = lrns(c("classif.rpart", "classif.kknn",
    "classif.glmnet")),
  super_learner = lrn("classif.log_reg")
)

背景与解释（译者注）：Stacking（堆叠）的关键在于 po("learner_cv")：它让 0 层学习器在 $train() 阶段就通过交叉验证产生"样本外"预测，从而避免"用训练数据自己的预测当特征"造成的过拟合信号泄漏。如果直接让学习器预测训练数据本身，1 层模型看到的特征会过于乐观，相当于把"背答案"的痕迹也当成了有用信息。这也是为什么 stacking 里使用交叉验证预测是推荐做法。

在介绍了 mlr3pipelines 的构件并看到它们落地之后，我们现在转向更高级的功能：把管道与调优结合起来。

8.4 调优图（Tuning Graphs）

通过把管道包装进 GraphLearner，我们可以借助 mlr3tuning 在两个复杂度层次上对管道进行调优：

  1. 调优一个固定的、通常是顺序的管道，其中预处理与给定的学习器结合。这其实就是在联合调优管道中各操作的选定超参数子集。在概念上（mlr3 中技术上也是如此），这与调优一个不属于任何管道的普通学习器并没有多大区别。

  2. 不仅调优管道的超参数（其结构在所包含的操作上并未完全固定），还要调优究竟把哪些具体的 PipeOp 应用到数据上。这就允许我们以数据驱动方式选择这些操作（例如用哪个学习器、做哪种预处理），这一做法被称为「组合式算法选择与超参数优化」（Combined Algorithm Selection and Hyperparameter optimization，CASH）(Thornton et al. 2013)。我们即将看到，在 mlr3pipelines 中可以通过功能强大的分支（branch，8.4.2 节）和代理（proxy，8.4.3 节）元算子来实现。通过它们，我们可以在 mlr3 中方便地创建自己的「迷你 AutoML 系统」(Hutter, Kotthoff, and Vanschoren 2019)，甚至可以针对特定任务量身定制。

8.4.1 调优 Graph 超参数

让我们考虑一个简单的顺序管道：先 po("pca") 后 lrn("classif.kknn")：

graph_learner = as_learner(po("pca") %>>% lrn("classif.kknn"))

我们的 PCA PipeOp 的 rank. 超参数的最优设置，在现实中可能取决于 KNN 模型的 k 超参数取值，因此联合调优是合理的。为此，我们只需使用第 4 章介绍的调优 Learner 的语法。

lrn_knn = lrn("classif.kknn", k = to_tune(1, 32))
po_pca = po("pca", rank. = to_tune(2, 20))
graph_learner = as_learner(po_pca %>>% lrn_knn)
graph_learner$param_set$values
$pca.rank.
Tuning over:
range [2, 20]


$classif.kknn.k

range [1, 32]

我们可以看到，管道的 $param_set 中包含了所有被选中超参数的调优令牌（tune token），从而形成一个联合搜索空间。我们可以在一个带嵌套重采样的基准实验中，用 AutoTuner 比较调优与未调优的管道：

glrn_tuned = auto_tuner(tnr("random_search"), graph_learner,
  rsmp("holdout"), term_evals = 10)
glrn_untuned = po("pca") %>>% lrn("classif.kknn")
design = benchmark_grid(tsk("sonar"), c(glrn_tuned, glrn_untuned),
  rsmp("cv", folds = 5))
benchmark(design)$aggregate()[, .(learner_id, classif.ce)]
               learner_id classif.ce
1: pca.classif.kknn.tuned     0.2028
2:       pca.classif.kknn     0.2458

调优管道通常比调优单个学习器耗时更长，因为训练步骤往往更复杂，搜索空间也更大。因此，并行化（10.1 节）和/或更高效的搜索大调优空间的调优方法（例如贝叶斯优化，5.4 节）往往比较合适。

背景与解释（译者注）：当 PipeOp 与学习器被 as_learner() 包装成 GraphLearner 之后，它们的超参数会汇聚到同一个 $param_set 中，并以各自的 ID 为前缀（例如 pca.rank.、classif.kknn.k）。这使得"管道的超参数调优"在语法上与普通学习器完全一致：to_tune() 负责标记搜索空间，AutoTuner/tune() 负责执行优化。如果你已经熟悉第 4 章的调优流程，这里几乎没有新增的语法负担。

8.4.2 用 po("branch") 调优备选路径

在前一节中，我们调优了 stacking 管道里的 KKNN 和决策树，也调优了 PCA 的秩。但其实我们在调优 PCA 时，并没有先考虑它是否有益。在本节中，我们将通过 PipeOpBranch 和 PipeOpUnbranch 来回答这个问题：它们使得在管道中指定多个备选路径成为可能。po("branch") 创建多条路径，数据只能沿其中一条流动，具体由 selection 超参数决定（图 8.13）。这一概念使我们能够用调优来决定把哪些 PipeOp 和 Learner 纳入管道，同时还允许对每条路径中的所有选项进行调优。

为了演示备选路径，我们将使用 MNIST (LeCun et al. 1998) 数据，它很适合用来演示预处理。数据从 OpenML 加载（在11.1 节中介绍），我们会对数据做子集化以加快示例运行。

library(mlr3oml)
otsk_mnist = otsk(id = 3573)
tsk_mnist = as_task(otsk_mnist)$
  filter(sample(70000, 1000))$
  select(otsk_mnist$feature_names[sample(700, 100)])

po("branch") 的初始化要么给一个分支的数量，要么给一个 character 向量（指明各分支的名称），后者能让 selection 超参数（下面讨论）更易读。下面我们创建三个分支：什么都不做（po("nop")）、应用 PCA（po("pca")）、先移除常数特征（po("removeconstants")）再应用 Yeo-Johnson 变换（po("yeojohnson")）。重要的是必须用 po("unbranch")（参数与 "branch" 相同），以确保各输出合并成一个结果对象。

paths = c("nop", "pca", "yeojohnson")

graph = po("branch", paths, id = "brnchPO") %>>%
  gunion(list(
    po("nop"),
    po("pca"),
    po("removeconstants", id = "rm_const") %>>%
      po("yeojohnson", id = "YJ")
  )) %>>% po("unbranch", paths, id = "unbrnchPO")

graph$plot(horizontal = TRUE)

我们可以看到该 Graph 的输出如何取决于 branch.selection 超参数的设置：

# use the "PCA" path
graph$param_set$values$brnchPO.selection = "pca"
# new PCA columns
head(graph$train(tsk_mnist)[[1]]$feature_names)
[1] "PC1" "PC2" "PC3" "PC4" "PC5" "PC6"
# use the "No-Op" path
graph$param_set$values$brnchPO.selection = "nop"
# same features
head(graph$train(tsk_mnist)[[1]]$feature_names)
[1] "pixel4"  "pixel8"  "pixel10" "pixel11" "pixel14" "pixel39"

ppl("branch") 简化了上述过程——只需把不同的路径传给 graphs 参数即可（这里为简洁起见省去 "rm_const"）：

ppl("branch", graphs = pos(c("nop", "pca", "yeojohnson")))

分支甚至还可以用来调优：对给定数据集，多个学习器中哪一个最合适。我们把例子再扩展一步，在决策树和 KKNN 之间加一个选择：

graph_learner = graph %>>%
  ppl("branch", lrns(c("classif.rpart", "classif.kknn")))
graph_learner$plot(horizontal = TRUE)

调优 selection 超参数有助于确定哪些选项组合起来效果最好。我们还额外调优 KNN 学习器的 k 超参数，因为它可能取决于所执行的预处理类型。由于这个超参数只有在选择 "classif.kknn" 路径时才被激活，我们设置一个依赖关系（4.4.4 节）：

graph_learner = as_learner(graph_learner)

graph_learner$param_set$set_values(
  brnchPO.selection = to_tune(paths),
  branch.selection = to_tune(c("classif.rpart", "classif.kknn")),
  classif.kknn.k = to_tune(p_int(1, 32,
    depends = branch.selection == "classif.kknn"))
)

instance = tune(tnr("grid_search"), tsk_mnist, graph_learner,
  rsmp("repeated_cv", folds = 3, repeats = 3), msr("classif.ce"))

instance$archive$data[order(classif.ce)[1:5],
  .(brnchPO.selection, classif.kknn.k, branch.selection, classif.ce)]
   brnchPO.selection classif.kknn.k branch.selection classif.ce
1:        yeojohnson             11     classif.kknn     0.2390
2:        yeojohnson             15     classif.kknn     0.2463
3:        yeojohnson              8     classif.kknn     0.2463
4:        yeojohnson             18     classif.kknn     0.2507

如结果和图图 8.12所示，选择了 k 设为 11 的 KNN 学习器，它与 Yeo-Johnson 变换组合时表现最好。

8.4.3 用 po("proxy") 调优

本节涉及高级机器学习或技术细节。

po("proxy") 是一个元算子：它执行存储在 content 超参数中的操作，该操作可以是另一个 PipeOp 或 Graph。因此，它可用于调优并从多个可传给该超参数的 PipeOp 或 Graph 中做出选择（图 8.13）。

要用 po("proxy") 复现上面的例子，第一步是创建占位的 PipeOpProxy 算子，为那些需要调优的操作（即不同的路径）占位。

graph_learner = po("proxy", id = "preproc") %>>%
  po("proxy", id = "learner")
graph_learner = as_learner(graph_learner)

content 超参数的调优空间应当是一个待评估选项的离散集合，以 p_fct 的形式传入（4.4.2 节）。对于 "preproc" 代理算子，这简单来说就是我们想考虑的不同 PipeOp：

# define content for the preprocessing proxy operator
preproc.content = p_fct(list(
  nop = po("nop"),
  pca = po("pca"),
  yeojohnson = po("removeconstants") %>>% po("yeojohnson")
))

对于 "learner" 代理，情况更复杂一些，因为学习器的选择依赖于不止一个搜索空间分量：学习器本身的选择（lrn("classif.rpart") 或 lrn("classif.kknn")）以及 KNN 学习器被调优的 k 超参数。为此，我们给 .extra_trafo 传一个变换函数（4.4.3 节）。注意在该变换内部我们对 learner.content 做了克隆（clone），否则我们最终会按引用修改搜索空间内部的原始 Learner 对象（1.5.1 节）。

# define content for the learner proxy operator
learner.content = p_fct(list(
    classif.rpart = lrn("classif.rpart"),
    classif.kknn = lrn("classif.kknn")
))

# define transformation to set the content values
trafo = function(x, param_set) {
    if (!is.null(x$classif.kknn.k)) {
      x$learner.content = x$learner.content$clone(deep = TRUE)
      x$learner.content$param_set$values$k = x$classif.kknn.k
      x$classif.kknn.k = NULL
    }
    x
}

现在我们可以把这一切拼起来，加入 KNN 调优，然后运行实验。

search_space = ps(
  preproc.content = preproc.content,
  learner.content = learner.content,
  # tune KKNN parameter as normal
  classif.kknn.k = p_int(1, 32,
    depends = learner.content == "classif.kknn"),
  .extra_trafo = trafo
)

instance = tune(tnr("grid_search"), tsk_mnist, graph_learner,
  rsmp("repeated_cv", folds = 3, repeats = 3), msr("classif.ce"),
  search_space = search_space)

as.data.table(instance$result)[,
  .(preproc.content,
    classif.kknn.k = x_domain[[1]]$learner.content$param_set$values$k,
    learner.content, classif.ce)
]
   preproc.content classif.kknn.k learner.content classif.ce
1:      yeojohnson             18    classif.kknn     0.2427

同样地，最佳配置是带 Yeo-Johnson 变换的 KNN 学习器。在实践中，po("proxy") 提供了完全的灵活性，对于更复杂的使用场景可能更有用；而 ppl("branch") 在比较直截了当的场景中更高效。

背景与解释（译者注）：po("branch") 与 po("proxy") 都能实现"从若干选项里选一个"，但思路不同：分支在结构上显式列出所有备选路径，数据只走被选中的一条，直观、可追溯；代理则是放一个"占位符"，把"选项本身"作为超参数（content）放进搜索空间，更适合选项多、需要借助 transform 做复杂参数注入的场景。二者常被视为构建 AutoML 工作流的基础设施。另一个重要小细节：在 trafo 中修改 R6 对象前先 clone(deep = TRUE)，可避免污染搜索空间中的原始对象。

8.4.4 使用子抽样的 Hyperband

本节涉及高级机器学习或技术细节。

在5.3 节中，我们学习了 Hyperband 调优器，以及它如何利用保真度（fidelity）参数来高效调优学习器。既然现在你已经学会了管道以及如何调优它们，在这个简短的小节中，我们将回到 Hyperband，展示如何把本章学到的所有内容组合起来，使 Hyperband 能用于任何 Learner。

我们之前看到，有些学习器的某些超参数可以自然地充当保真度参数，例如随机森林中的树的数量。然而，利用管道，我们现在可以为任何模型创建保真度参数——使用 po("subsample")。po("subsample") 的 frac 参数控制送入后续 Learner 的数据量。一般来说，给 Learner 的数据越少，模型训练越快，但预测质量比提供更多训练数据时更差。用较少的数据做重采样，仍然能让我们获得有关不同模型配置相对性能的一些信息，因此"子抽样的数据比例"是保真度参数的绝佳候选。

在这个例子中，我们将在 tsk("sonar") 上优化 SVM 的超参数 cost 和 gamma：

library(mlr3tuning)

learner = lrn("classif.svm", id = "svm", type = "C-classification",
  kernel = "radial", cost  = to_tune(1e-5, 1e5, logscale = TRUE),
  gamma = to_tune(1e-5, 1e5, logscale = TRUE))

然后我们构造 po("subsample")，指定把 frac 参数在 \([3^{-3}, 1]\) 区间内作为保真度参数，并设置 "budget" 标签把这个信息传给 Hyperband。我们把它加到 SVM 上，创建一个 GraphLearner。

graph_learner = as_learner(
  po("subsample", frac = to_tune(p_dbl(3^-3, 1, tags = "budget"))) %>>%
  learner
)

按照良好实践，我们对学习器做封装（encapsulate）并添加一个回退（fallback），以防止致命错误（5.1 节）。

graph_learner$encapsulate("evaluate", lrn("classif.featureless"))
graph_learner$timeout = c(train = 30, predict = 30)

现在我们可以像往常一样通过调优 GraphLearner 来调优我们的 SVM，下面为 Hyperband 设置 eta = 3。

instance = tune(tnr("hyperband", eta = 3), tsk("sonar"), graph_learner,
  rsmp("cv", folds = 3), msr("classif.ce"))

instance$result_x_domain
$subsample.frac
[1] 1

$svm.cost
[1] 278.7

$svm.gamma
[1] 0.05041

背景与解释（译者注）：Hyperband 属于"多保真度"调优方法：它用廉价但粗略的评估（这里指只用部分数据训练）快速淘汰没希望的配置，再把预算集中到少数有潜力的配置上。保真度参数（fidelity）就是"评估开销与评估准确性之间的旋钮"。mlr3 中通过给某个参数打上 tags = "budget" 标签，Hyperband 便知道该用哪个参数来控制每轮评估的资源量。这里用 po("subsample") 的 frac 充当 budget，使得任何学习器都能接入 Hyperband。

8.4.5 用过滤管道做特征选择

本节涉及高级机器学习或技术细节。

在6.1.4 节中，我们学习了基于过滤器的特征选择，以及如何手动运行一个过滤器然后提取被选中的特征——通常使用任意的、未经调优的阈值。现在我们已经介绍了管道和调优，让我们简要回到特征选择，演示如何利用 po("filter") 来自动化基于过滤器的特征选择。po("filter") 有一个 filter 构造函数参数，它接收一个 Filter 对象作为过滤方法，同时还有多种选择特征的参数可供选择：

  • filter.nfeat —— 要选择的特征数量
  • filter.frac —— 要选择的特征比例
  • filter.cutoff —— 过滤器取值的最小阈值；过滤值大于等于该阈值的特征被保留
  • filter.permuted —— 在应用过滤器之前先向任务中加入随机排列的特征；所有位于第 permuted 个随机特征之前的特征被保留

下面我们使用信息增益（information gain）过滤器并选择排名前三的特征：

library(mlr3filters)
library(mlr3fselect)

task_pen = tsk("penguins")

# combine filter (keep top 3 features) with learner
po_flt = po("filter", filter = flt("information_gain"), filter.nfeat = 3)
graph = po_flt %>>% po("learner", lrn("classif.rpart"))

po("filter", filter = flt("information_gain"), filter.nfeat = 3)$
  train(list(task_pen))[[1]]$feature_names
[1] "bill_depth"     "bill_length"    "flipper_length"

把阈值（3）定为 3 是比较随意的，但通过调优一个图，我们可以优化这个阈值：

# tune between 1 and total number of features
po_filter = po("filter", filter = flt("information_gain"),
  filter.nfeat = to_tune(1, task_pen$ncol))

graph = as_learner(po_filter %>>% po("learner", lrn("classif.rpart")))

instance = tune(tnr("random_search"), task_pen, graph,
  rsmp("cv", folds = 3), term_evals = 10)
instance$result
   information_gain.filter.nfeat learner_param_vals  x_domain classif.ce
1:                             4          <list[2]> <list[1]>    0.06397

在这个例子中，4 是最优的特征数量。在特征选择中对调优结果做可视化特别有用，因为可能出现最优结果只是比特征更少的结果略好一点的情况（更少的特征会得到训练更快、可能也更容易解释的模型）。

autoplot(instance)

现在我们看到，在这个案例中，四个变量可能同样好，因此我们可以考虑继续采用四个特征，而不是 instance$result 建议的六个。

8.5 结论（Conclusion）

在本章中，我们在第 7 章所学内容的基础上，构建了复杂的非顺序 Graph。我们看到了如何构建自己的图，以及如何使用 ppl() 加载 mlr3pipelines 中现成的 Graph。接着我们讨论了调优管道的不同方式，包括超参数的联合调优，以及调优 Graph 中 PipeOp 的选择，从而能够构建简单的、自定义的 AutoML 系统。在第 9 章中，我们将更详细地研究如何利用管道进行数据预处理。

8.6 练习（Exercises）

  1. 创建一个图：把所有不含缺失值的数值列替换为它们的 PCA 变换。用两种方式解决：一个是在顺序图中使用 affect_columns，另一个是在非顺序图中使用 po("select")。在 tsk("diabetes") 上训练该图以检查结果。提示：你可能会发现 selector_missing() 很有用。
  2. 8.3.2 节中的 po("select") 是必要的：它用于移除冗余的预测（回忆一下这是二分类任务，因此我们不需要两类预测）。但是，如果这是一个多分类任务，那么用 selector_grep() 就需要给出一个用于所有应保留的预测列的模式，这将是低效的。更合适的做法是给"要移除的那一个类别"提供模式。你如何用 mlr3pipelines 提供的 Selector 函数做到这一点？实现它并在 tsk("wine") 上训练修改后的 stacking 管道，以 lrn("classif.multinom") 作为 1 层学习器。
  3. 如何在不显式命名你想排除的类别的情况下解决上一题，使你的图适用于任何分类任务？提示：看看8.3.1 节中的 selector_subsample。
  4. (*) 组合管道、分支和调优，创建你自己的「迷你 AutoML 系统」。它应当允许自动预处理，以及自动选择一个表现良好的学习算法。你的 PipeOp 和模型都应当被调优。你的系统应当配备两种预处理选项（缺失值插补和因子编码）以及至少三种可供选择的学习算法。你可以用随机搜索来优化它，或尝试使用更高级的调优算法。至少在三个不同的数据集上测试它，并通过嵌套重采样把它与未调优的随机森林的性能做比较。
