预处理（Preprocessing）

《Applied Machine Learning Using mlr3 in R》中文翻译 · 章节 第 9 章 预处理

Janek Thomas
慕尼黑路德维希-马克西米利安大学（Ludwig-Maximilians-Universität München），慕尼黑机器学习中心（Munich Center for Machine Learning, MCML）以及 Essential Data Science Training GmbH

第 7 章和第 8 章对 mlr3pipelines 做了技术性介绍，本章将演示如何使用这些流水线来解决为机器学习预处理数据时的常见问题，包括因子编码（factor encoding）、缺失值插补（imputation of missing values）、特征与目标变换（feature and target transformations）以及函数型特征提取（functional feature extraction）。特征选择（feature selection）是一种重要的预处理方法，在第 6 章中介绍。

在本书中，预处理（preprocessing）指在用数据拟合模型之前对数据所做的一切，而后处理（postprocessing）则指在模型拟合完成后对预测结果所做的一切。

数据清洗（data cleaning）是预处理的重要组成部分，涉及去除数据中的错误、噪声和冗余；我们在此只非常简要地提及数据清洗，因为它通常是在 mlr3 之外对原始数据集进行的。

数据清洗（Data Cleaning）

预处理的另一个方面是特征工程（feature engineering），它涵盖在数据送入机器学习模型之前对数据进行的其他所有变换，包括从可能非结构化的数据（如书面文本、序列或图像）中创建特征。特征工程的目标是让数据能够被给定的学习器处理，和/或进一步提升预测性能。需要指出的是，特征工程对较简单的算法帮助最大，而高度复杂的模型通常从中获益较少，并且几乎不需要数据准备即可训练。可以通过特征工程解决的数据常见难题包括：偏态分布的特征、高基数（high-cardinality）分类特征、缺失观测、高维特征以及分类任务中的类别不平衡。深度学习在自动化特征工程方面已展现出有前景的结果，然而其有效性取决于所处理数据的复杂性和性质，以及所针对的具体问题。通常它在自然语言处理和计算机视觉问题上表现良好，而对于标准表格数据，基于树的集成方法（如随机森林或梯度提升）往往仍然更优（且更易处理）。不过，表格型深度学习方法目前正在迅速追赶。因此，人工特征工程往往仍然必要，但借助 mlr3pipelines 可以尽可能简化这一过程。

特征工程（Feature Engineering）

在本章中，我们将使用 Ames 房价数据的一个改编版本 (De Cock 2011)。我们对数据做了少许改动，并引入了一些额外的（人为）问题，以便在单个数据集上尽可能全面地展示预处理的各种方面。修改后的版本随 mlr3data 一起发布，从原始数据重建该版本的代码可在 https://github.com/mlr-org/mlr3data/ 的 data-raw 目录中找到。这个原始数据集是作为 Boston Housing 数据的替代品收集的，常用于展示机器学习中的特征工程。原始版与处理版数据均可直接从 AmesHousing 包中加载。该数据集包含 2006 至 2010 年间售出的位于爱荷华州埃姆斯（Ames, Iowa）的 2,930 套住宅物业（行）。它包含 81 个特征，涉及房产的各个方面、地块的大小与形状以及房产状况与质量的信息。预测目标是以美元计的售价，因此这是一个回归任务。

ames = mlr3data::ames_housing

9.1 数据清洗（Data Cleaning）

第一步，我们探索数据并寻找诸如常量特征或重复特征之类的简单问题。使用 DataExplorer 或 skimr 这类包可以非常高效地完成这项工作，它们能创建大量信息丰富的图形。

下面我们总结数据清洗中最主要的发现，但仅作粗略考察：

# 1. `Misc_Feature_2` 是只有一个水平 `Othr` 的因子。
summary(ames$Misc_Feature_2)
Othr 
2930 
# 2. `Condition_2` 与 `Condition_3` 完全相同。
identical(ames$Condition_2, ames$Condition_3)
[1] TRUE
# 3. `Lot_Area` 与 `Lot_Area_m2` 是同一数据的不同量纲
cor(ames$Lot_Area, ames$Lot_Area_m2)
[1] 1

对这三个问题而言，直接移除有问题的特征（或成对特征中的一个）可能就是最好的处理方式。

to_remove = c("Lot_Area_m2", "Condition_3", "Misc_Feature_2")

其他应当检查的典型问题包括：

  1. ID 列，即对每条观测都唯一的列，应被移除或打上标记。
  2. NA 未被正确编码，例如编码为 "NA" 或 ""
  3. 数据中的语义错误，例如负的 Lot_Area
  4. 对于无法处理这类特征的算法，数值特征被编码成了分类特征。

在继续特征工程之前，我们将创建一个贯穿本章使用的任务、度量（measure）和重采样（resampling）策略。

tsk_ames = as_task_regr(ames, target = "Sale_Price", id = "ames")
# 移除有问题的特征
tsk_ames$select(setdiff(tsk_ames$feature_names, to_remove))

msr_mae = msr("regr.mae")
rsmp_cv3 = rsmp("cv", folds = 3)
rsmp_cv3$instantiate(tsk_ames)

最后，我们运行一个非常简单的实验，用简单的无特征基线（featureless baseline）来验证我们的设置是否按预期工作。注意，下面我们设置了 robust = TRUE，以便始终预测售价的中位数，而非均值。

lrn_baseline = lrn("regr.featureless", robust = TRUE)
lrn_baseline$id = "Baseline"
rr_baseline = resample(tsk_ames, lrn_baseline, rsmp_cv3)
rr_baseline$aggregate(msr_mae)
regr.mae 
   56056

背景与解释（译者注）：本节介绍的数据清洗属于传统意义上的「脏数据」处理。在实际项目中，这类问题（常量列、重复列、ID 列、编码不规范等）通常应在进入 mlr3 之前就处理好。作者在此安排一个非常简单的基线模型（regr.featureless），其作用是在后续对比中给出「不看任何特征也能达到的误差水平」——一个模型若连基线都打不过，通常说明预处理或模型选择存在问题。后文所有实验都围绕这个基线展开对比，读者应把每次 bmr$aggregate() 输出中的第一行当作参照物。

9.2 因子编码（Factor Encoding）

许多机器学习算法实现（如 XGBoost (Chen and Guestrin 2016)）无法处理分类数据，因此必须将分类特征编码为数值变量。

lrn_xgb = lrn("regr.xgboost", nrounds = 100)
lrn_xgb$train(tsk_ames)
Error:
! 
✖ <TaskRegr:ames> has the following unsupported feature types: factor
→ Class: Mlr3ErrorInput

分类特征可以按其基数（cardinality）分组，基数指的是它们包含的水平数：二值特征（binary features，两个水平）、低基数特征和高基数特征；关于什么算高基数特征并没有统一阈值，这个阈值甚至可以被调优。目前，我们暂且把水平数超过 10 的特征视为高基数：

names(which(lengths(tsk_ames$levels()) > 10))
[1] "Exterior_1st" "Exterior_2nd" "MS_SubClass"  "Neighborhood"

二值特征可以简单地通过把其中一个特征水平设为 1、另一个设为 0 来编码。

names(which(lengths(tsk_ames$levels()) == 2))
[1] "Alley"       "Central_Air" "Street"

低基数特征可以通过独热编码（one-hot encoding）来处理。独热编码是把分类特征转换为二进制表示的过程，其中每个可能的类别都表示为单独的二进制特征。理论上，只需创建比水平数少一个的二进制特征即可，因为把所有二进制特征都设为 0 也是一种合法表示。这通常被称为哑变量或处理编码（dummy or treatment encoding），当学习器是广义线性模型（GLM）或可加模型（GAM）时必须使用这种编码。

独热编码（One-hot Encoding）

有些学习器支持处理分类特征，但若它们内部应用的编码仅适合低基数特征（如独热编码），遇到高基数特征时仍可能崩溃。影响编码（impact encoding）(Micci-Barreca 2001) 是处理高基数特征的好方法。影响编码把分类特征转换为数值。其思想是利用目标特征，在分类特征与一个能反映该特征预测目标重要性的数值之间建立映射。影响编码包含以下步骤：

影响编码（Impact Encoding）
  1. 按分类特征对目标变量分组。
  2. 计算每组目标变量的均值。
  3. 计算目标变量的全局均值。
  4. 计算每个组的得分（impact score），即该组目标变量的均值与目标变量全局均值之差。
  5. 用影响得分替换分类特征。

影响编码在保留分类特征信息的同时，也创造了一个能反映其在预测目标时重要性的数值表示。与独热编码相比，其主要优势是无论分类特征有多少水平，都只创建一个数值特征，因此尤其适用于高基数特征。由于影响得分的计算用到了目标的信息，编码过程必须嵌入交叉验证中，以避免训练数据与测试数据之间的信息泄漏（第 3 章）。

除了编码特征之外，针对分类特征的其他基本预处理步骤还包括：移除常量特征（只有一个水平的特征，可能已在数据清洗阶段被移除），以及合并（collapse）出现频率很低的水平。这类问题可能作为重采样的产物而出现，因为重采样会进一步缩小数据集规模。对这些特征进行分层（stratification）是缓解该问题的另一种方式（第 3.2.6 节）。

在下面的代码中，我们用 po("removeconstants") 移除只有一个水平的特征，用 po("collapsefactors") 合并数据中出现频率低于 1% 的水平，用 po("encodeimpact") 对高基数特征进行影响编码，用 po("encode", method = "one-hot") 对低基数特征做独热编码，最后用 po("encode", method = "treatment") 对二值特征做处理编码。

factor_pipeline =
    po("removeconstants") %>>%
    po("collapsefactors", no_collapse_above_prevalence = 0.01) %>>%
    po("encodeimpact",
        affect_columns = selector_cardinality_greater_than(10),
        id = "high_card_enc") %>>%
    po("encode", method = "one-hot",
        affect_columns = selector_cardinality_greater_than(2),
        id = "low_card_enc") %>>%
    po("encode", method = "treatment",
        affect_columns = selector_type("factor"), id = "binary_enc")

这里各操作的执行顺序很重要：po("encodeimpact") 把高基数的 factor 类型特征转换为 numeric 特征，因此它们不会受到其后 po("encode") 操作符的影响。所以，独热编码的 PipeOp 无需明确指定不作用于高基数特征。同理，当处理编码 PipeOp 看到数据时，所有非二值的 factor 特征都已被转换，因此它默认只会作用于二值因子。

现在我们可以把这个流水线应用到我们的 xgboost 模型上，用于基准测试实验；同时我们也比较一个只用独热编码的更简单流水线，以展示不同策略带来的性能差异。

glrn_xgb_impact = as_learner(factor_pipeline %>>% lrn_xgb)
glrn_xgb_impact$id = "XGB_enc_impact"

glrn_xgb_one_hot = as_learner(po("encode") %>>% lrn_xgb)
glrn_xgb_one_hot$id = "XGB_enc_onehot"

bmr = benchmark(benchmark_grid(tsk_ames,
  c(lrn_baseline, glrn_xgb_impact, glrn_xgb_one_hot), rsmp_cv3))
bmr$aggregate(measure = msr_mae)[, .(learner_id, regr.mae)]
       learner_id regr.mae
1:       Baseline    56056
2: XGB_enc_impact    16357
3: XGB_enc_onehot    16446

在这个小实验中，我们看到扩展的因子编码流水线与较简单的独热编码策略流水线之间只有很小的差异。如果你有兴趣了解更多不同的编码策略，包括对比它们的基准测试研究，我们推荐 Pargent et al. (2022)。

背景与解释（译者注）：这里介绍了三种常见的分类变量编码方式，它们各自适用的场景不同。独热编码会把一个 k 水平分类特征展开成 k 个（或 k−1 个）0/1 列，特征维度随水平数线性增长，因此对高基数特征不友好（既浪费存储，也容易让树模型与正则化模型过拟合）。处理编码（treatment encoding）本质上是独热编码的「去第一类」变体，配合 GLM/GAM 时能避免完全共线性。影响编码（也称目标编码 target encoding）用目标均值压缩分类信息，维度恒为 1，但对目标的信息依赖要求它必须在交叉验证折内拟合，否则会引入严重的训练-测试泄漏。读者在实际中还需注意：mlr3 里 `po("encode")` 与 `po("encodeimpact")` 各自处理的是不同层次的分类特征，用选择器（selector）与 affect_columns 精确指定作用范围是避免意外改变无关列的关键。

9.3 缺失值（Missing Values）

真实世界数据中的一个常见问题是特征中的缺失值。在 Ames 数据集中，有几个变量至少有一个缺失数据点：

# 打印前五个含缺失数据的特征
names(which(tsk_ames$missings() > 0))[1:5]
[1] "Alley"          "BsmtFin_SF_1"   "BsmtFin_SF_2"   "BsmtFin_Type_1"
[5] "BsmtFin_Type_2"

许多学习器无法自动处理缺失值（例如 lrn("regr.ranger") 和 lrn("regr.lm")），另一些学习器可能能够处理缺失值，但使用的可能是并不理想的简单方法（例如直接丢弃含缺失数据的行）。

最简单的数据插补（data imputation）方法是用特征的均值（po("imputemean")）(图 9.1)、中位数（po("imputemedian")）或众数（po("imputemode")）替换缺失值。另一种做法是从特征的经验分布中抽样插补，例如直方图（po("imputehist")）。除了猜测缺失特征可能是什么之外，还可以用一个新水平替换缺失值，例如命名为 .MISSING（po("imputeoor")）。对于数值特征，Ding and Simonoff (2010) 表明，对于二分类和基于树的模型，将缺失值编码为超出范围（out-of-range，OOR）的值（例如一个高于最大观测值的常量）是一种合理的做法。

数据插补（Data Imputation）

对于预测任务而言，跟踪缺失数据通常很重要，因为缺失数据本身往往携带信息。为了保留「哪些数据缺失」这一信息，插补应当通过添加二进制指示特征（每个被插补的特征对应一个）来记录，若某观测的特征缺失则取 1，存在则取 0（po("missind")）。需要指出的是，记录这一信息本身并不能防止模型解释中的问题。举一个真实世界的例子：针对白人社区的医疗数据通常比针对少数族裔社区收集得更全面。对少数族裔社区的数据进行插补，往好了说是掩盖这种数据偏差，往坏了说会因作出严重失真的假设而使偏差雪上加霜（关于数据偏差与算法公平性，见第 14 章）。

在下面的代码中，我们用上面列出的 PipeOp 创建了一个流水线，并利用 po("featureunion") 组合多个作用于 "integer" 列的 PipeOp。

impute_hist = list(
      po("missind", type = "integer",
          affect_columns = selector_type("integer")
      ),
      po("imputehist", affect_columns = selector_type("integer"))
    ) %>>%
    po("featureunion") %>>%
    po("imputeoor", affect_columns = selector_type("factor"))

impute_hist$plot(horizontal = TRUE)

利用这个流水线，我们现在可以用无法处理缺失数据的 lrn("regr.ranger") 来运行实验；同时我们也比较一个只用 OOR 插补的更简单流水线，以展示不同策略带来的性能差异。

glrn_rf_impute_hist = as_learner(impute_hist %>>% lrn("regr.ranger"))
glrn_rf_impute_hist$id = "RF_imp_Hist"

glrn_rf_impute_oor = as_learner(po("imputeoor") %>>% lrn("regr.ranger"))
glrn_rf_impute_oor$id = "RF_imp_OOR"

design = benchmark_grid(tsk_ames,
  c(glrn_rf_impute_hist, glrn_rf_impute_oor), rsmp_cv3)
bmr_new = benchmark(design)
bmr$combine(bmr_new)
bmr$aggregate(measure = msr_mae)[, .(learner_id, regr.mae)]
       learner_id regr.mae
1:       Baseline    56056
2: XGB_enc_impact    16357
3: XGB_enc_onehot    16446
4:    RF_imp_Hist    16400
5:     RF_imp_OOR    16394

与编码类似，我们看到不同插补策略之间的性能差异很有限。这在此处符合预期，并印证了 Ding and Simonoff (2010) 的发现——超出范围插补对基于树的方法而言既简单又有效。

还存在许多更先进的插补策略，包括基于模型的插补（用机器学习模型来预测缺失值），以及多重插补（multiple imputation，反复对数据重采样并在每个样本中插补，例如用均值插补，以获得更稳健的估计）。然而，这些更高级的技术很少能显著提升模型的预测性能，上面介绍的简单插补技术通常已经足够 (Poulos and Valle 2018)。尽管如此，这些方法仍然重要，因为找到与观测值分布吻合良好的插补值，才能拟合出一个可以在后续步骤中被解释和分析的模型。

背景与解释（译者注）：本节对比了几类缺失值插补策略：均值/中位数/众数插补计算简单，但会低估方差并扭曲分布；直方图抽样（`imputehist`）从经验分布中随机抽取，能在一定程度上保持分布形状；超出范围插补（`imputeoor`）为数值特征填入一个「不可能出现」的常量、为分类特征新增一个「缺失」水平，其价值在于让树模型在分裂时能显式地学习「缺失与否」这一信号。这正好呼应了前文「缺失本身携带信息」的观点——树模型天然擅长利用 po("missind") 产生的指示列。对于线性模型等对分布敏感的算法，均值插补等简单方法仍是最常用的兜底方案；而多重插补（如 R 包 `mice`）主要服务于推断与不确定性量化，在预测性能上通常没有显著收益。

9.4 流水线 Robustify（Pipeline Robustify）

mlr3pipelines 提供了一个简单可复用的流水线（在众多用途中，主要用于插补与因子编码），名为 ppl("robustify")，它包含合理的默认设置，在大多数编码或插补数据的场景下都可以使用。该流水线包含以下 PipeOp（有些被多次应用，且大多数使用选择器）：

ppl("robustify")
  1. po("removeconstants") – 移除常量特征。
  2. po("colapply") – 字符与有序特征被编码为分类特征，日期/时间特征被编码为数值。
  3. po("imputehist") – 数值特征用直方图抽样插补。
  4. po("imputesample") – 逻辑特征通过从经验分布中抽样插补——这只影响 $predict() 步骤。
  5. po("missind") – 为被插补的数值与逻辑变量添加缺失数据指示列。
  6. po("imputeoor") – 分类特征的缺失值用一个新水平编码。
  7. po("fixfactors") – 修正分类特征的水平，使预测与训练时出现相同的水平（这可能涉及删除空的因子水平）。
  8. po("imputesample") – 上一步删除水平而产生的分类特征缺失值，通过从经验分布中抽样来插补。
  9. po("collapsefactors") – 合并分类特征的水平（从训练数据中最稀有的因子开始），直到水平数少于某个数量，由 max_cardinality 参数控制（保守默认值为 1000）。
  10. po("encode") – 分类特征做独热编码。
  11. po("removeconstants") – 移除上一步可能产生的常量特征。

ppl("robustify") 有可选参数 task 和 learner。如果提供了这些参数，则所得到的流水线会被设置成专门处理给定任务和学习器，例如，如果学习器具有 "missings" 属性，或者任务中本来就没有缺失值，那么流水线就不会进行缺失值插补。默认情况下，当不提供 task 和 learner 时，图会被设置为防御式的：它插补所有缺失值，并把所有特征类型转换为数值。

线性回归是一个简单的模型，无法处理我们在处理数据时可能遇到的多数问题，但借助 ppl("robustify")，我们现在可以把它纳入实验：

glrn_lm_robust = as_learner(ppl("robustify") %>>% lrn("regr.lm"))
glrn_lm_robust$id = "lm_robust"

bmr_new = benchmark(benchmark_grid(tsk_ames, glrn_lm_robust,  rsmp_cv3))
bmr$combine(bmr_new)
bmr$aggregate(measure = msr_mae)[, .(learner_id, regr.mae)]
       learner_id regr.mae
1:       Baseline    56056
2: XGB_enc_impact    16357
3: XGB_enc_onehot    16446
4:    RF_imp_Hist    16400
5:     RF_imp_OOR    16394
6:      lm_robust    16298

对线性回归做 robustify 处理后得到的模型，其表现大幅超过无特征基线，并且与更复杂的机器学习模型相比也毫不逊色。

背景与解释（译者注）：ppl("robustify") 是 mlr3 生态中最常用的「一键预处理」入口，本质是把本章前两节介绍的各种预处理操作按合理顺序组合成一个默认流水线。它的一个贴心设计是感知学习器与任务：当学习器自带缺失值处理能力（如部分树模型具备 "missings" 属性）或任务中没有缺失值时，相关插补节点会被自动移除，避免无谓的计算。使用时需留意，它的默认策略是一刀切式的「防御性」处理——所有分类特征最终都会走独热编码，因此若你有高基数分类特征或对编码方式有特殊要求（如本章 9.2 节的影响编码），仍应自己定制流水线，而不是盲目依赖 robustify。

9.5 特征与目标变换（Transforming Features and Targets）

对特征和目标做简单变换，对某些学习器可能是有益的（有时是必需的）。特别是，对目标做对数变换有助于使分布更加对称，并能帮助减小离群值的影响。类似地，对偏态特征做对数变换也有助于降低离群值的影响。在图 9.3中，我们绘制了 ames 数据集中目标的分布，以及对数变换后的目标分布，可以看到仅对变量取对数就能得到对称得多、离群值更少的分布。

library(patchwork)

# 复制 ames 数据
log_ames = copy(ames)
# 对目标进行对数变换
log_ames[, logSalePrice := log(Sale_Price)]
# 绘图
autoplot(as_task_regr(log_ames, target = "Sale_Price")) +
  autoplot(as_task_regr(log_ames, target = "logSalePrice"))

对特征做归一化（normalization）也可能是必要的，以确保尺度更大的特征不会产生更高影响力，这对基于距离的方法（如 k 近邻模型）或带正则化的参数模型（如 Lasso 或 Elastic net）尤其重要。许多模型会在算法需要时内部缩放数据，所以大多数时候我们无需在预处理中手动做这件事；不过如果确实需要，可以用 po("scale") 来对数值特征做中心化与缩放。

训练期间对目标做的任何变换，在模型预测期间都必须反转，以确保预测在正确的尺度上做出。举例来说，假设我们要对目标做对数变换，那么要采取以下步骤：

df = data.table(x = runif(5), y = runif(5, 10, 20))

5: 0.37355 10.48

df[, y := log(y)]

[1] 2.327 2.375 2.907 2.853 2.350
# 2. 进行线性回归预测
#    预测在对数变换后的尺度上

    1     2     3     4     5 
2.556 2.571 2.575 2.548 2.561

    1     2     3     4     5

在这个简单实验中，我们可以手动变换并反转目标，但在处理重采样和基准测试实验时这就复杂得多，因此流水线 ppl("targettrafo") 会替你完成这些繁重的工作。该流水线包含参数 targetmutate.trafo（用于在训练时对目标施加的变换）以及 targetmutate.inverter（用于在预测时反转原始变换的变换）。现在，我们把对数变换考虑进来，把这个流水线加到我们 robust 的线性回归模型上：

glrn_log_lm_robust = as_learner(ppl("targettrafo",
  graph = glrn_lm_robust,
  targetmutate.trafo = function(x) log(x),
  targetmutate.inverter = function(x) list(response = exp(x$response))))
glrn_log_lm_robust$id = "lm_robust_logtrafo"

bmr_new = benchmark(benchmark_grid(tsk_ames, glrn_log_lm_robust,
  rsmp_cv3))
bmr$combine(bmr_new)
bmr$aggregate(measure = msr_mae)[, .(learner_id, regr.mae)]
           learner_id regr.mae
1:           Baseline    56056
2:     XGB_enc_impact    16357
3:     XGB_enc_onehot    16446
4:        RF_imp_Hist    16400
5:         RF_imp_OOR    16394
6:          lm_robust    16298
7: lm_robust_logtrafo    15557

有了目标变换和 ppl("robustify")，简单的线性回归现在成了表现最好的模型。

背景与解释（译者注）：房价这类价格数据通常呈右偏分布，少数昂贵房产会严重拉偏均值并放大误差项的影响。对目标取对数后，模型在「对数价格」尺度上拟合，误差项更接近对称分布，MAE 也往往显著下降。但需要强调：变换必须在训练时施加，并在预测后反转（这里用 exp 恢复原始尺度），否则所有下游评估都会失真。ppl("targettrafo") 的两个回调参数 targetmutate.trafo（训练前对目标施加）与 targetmutate.inverter（预测后反转）正是为了保证这一点在重采样循环中也不会出错。类似的场景还有 Box-Cox 变换、对计数数据取平方根等，读者可按同样模式替换回调。值得注意的是，树模型（随机森林、XGBoost）对单调变换不敏感，因此对数变换的收益主要体现在线性模型等对分布敏感的方法上。

9.6 函数型特征提取（Functional Feature Extraction）

作为数据预处理的最后一步，我们将考察从函数型特征（functional features）中提取特征。在第 6 章中，我们讨论了自动化特征选择，以及如何用过滤器和包装器的自动化方法把数据集缩减为一组优化的特征。函数型特征提取与此不同，因为我们现在关注的是彼此相互依赖、合在一起可能提供有用信息（但单独来看没有信息量）的特征。图 9.4 可视化了普通特征与函数型特征之间的区别。

举一个具体的例子，考虑 Ames 数据集中房屋厨房电器的耗电情况。

energy_data = mlr3data::energy_usage

在这个数据集中，每一行代表一所房屋，每个特征是在给定时间点厨房电器的总耗电量 (Bagnall et al. 2017)。耗电量以两分钟为间隔测量，共产生 720 个特征。

library(ggplot2)
ggplot(data.frame(y = as.numeric(energy_data[1, ])),
    aes(y = y, x = 1:720)) +
  geom_line() + theme_minimal() +
  labs(x = "2-Minute Interval", y = "Power Consumption")

把这 720 个特征直接加进我们的完整数据集是个糟糕的主意，因为每个单独的特征都不提供有意义的信息；同理，我们也不能出于同样的原因自动化地选出最佳特征子集。相反，我们可以提取关于曲线的信息，以获得对厨房整体能源使用情况的洞察。例如，我们可以提取最大用电瓦数、总用电瓦数、尖峰次数以及其他类似特征。

为了提取特征，我们将编写一个继承自 PipeOpTaskPreprocSimple 的自定义 PipeOp。为此，我们添加一个名为 .transform_dt 的私有方法，把操作硬编码在我们的任务中。在这个例子中，我们选择函数型特征（它们都以「att」开头），提取耗电量的均值、最小值、最大值和方差，然后移除函数型特征。要了解更多关于构建自定义 PipeOp 的内容，请在 R 中运行 vignette("extending", package = "mlr3pipelines") 打开相应的 vignette。

PipeOpFuncExtract = R6::R6Class("PipeOpFuncExtract",
  inherit = mlr3pipelines::PipeOpTaskPreprocSimple,
  private = list(
    .transform_dt = function(dt, levels) {
        ffeat_names = paste0("att", 1:720)
        ffeats = dt[, ..ffeat_names]
        dt[, energy_means := apply(ffeats, 1, mean)]
        dt[, energy_mins := apply(ffeats, 1, min)]
        dt[, energy_maxs := apply(ffeats, 1, max)]
        dt[, energy_vars := apply(ffeats, 1, var)]
        dt[, (ffeat_names) := NULL]
        dt
    }
  )
)

在把它用于实验之前，我们先测试这个 PipeOp 是否按预期工作。

tsk_ames_ext = cbind(ames, energy_data)
tsk_ames_ext = as_task_regr(tsk_ames_ext, "Sale_Price", "ames_ext")
# 移除本章开头识别的冗余变量
tsk_ames_ext$select(setdiff(tsk_ames_ext$feature_names, to_remove))

func_extractor = PipeOpFuncExtract$new("energy_extract")
tsk_ames_ext = func_extractor$train(list(tsk_ames_ext))[[1]]
tsk_ames_ext$data(1,
  c("energy_means", "energy_mins", "energy_maxs", "energy_vars"))
   energy_means energy_mins energy_maxs energy_vars
1:        1.062     0.01427       21.98       3.708

这些输出与图 9.5相比看起来是合理的，因此我们现在可以运行使用特征提取的最终基准测试实验。我们无需把 PipeOp 添加到每个学习器上，因为可以在任何模型训练之前把它一次性应用到所有可用数据上（如上所示）。

learners = list(lrn_baseline, lrn("regr.rpart"), glrn_xgb_impact,
    glrn_rf_impute_oor, glrn_lm_robust, glrn_log_lm_robust)

bmr_final = benchmark(benchmark_grid(c(tsk_ames_ext, tsk_ames), learners,
  rsmp_cv3))

perf = bmr_final$aggregate(measure = msr_mae)

最终结果表明，加入这些提取出的特征提升了所有模型（除无特征基线外）的性能。

在这个例子中，我们本可以直接把变换应用到数据集上而不使用 PipeOp。然而，使用 PipeOp 的优势在于，我们可以把它链接到一部分学习器上，从而防止基准测试实验中的实验数量爆炸式增长。

背景与解释（译者注）：函数型特征（functional features）指那些本质上是一条曲线或时间序列的特征列，单独看每一列都没有独立含义，必须整体解读。直接把它们作为 720 个特征丢进模型通常是有害的：一是维度爆炸导致过拟合风险，二是每个特征毫无解释力。正确做法是先「降维」——提取曲线形态的统计量（均值、方差、峰值、斜率等），这正是本节自定义 PipeOp 做的事。PipeOpTaskPreprocSimple 是 mlr3pipelines 中用于「每个样本独立变换」的基类，自定义时只需实现私有方法 .transform_dt（训练与预测共用）。需要注意「train 一次、推理时复用一个已训练 PipeOp」与「把 PipeOp 编入流水线」的区别：前者适合一次性变换数据（无泄漏风险），后者适合需要把变换逻辑整体嵌入重采样/调优循环的场景。

9.7 结论（Conclusion）

在本章中，我们以第 7 章和第 8 章学到的所有内容为基础，考察了流水线在数据预处理中的具体用法。我们主要聚焦于特征工程，它借助 mlr3pipelines 尽可能自动化预处理流程，同时仍保证用户的可控性。我们考察了分类变量的因子编码、缺失数据插补、变量变换以及特征提取。预处理在机器学习实验中几乎总是必需的，应用 ppl("robustify") 在多数情况下都能通过执行最常见的预处理步骤来简化这一流程，我们将在第 11 章中看到它的应用。
